# linkage-fit 예제 — 접힌 덱에서 힌지를 되찾는다

`arm_flat.k` 는 파트 4개가 x 로 늘어선 폴더블 팔이고, `arm_folded.k` 는 그것에 **알려진** 군별
강체변환을 걸어 만든 접힌 상태다.

| PID | 변환 |
|---|---|
| 1 | 고정 |
| 2 | z 축, 45°, 피벗 (30, 0, 0) |
| 3 | z 축, 90°, 피벗 (60, 0, 0) |
| 4 | z 축, 90°, 피벗 (60, 0, 0) — **3 과 같은 힌지** |

```
KooRemapper linkage-fit linkage_fit.yaml
```

참 값을 알고 만든 덱이라 **되찾았는지 바로 확인할 수 있다.** 실행하면 PID 2 는 45°@(30,0,·),
PID 3·4 는 90°@(60,0,·) 으로 나오고 3·4 가 한 군으로 묶이며 그 군의 **피벗 산포가 0** 이다.

## 왜 피벗 산포를 보는가

각도가 같다고 같은 힌지가 아니다. 현장 보고(§2-1)의 실측이 그것이었다 — 각도만으로 묶었더니
피벗이 5.41mm 흩어진 채 한 군이 됐고, 그래도 숫자는 그럴듯했다. 그래서 이 op 은 군을 묶을 때
각·축·피벗·축이동이 **모두** 맞아야 한다고 요구하고, 같은 각 파트의 피벗이 `pivot_tol` 보다
흩어지면 **그 산포를 숫자로** 경고한다.

이 예제에서 그 경고를 보려면 `pivot_tol` 을 아주 작게(예: `1e-18`) 주면 된다 — 3·4 가 갈라지고
각 90° 두 파트의 산포가 찍힌다.

## 산출

`fold_groups.yaml` 은 `applyfold` 가 읽는 형태다 — 이 변환을 **다른(큰) 덱에** 그대로 찍을 수 있다.
