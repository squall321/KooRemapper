# SmartTwinMCP 에 드리는 요청 — stcx 실행 기록에 각도별 run 폴더 · d3plot 경로 (2026-10-28)

**보내는 곳** DynaForge(KooRemapper) · 후처리 모듈
**받는 곳** SmartTwinMCP — stcx 잡 도구(포털은 이 도구를 게이트웨이로 중계만 합니다)
**성격** 요청입니다. 꼴은 제안이고, 정하는 것은 SmartTwinMCP 입니다.
**총괄 계획** KooRemapper `docs/01-plan/features/drop-twin-1028.plan.md` — 이 요청은 계약 C-1 입니다.

## 1. 한 줄
전각도 낙하 잡의 결과에 **각도마다 run 폴더와 d3plot 경로**를 실어 주십시오. 지금은 잡 하나에 `work_dir` · `output_dir` 만 있어, 각도와 폴더의 대응을 폴더 이름 꼴에 기대어 짐작해야 합니다.

## 2. 왜 필요한가
- 낙하 트윈은 후처리 잡 안에서 각도마다 **S1 경량 추출본**(겉면 변위 · 응력 HDF5)을 만들고, 사진급 렌더(SceneForge)는 stcx viz 노드에서 그 추출본을 읽습니다(10-28 — viz 노드가 stcx 노드로 확인됨).
- DynaForge 의 manifest 는 각도마다 원본 경로를 정본으로 적어야 합니다. 원본은 지우지 않고(정리 승인은 사용자), 추출본이 어느 원본에서 나왔는지 거꾸로 찾을 수 있어야 합니다.
- 포털 요청서(09-16) §4 의 「산출 위치를 구조로」 와 같은 요구입니다 — 폴더 이름 꼴은 바뀔 수 있습니다.

## 3. 지금 아는 것 (10-28 실측)
- 폴더 꼴은 `<work_dir>/output/Run_<시각>_<해시>/` 이고 d3plot 은 그 아래 `Output/d3plot`(+ `d3plot01`…, 이 덱은 가족 파일 250개 · 18 GB)입니다.
- sphere 리포트의 `results[i].folder` 가 Run 폴더 이름이고 `angle` 이 각도라, 리포트를 반입한 뒤에는 이어 붙일 수 있습니다. 다만 후처리 잡이 리포트보다 먼저 돌고, 실패한 각도는 리포트에 없습니다.

## 4. 꼴(제안)
잡 결과(상태 응답이나 결과 목록)에 각도마다 한 줄씩 실어 주시면 됩니다.
```json
{"runs": [
  {"case_key": "Run_20260602_093108_fd1418", "angle": {"name": "P0001", "roll": 0.0, "pitch": -0.0, "yaw": 0.0},
   "run_dir": "/data/<사람>/<캠페인>/output/Run_20260602_093108_fd1418",
   "d3plot": "/data/<사람>/<캠페인>/output/Run_20260602_093108_fd1418/Output/d3plot",
   "status": "done", "states": 4952}
]}
```
- `status` 는 실패한 각도도 그대로 실어 주십시오(빠지면 「없다」 와 「실패했다」 를 못 가립니다).
- `states` 는 아시면 넣어 주십시오. 모르면 빼도 됩니다 — 지어내지 않는 쪽이 낫습니다.
- 응답에 싣기 어렵다면 `output_dir` 에 같은 꼴의 `runs.json` 을 남기는 것도 좋습니다.
