# CI 에 gmsh — 해결됨. 그리고 워크플로 파일을 미는 법

**작성일**: 2026-09-25 (같은 날 해결)
**상태**: **적용 완료** (`bc2eba2`)
**한 줄**: `.github/workflows/` 는 HTTPS+PAT 로는 못 민다. **SSH 로 밀면 된다.**

## 무슨 일이었나

덱 계약 2차 P0-3 에서 "gmsh 가 없으면 **skip 이 아니라 FAIL**" 로 바꿨다. 그 skip 안에 실제
결함(`meshfix` 의 CRLF 소실·2줄 포맷 요소 소실)이 숨어 있었고 실사용 박스가 우리보다 먼저
찾아 돌려줬으니 그 수정 자체는 옳다. 그런데 `.github/workflows/regress.yml` 은 gmsh 를 깔지
않아 **그 커밋 이후 CI 가 빨갰다.**

고치는 커밋을 밀려는데 거부됐다.

```
! [remote rejected] main -> main
  (refusing to allow a Personal Access Token to create or update workflow
   `.github/workflows/regress.yml` without `workflow` scope)
```

## 해결 — SSH 로 민다

이 제약은 **HTTPS + PAT 경로에만** 걸린다. SSH 키는 스코프가 없으므로 그대로 통과한다.
이 박스에는 이미 쓸 수 있는 키가 있다(`ssh -T git@github.com` → `Hi squall321!`).

```bash
git push git@github.com:squall321/KooRemapper.git main
```

`origin` 을 바꾸지 않고 URL 을 직접 줬다 — 평소 경로(HTTPS)를 건드리지 않기 위해서다.
워크플로 파일을 자주 고칠 일이 생기면 `git remote set-url origin git@github.com:...` 로
아예 SSH 로 옮기는 것도 방법이다.

## 패치가 한 일

- `apt-get install -y ... gmsh`. `meshfix` 가 쓰는 `.geo` 기능(`Merge` · `ClassifySurfaces` ·
  `CreateGeometry` · `Surface{:}`)은 gmsh 4.0+ 이면 된다 — apt 판으로 충분하다.
- 회귀 단계에 `KOOREMAPPER_GMSH=/usr/bin/gmsh`. **경로 고정이 핵심이다** — PATH 탐색에
  맡기면 어떤 gmsh 를 집었는지로 결과가 갈린다(이 박스의 `~/.local/bin/gmsh` 는 깨진 파이썬
  래퍼라 `meshfix` 가 rc=1 로 죽는다).
- `KOOREMAPPER_TEST_GMSH` 는 일부러 안 준다 — `test_gmsh_discovery.py` 는 '없으면 건너뛴다' 를
  스스로 선언한 상태이고, 그것까지 켜는 것은 이 변경의 범위를 넘는다.

## 남는 위험

apt 판 gmsh 로 `meshfix` 가 실제로 도는지는 **첫 CI 실행으로** 확인된다. 이 박스에서는
`KOOREMAPPER_GMSH` 만 준 상태로 세 시험이 전부 통과한다(gmsh 4.14.1). 버전 문제가 있으면
CI 가 그 사실을 분명히 말할 것이고, 원인을 알 수 없는 실패로 남는 것보다 낫다.
