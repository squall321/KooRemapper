## 1. 삽입을 지었습니다 — §3-3 의 우리 몫

`KooRemapper cad_solid_merge_to_deck <config.yaml>`(이름은 §2 소유 표의 이름 그대로입니다). 매뉴얼 §49.

```yaml
model: deck.k                      # 넣을 기존 덱
output: merged                     # → merged.k · merged_fragment_map.json
fragment: fragment_<ref>.k
fragment_map: fragment_<ref>.json
# deck_unit: mm-t-s                # 대상 덱의 단위(기본값)
```

- **대응표는 §3-3 의 칸 그대로 읽습니다** — 맨 위 넷 · `ranges` 넷 · `parts[]` 여덟. 모르는 칸·빠진 칸은 거절합니다.
  JSON 은 엄격하게 읽습니다(꼬리 쓰레기 · 중복 키 · 잘못된 이스케이프 거절, `\uXXXX` 는 UTF-8 로 — 여러분 파일은
  `ensure_ascii=False` 라 쓰이지 않지만 받습니다).
- **넣기 전에 조각을 대응표와 대조합니다** — 번호가 `ranges` 안이고 lo·hi 가 실제 최소·최대인가 · 파트 집합 · 파트마다
  요소 수·요소 구간 · 그 요소가 쓰는 절점 = 절점 구간 · **`coord_sha`**. 하나라도 어긋나면 넣지 않습니다(rc 1).
  `coord_sha` 는 여러분 `core/remesh_impact.coord_sha` 의 식을 C++ 로 옮겼고, 파이썬으로 돌린 기댓값 셋(음수·음의 0·세 자리
  지수 포함)과 같습니다.
- **번호는 대상 덱(인클루드 닫힘까지)의 최대값 위로 옮깁니다** — 과도기 번호 길(Q5) 그대로입니다. PID·SECID·MID 는
  **한 이동량**으로 옮겨, 여러분 규약(셋이 같은 번호 · `ranges.pid` 가 셋의 대역)이 덱 안에서도 섭니다.
- **좌표 글자는 바이트 그대로**이고 번호 칸만 덱의 폭(8 · `i10=y` 면 10)으로 씁니다. 넣을 블록을 다시 읽어 `coord_sha` 를
  한 번 더 잽니다. 산출 옆에 **같은 칸 집합의 대응표를 덱 번호로 옮긴 것**(`<output>_fragment_map.json`)을 둡니다.
- **불러 본 값(2026-10-16)** — 여러분 라이브 판의 조각 `fragment_f950947d9cb1`(합성 과제 K2라이브-B · 파트 4 · 절점

## 2. 새 질문 다섯 — 답

| # | 질문 | 답 |
|---|---|---|
| 새 1 | 변환 JSON 에 파트 지목이 필요한가 | **지금은 필요 없습니다.** 그것을 읽을 저희 쪽(DF-28 마스킹)이 아직 0건입니다. 마스킹을 지을 때 칸 이름과 값(노드 경로인가 덱 PID 인가)을 정해 여쭙겠습니다 — 그때까지 칸 여덟 그대로 두십시오 |
| 새 2 | `anchor_2pt` 의 `residual_mm: null` 을 받는가 | **받습니다.** 모르는 것을 0 으로 쓰지 않는 쪽이 맞습니다(0 이면 「검증해 보니 맞았다」로 읽힙니다) |
| 새 3 | `planar_region` 을 산출물 파일로 받겠는가 | **지금은 필요 없습니다.** 새 1 과 같은 까닭입니다 — DF-28 을 지을 때 다각형이 필요하면 칸 일곱(§3-9) 그대로 부탁드리겠습니다 |
| 새 4 | 대응표의 `ranges.sid: null` 을 받는가 | **받습니다 — 이미 그렇게 읽습니다.** `null` 은 「쓴 번호가 없다」이고, 그 조각에 `*SET_*` 가 있으면 거절합니다(시험으로 고정). 세트가 든 조각(`sid` 가 `null` 이 아님)은 아직 받지 않습니다 — 여러분 조각은 늘 `null` 이라 지금 막히는 것은 없습니다 |
| 새 5 | `unit`·`frame` 을 대응표에서 읽는가 | **예 — 대응표에서 읽습니다.** `.k` 머리 주석은 보지 않습니다. `unit` 이 대상 덱 단위(`deck_unit`, 기본 `mm-t-s`)와 다르거나 `frame` 이 `world` 가 아니면 **거절**합니다 — 환산·좌표 변환은 하지 않습니다(Q6 의 「모르는 칸은 거절」과 같은 규율) |

## 3. 저희 쪽에 아직 열린 것

- **Q11 — 여러분 `assess_edit_impact` 와 겹치던 저희 사전 조회의 새 이름.** 그 op 이 아직 0건이라 이름을 정하지
  않았습니다. 지을 때 저희 이름 결정 절차로 정해 알려 드립니다. 여러분이 기다리실 것은 없습니다.
- **Q13 — 마스크 관문.** 관문은 저희 몫이고 아직 0건입니다. `edge_len` 의 어느 값을 쓸지는 TIM 실측(요청 쪽)과 함께
  임계를 정할 때 정합니다.
- **번호 발행표(Q5·Q7).** 대역을 어느 범위(세션·캠페인·조직)로 둘지가 저희 쪽 결정으로 남아 있습니다. 그동안은
  **과도기 길 그대로**입니다 — 여러분이 고른 시작 번호(기본 1)로 쓰시고, 저희 삽입이 옮기며, `ranges` 가 정본입니다.
  발행표가 서면 바뀌기 **전에** 먼저 알려 드립니다(약속 그대로).

## 4. 짓다가 본 것(여러분이 바꾸실 것은 없습니다)

- 조각의 `*PART` 는 제목 **앞에** `$# 이름` 주석을 답니다. LS-DYNA 는 `$` 줄을 어디서든 건너뛰므로 합법이고, 저희 삽입도
  주석을 그대로 둡니다. 다만 저희 도움말 실행기의 검사기 하나가 그 꼴에서 제목을 카드로 잘못 읽었습니다 — 저희 쪽에서
  고쳤습니다(`fbb633a`).
- 자리표시 물성(RO = E = 1.0)은 그대로 넣고 **MID 마다 경고**합니다 — 일부러 눈에 띄게 두신 뜻을 살렸습니다.
- 시작 번호를 기본값(1)이 아닌 값으로 주셔도(이 판은 500001/600001/900) 과도기에는 **옮깁니다**. 그 번호를 덱 번호로
  그대로 쓰고 싶은 경우가 생기면 알려 주십시오 — 그 길은 발행표(`ranges` 대조)로 엽니다(조용히 옮기지 않는 길).
