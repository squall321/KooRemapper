# StepForge 에 드리는 요청 — 낙하 트윈 (2026-10-28)

**보내는 곳** DynaForge(KooRemapper) · 후처리 모듈
**받는 곳** StepForge
**성격** 무엇을 만들어 달라는 **요청**입니다. 꼴은 제안이고, 정하는 것은 StepForge 입니다.
**경계** 10-15 합의 그대로입니다 — 두 앱은 **서로를 부르지 않고 파일로만 주고받습니다**. 새로 생기는 장면 포지(SceneForge, 이름 확정 전)도 같은 규칙을 따릅니다.
**총괄 계획** `docs/01-plan/features/drop-twin-1028.plan.md` — 계약 번호(C-n)는 그 문서와 같습니다.

---

## 1. 한 줄
전각도 낙하 해석의 변형을 **실제 CAD 형상 위에** 보여 주려고 합니다. 그러려면 "어느 FE 파트가 어느 CAD 파트인가"와 "FE 변위를 CAD 정점으로 어떻게 옮기나"가 필요한데, 둘 다 형상의 일이라 StepForge 의 몫이라고 봅니다.

## 2. 왜 지금인가
- 1,000방향 낙하 결과는 지금 파트별 최대 응력만 남고, 변형 거동은 볼 수 없습니다.
- 그래서 둘을 만들기로 했습니다(사용자 결정 10-28).
  - **브라우저 3D 변형 뷰어** — 엔지니어가 매일 쓰는 것. DynaForge 화면에 둡니다.
  - **사진급 렌더** — 디지털 트윈 보고와 **실물 시험 재현**용. 새 포지(SceneForge)가 맡습니다.
- 두 화면 모두 FE 메시가 아니라 원 CAD 형상으로 보여야 제 값을 합니다. 특히 시험 사진과 견주는 데는 매끈한 실제 형상이 필수입니다.

## 3. 이미 가지신 것 (10-28 에 읽어서 확인했습니다)
- `core/step_material.py` — STEP 에서 재질 이름·밀도를 직접 읽음
- `core/export/gltf_batch.py` — 파트 수천 개를 드로우콜 하나로 묶고 정점마다 `_PARTID` 를 남기는 glb
- `core/deck_step.py` — 덱(.k) → STEP(파트 이름 = `*PART` 제목, 패싯 바디)
- `match_parts_across` — 형상 지문으로 후보를 모으고 부울 대칭차로 확정하는 과제 간 파트 대응
- OCC 형상 커널

새로 지어 달라는 것보다 **이것들을 낙하 트윈 쪽으로 이어 달라는** 요청에 가깝습니다.

## 4. 부탁 넷
### ① C-5 파트 대응표 — 덱 PID ↔ StepForge 파트 키
- **무엇** — 낙하 모델 덱의 PID 마다 대응하는 CAD 파트 키, 근거(이름 · 형상 지문 · 부울 확인), 확신도.
- **왜** — 변형을 CAD 에 옮기는 출발점이고, 재질(C-8)을 덱 파트에 거는 열쇠이기도 합니다.
- **꼴(제안)** — JSON 한 파일. `{deck_sha256, step_revision, pairs: [{pid, part_key, basis, confidence}], unmatched: [{pid, reason}]}`.
- **꼭 지켜 주셨으면 하는 것** — 못 맞춘 파트를 버리지 말고 `unmatched` 에 까닭과 함께 남겨 주십시오. 조용히 빠지면 렌더에서 그 파트가 사라져도 아무도 모릅니다.

### ② C-6 매핑 가중치 — FE 표면 절점 → CAD 정점
- **무엇** — 파트마다 희소행렬(CSR). 행 = CAD 테셀레이션 정점, 열 = FE 표면 절점. 매 프레임은 받는 쪽이 "가중치 × 변위" 로 계산합니다.
- **왜** — 초기 형상에서 한 번만 셈하면, 1,000각도 × 수백 프레임을 행렬 곱 하나로 처리할 수 있습니다.
- **판** — `(STEP 판, 덱 sha, 테셀레이션 설정)` 이 같으면 다시 셈하지 않게 해 주십시오.
- **입력** — FE 표면 메시는 우리가 드립니다(§5). 덱 전체를 다시 읽으실 필요는 없습니다.

### ③ C-7 CAD 장면 — glb(있음) + **USD(신규)**
- glb 는 지금 그대로 쓰겠습니다(브라우저 뷰어).
- 사진급 렌더 쪽(Omniverse)은 USD 가 편합니다. 파트 계층 · 파트 키 · 재질 이름을 실은 USD 로 내 주실 수 있을지 여쭙니다. 어렵다면 glb → USD 변환은 SceneForge 가 맡겠습니다.

### ④ C-8 재질 이름·밀도를 장면에 싣기
- 이미 STEP 에서 읽고 계신 값을 C-7 의 파트마다 실어 주십시오.
- 외관(색·마감)은 SceneForge 의 외관 라이브러리가 재질 이름으로 겁니다. StepForge 는 이름만 주시면 됩니다.

## 5. 우리가 드릴 것
- **C-4 덱** — 낙하 모델의 `.k` 파일과 sha256.
- **FE 표면 메시** — 경량 추출본(C-3)의 공통 메시(`/mesh`)에서 표면 절점·면과 PID. 가중치(②)를 셈할 때 쓰십시오.

## 6. 여쭐 것
1. **파트 키의 꼴** — 정의 key 인지, 인스턴스 경로까지인지. 같은 부품이 여러 번 놓인 모델에서 어느 쪽이 맞는지 알려 주십시오.
2. **원 STEP 이 없는 모델** — 덱만 있는 낙하 모델도 있습니다. 그때는 `deck_step` 의 패싯 STEP 으로 대신하고, 결과에 "매끈한 외관 아님" 이라고 적는 것이 맞을까요?
3. **테셀레이션 설정** — 가중치의 판에 넣을 값(선형·각도 편차 등)이 무엇인지.
4. **USD 내보내기** — StepForge 에서 하실지, glb 를 받아 SceneForge 가 바꿀지.
5. **일정** — 우리 쪽 P1(공통 바탕)에 맞추려면 대응표와 가중치가 먼저 필요합니다. 그 전에 P0 에서 낙하 모델 하나로 가능성만 먼저 보고 싶습니다.

## 7. 급한가
**P0 가능성 확인은 급합니다.** 모델 하나로 대응표가 전 파트를 덮는지, 가중치가 어떤 품질인지만 먼저 알면 설계가 섭니다. 본 구현은 P1 입니다.
