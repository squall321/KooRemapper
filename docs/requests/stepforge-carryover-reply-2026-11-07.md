# StepForge 이월 요청 답신 — 세 파일 꼴 · 적용 · 질문 여덟 (2026-11-07)

**받는 곳** StepForge · **보내는 쪽** DynaForge(KooRemapper) · **원문** StepForge `docs/REQUEST-2026-11-06-carryover.md`(main `47cd7a1`).
경계 합의(`BOUNDARY-DYNAFORGE.md` §1 · 우리 답신 `stepforge-boundary-reply-2026-10-15.md` · `-10-16.md`)를 그대로 따른다 — 이미 있는 덱의 바이트는 우리가 고친다.

## 0. 요약 — 사용자 결정(11-07)
- **적용 연산은 짓는다. 다만 계획 파일 v2(PID 마다 덱 범위 · 설계 변형의 `snapshot.basis`/`project_id`)의 꼴이 정해진 뒤에.** 지금은 꼴과 질문에만 답한다.
  새 연산의 이름은 지을 때 따로 정한다(우리 카탈로그 이름 = CLI 이름이라 사용자 확인을 거친다).
- **나눠 쓰는 절점** — 다른 PID 와 나눠 쓰는 절점이 있는 PID 는 옮기거나 모프하지 않고, 어느 절점이 어느 PID 와 걸렸는지 낸다(Q4).
- **절점 · 세그먼트 · 요소로 건 참조** — 바꿔 넣거나 지우는 PID 를 절점 · 세그먼트 · 요소로 가리키는 접촉 · 세트가 있으면 그 줄을 적용하지 않고 무엇이 걸렸는지 낸다.
  PID 로 건 참조(파트 세트 · 접촉의 파트 지정)는 그대로 산다(Q1).
- **셸 두께가 바뀐 모프** — StepForge 가 새 섹션 카드를 낸다(Q8 — 꼴은 아래).

## 1. 지금 우리에게 있는 것 · 없는 것 (소스로 본 것)
| 쓸 곳 | 연산 | 지금 하는 일 |
|---|---|---|
| 옮김 · 모프 | `update` · `applyfold` | `*NODE` 묶음으로 같은 번호의 좌표를 덮는다 · 군별 강체 변환을 찍는다(군끼리 절점을 나눠 쓰면 거절, 찍은 뒤 되읽어 대조) |
| 번호 | `id_floor` | 덱 바닥 — 인클루드 닫힘과 빔 · 이산 · 질량 요소까지 센 최댓값 위 시작 번호(발행표 없음 — 「요청 때 발행」, 사용자 결정 10-16) |
| 새 파트 넣기 | `cad_solid_merge_to_deck` | 경계 3-3 조각(대응표 JSON · PID = SECID = MID · 섹션 · 물성 카드 동봉)을 **새 파트로 더한다** — 이월 조각(기존 PID 를 바꿔 넣음 · 덱의 SECID · MID 를 가리킴)은 그대로는 못 받는다 |
| 다시 잇기 | `rebind_entities_after_remesh` | PID 는 `*PART` 제목으로, 절점 · 요소는 같은 파트 · **정확히 같은 좌표**로 잇는다 — 새로 지은 메시에는 쓸 수 없다 |
| 결과 검사 | `info` | 요소 품질 지표(뒤집힘 · 야코비안 등) |

**없는 것** — 계획 파일 하나로 PID 마다 처리를 적용하는 연산. 위 연산들의 읽기 · 쓰기 · 대조 길을 함께 써서 새로 짓는다(v2 뒤).

## 2. 질문 여덟의 답
### Q1 적용 꼴
| 처리 | 우리가 할 일 |
|---|---|
| `keep` · `review` | 손대지 않는다. keep 줄의 `touches_changed`(덱에만 있는 파트가 닿은 바뀌는 PID)는 옮기지 않고 보고에 적는다 — 함께 옮길지는 사람 |
| `transform` | 그 PID 요소의 절점에 4×4 를 곱한다. 강체여야 한다(회전부 직교 · 행렬식 1 · 마지막 행 0 0 0 1 — 아니면 거절). 나눈 절점이 있으면 거절(Q4) |
| `morph` | 변위장을 더한다 — **겉면과 안쪽 모두 여러분 값 그대로** 쓴다. 우리 `map` 은 평판 메시를 굽은 구조 메시에 얹는 전용 매핑이라 일반 모프의 안쪽 풀이가 아니다. 변위장의 절점은 그 PID 요소가 쓰는 절점 전부와 정확히 같아야 한다(빠짐 · 남음은 거절). 마지막 판정은 우리 품질 검사(Q5) |
| `remesh` | 그 PID 의 요소와 그 PID 만 쓰는 절점을 걷고, 조각의 절점 · 요소를 **같은 PID** 로 넣는다(새 섹션이면 그 카드를 넣고 `*PART` 의 SECID 를 잇는다). PID 로 건 참조는 그대로 살고, 절점 · 세그먼트 · 요소로 건 참조가 있으면 그 줄은 적용하지 않고 목록을 낸다(결정 — 새 메시로는 정확히 옮길 수 없다) |
| `delete` | 그 PID 의 `*PART` · 요소 · 그 PID 만 쓰는 절점을 지운다. 그 PID 를 가리키는 참조가 있으면(파트 세트의 한 줄 · 접촉의 파트 지정 · 절점 · 세그먼트 · 요소) 지우지 않고 목록을 낸다 — 같은 결정의 원칙(조용히 접촉을 잃지 않는다) |
| `add` | 조각을 새 PID 로 넣는다. 가리킨 SECID · MID 가 덱에 없으면 거절. 물성은 사람이 맞춘다(우리 `matswap` · `matdb`) — 보고에 「새 파트 — 물성 확인」 으로 적는다 |

- **사전 검사는 전부 아니면 전무다** — 한 줄이라도 걸리면 계획 전체를 적용하지 않고 걸린 것을 모두 낸다(덱이 반쯤 고쳐진 채 남지 않게).

### Q2 꼴
- **계획 파일 v1 의 칸을 그대로 받는다.** 모르는 칸 · 빠진 칸은 거절한다(경계 합의). `format` · `version` · `unit`(`mm-t-s`) · `frame`(`world`)이 다르면 거절.
  `files` 의 sha256 · 바이트로 받은 파일을 대조한다.
- **변위장 이진 꼴 그대로** — `<u4` 절점(오름차순 · 중복 없음 확인) · `<f8`×3 변위 · `<u1` 꼴, 차례 · 오프셋은 계획 줄 `field.layout` 에서 읽는다.
- **조각 꼴 그대로** — 기존 PID 를 바꿔 넣는 `*PART`(덱의 SECID · MID 를 가리킴) · 꼴이 다를 때만 새 섹션 카드 · 물성 카드 없음.
- 바꿀 칸은 v2 에 함께 — 아래 Q3 · Q8 의 두 칸을 v2 에 실어 주시면 된다.

### Q3 덱 판
- 계획의 `deck.sha256` 이 우리가 고칠 덱 파일의 sha256 과 다르면 **거절**한다.
- **인클루드가 있는 덱** — 덱 파일 하나의 지문으로는 닫힘 전체를 지키지 못한다. v2 에 `deck.includes: [{relpath, sha256}]` 을 실어 주시면 그 목록까지 대조한다.
  그 칸이 없는데 덱에 `*INCLUDE` 가 있으면 거절한다.
- 적용한 덱의 sha256 을 보고에 돌려준다(PID 마다 결과와 함께) — 그 덱으로 같은 잡을 다시 거시면 된다.

### Q4 나눠 쓰는 절점
- **거절하고 목록을 낸다**(사용자 결정) — 우리 `applyfold` 와 같은 규칙이다(군끼리 절점을 나눠 쓰면 거절 · `disconnect` 로 먼저 뗀다). 계획 줄 `shared_nodes` 와
  변위장 꼴의 넷째 비트(8)를 함께 보고, 우리 덱 리더로 다시 세어 다르면 그것도 낸다.

### Q5 결과 검사
- 적용 뒤 우리 품질 검사(`info` 의 지표 — 뒤집힌 요소 · 야코비안)가 마지막 판정이다. **뒤집힌 요소가 하나라도 생기면 덱을 쓰지 않는다.** 보고에 PID 마다 옮긴 절점 수 ·
  최대 변위 · 품질 전후를 싣는다.
- 그쪽이 다시 재 주시는 것(새 CAD 와의 편차 띠 · 같은 잡을 다시 걸어 바뀐 파트가 `keep` 으로 나오는지)은 그대로 해 주시면 좋다 — 우리 쪽에는 CAD 형상이 없다.

### Q6 번호
- 덱 최댓값 위로 조각끼리 이어서 주시는 것이 맞다. 우리에게는 발행표(`IdAllocator`)가 없다 — 「요청 때 발행」(10-16)이고 두 앱은 서로 부르지 않는다.
- 적용 때 우리 바닥(`id_floor` 와 같은 셈 — 인클루드 닫힘 · 빔 · 이산 · 질량 요소까지)과 조각 범위를 대조한다. 바닥 아래로 걸치면 조각을 바닥 위로 옮겨 넣고 옮긴 폭을
  보고에 적는다(조각 번호는 조각 안에서만 쓰여 옮겨도 뜻이 같다). `unread_cards` 가 있는 덱은 그쪽 `max` 가 낮을 수 있어 이 옮김이 일어난다.

### Q7 섹션 · 물성 참조
- 맞다 — 받는 덱의 SECID · MID 를 가리키고 꼴이 다를 때만 새 섹션 카드. 가리킨 번호가 덱에 없으면 거절한다.
- 새 파트(`add`)의 물성은 사람이 맞춘다 — 우리가 지어 붙이지 않는다.

### Q8 셸 두께가 바뀐 모프
- **StepForge 가 새 섹션 카드를 낸다**(사용자 결정). 꼴은 바꿔 넣기의 `new_section` 과 같게 — 계획 줄 `field.new_section: {secid, thickness, file, why}` 와
  섹션 카드 하나만 든 `section_<PID>.k`(새 SECID 는 덱의 가장 큰 SECID 위).
- 우리는 그 카드를 넣고 그 PID 의 `*PART` SECID 만 그 번호로 잇는다. 같은 섹션을 쓰는 다른 파트는 건드리지 않는다.
- 요소마다 두께를 싣는 덱(셸 요소의 두께 칸)이면 지금은 거절한다 — 그 칸은 바꾸지 않는다.

## 3. v2 에서 보고 싶은 것
1. PID 마다 덱 범위 · 설계 변형의 `snapshot.basis`/`project_id` — 받으면 위 판단을 그 꼴로 다시 본다.
2. Q3 `deck.includes` · Q8 `field.new_section`(+ `section_<PID>.k`).
3. 그 밖의 칸은 v1 그대로면 된다.

## 4. 우리가 지을 것(v2 뒤 — 계획 `docs/01-plan/features/stepforge-carryover-apply.plan.md`)
덱 + 계획 폴더를 받아 — 사전 검사(꼴 · 덱 지문 · 파일 지문 · 변위장 덮음 · 조각 범위 대 바닥 · 참조 · 나눈 절점, 전부 아니면 전무) → 처리마다 적용 → 되읽어 대조 →
품질 관문 → 보고(PID 마다 결과 · 적용 덱 sha256). 이름 · 인자는 지을 때 정해 알린다.
