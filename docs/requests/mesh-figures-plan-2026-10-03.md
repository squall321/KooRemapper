## 3D 렌더링이 필요한가 — 단면에는 **아니다**

| 실측 | 값 |
|---|---|
| 273,600 요소(실제 배터리 적층) 평면 단면, 순수 파이썬 | **0.79~0.83 s** |
| 288,000 요소 합성 패널, 순수 파이썬(별도 측정) | **0.35 s** |
| 1,280 다각형 → SVG | **163 KB** |
| 288,000 요소 → 잘린 요소 | **2,880개 (1/100)** |

모서리∩평면은 **1차 방정식**이다. 반복도 테셀레이션도 법선도 음영도 없으므로 **거짓말할 경로가
없다.** WebGL·GPU·OCC 가 하나도 필요 없고, **단면이 스스로 100배 솎아** 벡터로 내도 글자가
글자로 남는다.

3D 음영이 필요한 자리는 따로다(자유면 뷰). 그것도 메시에서는 `extract-surface` 로 자유면만
뽑아 CPU 로 투영하는 것이고 WebGL 이 아니다.

## 메시에 적합한 것 / CAD 어법 중 버릴 것

**버린다 — 은선 투영(`HLRBRep`).** 은선 제거의 결과로 남는 "보이는 선" 은 결국 자유면 모서리
**89,292개**인데, 그것은 면을 **세기만** 해서 2.25 s 에 나온다(실측). 투영도 깊이정렬도 필요
없다. 게다가 자유면 모서리만 그려도 `ink_ratio` 가 **0.68** 로 이미 포화 근처다. CAD 의 이득
("구멍·모서리가 음영보다 잘 보인다")이 옮겨오지 않는다 — 메시에 구멍은 위상이 아니라 "요소가
없는 자리" 다. **대체물: 특징 모서리**(이면각 필터) → O(10²~10³).

**버린다 — 단면 위 `BRepExtrema` 최소거리 치수.** 정합 메시에서 인접 층은 **절점을 공유**하므로
최소 간극이 구조적으로 **정확히 0** 이다(실측 — `modelmeta` 가 `wrapped.k` 의 두 계면 모두
`gap_min: 0`). "최소 간극" 을 재면 언제나 0 이고 뜻이 없다. **대체물: 층 두께와 반경 `R−z`** —
둘 다 닫힌식으로 안다(탐색 결과가 아니다). 비정합 조립의 간극은 `modelmeta` 의 `gap_avg`
(실측 0.0728 / 0.0449)로 남긴다.

**버린다 — 전체 요소 와이어프레임.** `ink_ratio`(그린 선 길이 px ÷ 캔버스 픽셀)가 1.0 을 넘는
자리는 실측 **약 33,000 HEX8** 이다. 배터리 273,600 요소는 **5.49** — 픽셀마다 평균 5.5번
칠한다. 자유면만 그리면 **0.68**(8.1배 감소). 전체 면 843,123 중 자유면은 **44,646(5.3%)** 뿐
이므로 **90% 가 묻혀서 안 보이는 선**이다.

**버린다 — 등각(isometric) 칸을 적층에 쓰는 것.** 실측 — 배터리 덱(75.003 × 71.7065 × 2.478)을
1200×900 등축으로 그리면 적층 60장 **전체가 28.19 px** 이고 다섯 층 유형이 **전부 1 px 미만**
(0.091 / 0.137 / 0.228 / 0.739 / 0.796). 가장 얇은 층을 1 px 로 만들려면 적층축을 **×11.0**.
`75.003 / 0.008 = 1 : 9,375` 다.

**메시에서 더 강해지는 것 — 겹침.** CAD 의 "과제끼리 나란히" 는 파트를 이름으로 짝짓고 신뢰도를
달아야 한다(StepForge D-444~447). **메시 덱 쌍에는 그 문제가 없다** — 절점 번호가 짝이고
KooRemapper 가 그것을 **요구한다**(§44.6·44.7). 그래서 나란히가 아니라 **겹침**이 된다.
실측 — `arm_flat.k`/`arm_folded.k` 둘 다 96절점·24요소·4파트, `wrapped_neutral.k`/`wrapped.k`
둘 다 600절점으로 번호가 같다.

**그대로 베낀다 — StepForge `core/figure.py` 의 함정 16개 전부.** 그 파일은 기하를 한 줄도 안
만지고, `*PART` 제목은 STEP 라벨과 똑같이 자유 텍스트이며, 같은 챗 호스트가 같은 규칙으로
자른다. 1차는 의존성 0 이라 matplotlib 을 안 쓰지만 **규약은 지킨다**(§안전·텍스트 동반·한 자리).

## ① 의 구체안

**입력** — `wrapped_neutral.k`(중립면을 축 0 으로 옮긴 평면 적층)와 `wrapped.k`(감긴 적층).

**출력** — 한 장에 두 칸. 왼쪽은 평면 적층 단면에 **`z=0` 선과 중립축 선을 둘 다**, 오른쪽은

각각 둔다. ⚠ 과장 비율을 숨기면 그림이 거짓말한다 — 적는 것이 기능의 일부다.

**함께 찍는 텍스트**(LLM 은 픽셀을 못 본다) — 자른 평면과 **왜 그 축인가** · **맞은 파트 수/전체**

## 배치

- 단면 계산은 **C++ op** 이다. 퇴화 PENTA6 정규화(`KFileReader.cpp:19-76`)·파트/재질 접근이
  이미 C++ 에 있다. 파이썬으로 짜면 **파서가 둘이 되어 갈린다**(D-236 과 같은 부류).
- ⚠ **면 테이블(`Element.h:99-124`)로 짜면 TET4 가 틀린다**(실측). TET4 는 `n5..n8 = n4` 로
  저장되는데 `isFaceDegenerate` 는 `fn[0]==fn[1] && fn[2]==fn[3]` 만 보므로 **변으로 찌그러진
  가짜 면(고유절점 2개)을 못 걸러낸다** — 면 0 은 `[n0,n3,n3,n3]`, 면 3 은 `[n3,n2,n3,n3]` 이고
  둘 다 `isFaceDegenerate=False` 로 통과한다. 그래서 **모서리 기반**으로 짠다 — 종류별 모서리 표
  → 모서리∩평면 교점 → **중복 제거** → 절단면 2D 기저에서 **각도 정렬**. 퇴화 저장이 만드는
  겹친 교점이 중복 제거로 사라지므로 종류에 둔감해지고, 면 테이블의 TET4 결함을 **피해 간다.**
- ⚠ 각도 정렬은 **볼록**일 때만 맞다. 요소가 뒤집히면(음수 야코비안) 순서가 틀려 채움이 거짓이
  된다 — 그래서 음수 개수를 함께 찍는다(A-10). 추적 덱 489장 중 111장이 그 경우다.
- ⚠ `getValidFaceIndices()` 가 TET4 의 가짜 면을 통과시키는 것은 **이 op 밖의 문제이기도 하다**
  — 자유면 추출이 그것을 쓰면 TET 덱의 표면이 틀릴 수 있다. 확인해서 따로 보고한다(손대지 않았다).
- op 은 **좌표(다각형 꼭짓점 + pid) + 매니페스트**를 낸다. 그림은 `ReportVisuals.tsx` 가 이미
  하는 방식(인라인 SVG + 그림 안 범례 + canvas 경유 PNG)으로 그린다 → **그래픽 의존성 0**.
- MCP 는 **매니페스트를 텍스트로 + SVG 다운로드 URL** 로 낸다. `Image` 블록은 2차.
