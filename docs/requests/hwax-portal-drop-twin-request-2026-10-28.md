# HWAX 포털에 드리는 요청 — 낙하 트윈 (2026-10-28)

**보내는 곳** DynaForge(KooRemapper) · 후처리 모듈
**받는 곳** HWAX Portal(절차 · 실행기 · 앱 등록·배포) · 필요하면 HWAXProd 운영
**성격** 요청입니다. 꼴은 제안이고, 포털 쪽 결정을 따릅니다.
**총괄 계획** `docs/01-plan/features/drop-twin-1028.plan.md` — 계약 번호(C-n)·단계(Pn)는 그 문서와 같습니다.

---

## 1. 한 줄
1,000방향 낙하 결과를 **변형까지 볼 수 있게** 하려고 세 포지(DynaForge · StepForge · 새 장면 포지 SceneForge)가 나눠 만듭니다. 세 포지는 서로를 부르지 않고 파일로만 주고받기로 했으므로, **사슬을 잇는 일과 stcx·viz 노드로 가는 길이 포털에 걸려 있습니다.**

## 2. 바탕이 되는 결정
- **09-17 (W-93)** — DynaForge 가 클러스터에 후처리 잡을 걸고 리포트 HTML(약 10 MB)만 받는다. d3plot(잡 하나 37~50 GB)은 나르지 않는다.
- **10-28** — 그 원칙을 지키면서 후처리 잡 안에서 **경량 추출본(S1)** 을 함께 만든다(10-28 원형 실측 — 상태 전부를 담으면 각도당 204–670 MB, §7). 위험 각도 화면과 사진급 렌더는 이 추출본에서 그린다.
- **viz 노드** — cae00 의 viz 노드 10대(RTX PRO 6000 ×2)에서 사진급 렌더와 (선택) 대리모델 학습을 돌린다.

## 3. 부탁 여섯
### ① C-1 stcx 실행 기록에 각도별 경로를 더해 주십시오
- 지금 DynaForge 가 stcx 잡에서 받아 두는 칸은 `registry_id` · `slurm_job_ids` · `work_dir` · `output_dir` 입니다.
- 후처리 잡이 S1 을 만들려면 **각도마다 run 폴더와 d3plot 경로**가 있어야 합니다. 잡 상태 응답이나 결과 목록에 이 둘을 실어 주실 수 있을지 여쭙니다.
- 덧붙여 KR-10(stcx `job_status` 상태 칸 고정)도 이 응답 원문으로 같이 닫을 수 있습니다.

### ② C-13 실행기에서 viz 노드를 고를 수 있게 해 주십시오
- 렌더 잡은 GPU 가 있는 viz 노드에서 돌아야 합니다. 지금 실행기 계약(K1~K7, h02·h03 분배)에 **노드 종류(gpu/viz)를 지정하는 칸**을 더해 주실 수 있을지 여쭙니다.
- 앱은 노드를 직접 고르지 않고, 지금처럼 실행기가 고르는 규율을 그대로 지키겠습니다.

### ③ 새 포지 SceneForge 등록 (이름은 10-28 확정)
- **HEAX manifest 2엔트리** — 웹(proxy · `portal_auth: true`)과 MCP(직결 · `portal_auth` 없음). DynaForge 와 같은 꼴입니다.
- **게이트웨이 공유 시크릿과 PAT** — `POST /auth/sso/verify` 를 처음부터 둡니다(표준 위임 점검 — DynaForge KR-18 과 같은 계약).
- **포트** — 제안은 API 8710 · MCP 8711 · Postgres 5437 입니다. PORT-MAP 에서 정해 주십시오.
- **배포** — `deploy-all-from-drive.sh`·update-all 편입과 Drive 미러. 렌더 작업자 이미지는 viz 노드에 깔려야 해서 노드 쪽 배포 길도 필요합니다.

### ④ 절차 R2 를 넓혀 주십시오
- 지금 R2 는 「잡 제출 → 후처리 → 리포트 반입 → 판독」 입니다.
- 여기에 **(신규) S1 추출 → (신규) 렌더 요청(C-10) → 렌더 결과 반입(C-11)** 을 잇는 단계가 붙습니다.
- 셋 다 오래 걸릴 수 있으니 `expect: job` 규칙(제출 · 회수 두 절차)을 따르겠습니다. 상태 조회 도구도 함께 내겠습니다.
- DynaForge 의 후처리 연산은 09-16 요청서의 ① 꼴(`run_operation` 의 `operation="postprocess"` + `args_schema`)로 내겠습니다. 포털 절차가 한 줄도 안 고치는 쪽입니다.

### ⑤ C-12 시험 영상과 카메라 교정을 넘길 길
- 실물 시험 재현에는 고속 카메라 영상, 카메라 위치·렌즈, 촬영 fps, 충돌 시각이 필요합니다.
- 시험실 자료가 어디 있는지, 포털이 그것을 SceneForge 로 넘기는 길을 낼 수 있는지 여쭙니다.

### ⑥ viz 노드가 S1 추출본을 읽는 길
- 추출본은 클러스터 저장소(d3plot 옆)에 생깁니다. viz 노드는 cae00 쪽이라 **저장소가 다를 가능성이 큽니다.**
- 렌더는 한 번에 한 각도만 쓰므로 **요청한 각도만 복사**하는 길이면 충분합니다(각도당 204–670 MB — 10-28 원형 실측, 1,000각도면 0.2–0.7 TB). 마운트로 읽을 수 있다면 더 좋습니다.
- 어느 쪽이 되는지 알려 주십시오. 대리모델 학습(S4, 선택)은 1,000각도 전부가 필요해서 그때 다시 여쭙겠습니다.

## 4. 우리가 지킬 것
- 포털 요청서(09-16) §4 의 넷 — 지어내지 않는다 · 성패를 본문으로 · 경고를 버리지 않는다 · 산출 위치를 구조로.
- 기존 잡 무변경 — 지금 리포트와 판정은 그대로입니다. 새 단계가 실패해도 R2 의 기존 결과는 영향이 없습니다.
- 정본 재계산 금지 — 파트별 최대 응력의 정본은 반입 리포트입니다. 추출본과 렌더는 보기 전용입니다.

## 5. 여쭐 것
1. ①의 각도별 경로를 stcx 응답에 실을 수 있는지, 아니면 `output_dir` 아래 규칙(폴더 이름 꼴)으로 우리가 찾아야 하는지
2. ②의 노드 종류 칸을 실행기 다음 판에 넣을 수 있는지
3. ⑥에서 viz 노드가 클러스터 저장소를 마운트할 수 있는지
4. SceneForge 이름이 확정됐습니다(10-28) — 등록 순서(HEAX · 게이트웨이 · PORT-MAP · deploy-all)를 어떻게 밟으면 되는지
5. ⑦ — 지금 tbot 봇의 역할이 viz 노드 SSH 를 허용하는지, 아니면 봇에 viz 노드를 더하거나 SceneForge 용 봇을 따로 둬야 하는지

## 6. 급한가
**P0(확인·실측) 단계에서 ②와 ⑥의 답이 필요합니다.** viz 노드에 GPU 잡을 보낼 수 있는지, 추출본을 읽을 수 있는지가 설계를 가릅니다. 나머지는 P1 이후입니다.

## 7. 덧붙임 — P0 결과와 결정 (10-28 저녁)
보내기 전에 오늘 P0 실측과 사용자 결정을 반영했습니다. 측정 전체는 KooRemapper `docs/04-report/drop-twin-p0-1028.report.md` 입니다.

### ⑦ (새 부탁) viz 노드 접근 — STE 와 같은 Teleport tbot 경로
- 사용자 결정 — SceneForge 의 viz 노드 확인은 STE 가 쓴 tbot(Machine ID) 경로로 합니다(`docs/ste-cae00` D-31 · `docs/cae00-deploy-guide.md`).
- 여쭐 것 — 지금 cae00 의 tbot 봇 역할이 viz 노드 SSH 까지 허용하는지입니다. 아니면 봇에 viz 노드를 더하거나 SceneForge 용 봇을 따로 둬야 합니다. 개발 박스에는 tsh · tbot 이 없습니다.
- 노드에서 먼저 할 일은 읽기 확인입니다(nvidia-smi -q · 드라이버 · `/etc/os-release` · 메모리 · 디스크). MIG 모드 전환과 파티션은 GPU 재설정이 필요해 남의 잡을 끊을 수 있으므로, 노드 관리자와 시간을 잡고 하겠습니다.

### 사용자 결정
- 새 포지 이름 **SceneForge 확정**. 리포를 만들었고(로컬 — GitHub 비공개 저장소는 곧), 개발은 전용 Claude 세션이 하고 사용자가 검토합니다.
- USD 는 SceneForge 가 StepForge 의 glb + 파트 표에서 만듭니다(D-9). 외관은 CAD 색 + 재질 이름별 라이브러리(D-7).
- 원본 d3plot 정리 승인은 사용자 본인입니다(D-4).
- NVIDIA 라이선스 서면 확인은 SceneForge 몫입니다. 공개 문서상 Omniverse 는 2026-05 부터 개발 · 운영 · 재배포가 무료이고 지원만 유료입니다.

### 실측 (포털과 닿는 것만)
- **S1** — 상태 4,952개 전부를 담은 원형이 각도당 204–670 MB(d3plot 18.2 GB 의 1.1–3.7%), 2–4분 · 2.6 GB 입니다. 정식 꼴(상태 솎기 · 파트별 스케일)로 줄일 여지가 큽니다.
- **1,000각도 리포트** — 약 484 MB 입니다(앞서 적은 1 GB 는 틀렸습니다). DynaForge 상세 질의는 22초 → 6.7초로 고쳤고(`288afb7`), 블록 분리는 P1 입니다.
