### ② `KFileWriter` 가 `*NODE` 를 id + x + y + z 로 줄여 쓴다 — 한 결함, 두 증상

`src/parser/KFileWriter.cpp:292-296` 을 직접 확인했다.

```cpp
file << std::setw(8) << node.id
     << formatDouble(pos.x) << formatDouble(pos.y) << formatDouble(pos.z)
     << std::endl;
```

- **TC/RC 칸이 애초에 쓰이지 않는다.** 그 파일에 `tc|rc|constraint` grep **0건**. 전 자유도 구속
  (`TC=7 RC=7`)을 준 노드가 **구속 없는 노드로 바뀐다.** rc=0 이다.
- **ID 칸이 `setw(8)` 로 못 박혀 있다.** 좌표는 `coordFieldWidth_` 로 파라미터화돼 있는데 ID 는
  아니다. 원본 줄의 `*KEYWORD I10=Y` 는 그대로 베껴 나가므로, 선언은 10칸인데 본문은 8칸인
  덱이 나온다 — 이 리포 자신의 시험(`test_i10_card_width.py`)이 단언하는 계약과 어긋난다.

`KFileWriter` 를 만드는 자리가 **9곳**이고 걸리는 op 은 map·shellmap·unfold·squeeze·tetremesh·
generate·indent·bend 계열이다. `201e0c8`/`9150ee6` 이 고친 것은 ModelAssembler·meshfix 경로였고
이 경로는 안 밟혔다. 고치는 길은 이미 반쯤 깔려 있다 — `coordFieldWidth_` 의 전례대로
`idFieldWidth_` 를 두고 덱 폭에서 채우면 된다.

**왕복 회귀가 이것을 못 잡는 이유가 구조적이다** — LF 판과 CRLF 판을 **서로** 비교하므로
양쪽에서 똑같이 잃으면 초록이다.

## 5. 초록 뒤의 구멍 — 시험이 지켜 주지 않는 것

- **`ctest 1/1` 은 이 캠페인에 대해 아무 말도 하지 않는다.** 단언 52개가 전부 기하
  (Vector3D·Mesh·Element·Node·Interpolation·Mapping)이고, `KFileReader`·`DeckWriter`·
  `ModelAssembler`·`ReferenceIntegrity`·`SetDef` 를 언급하는 단위 시험은 **0건**이다. 덱 계약
  보증은 100% `tools/regress` 파이썬에 얹혀 있다. 여러 커밋이 근거로 나란히 적은 "ctest 1/1" 은
  덱 계약에 관해서는 신호가 아니다.
- **누락 축이 1/40 만 잠겨 있다.** 오탐 축(QUIET)은 픽스처 7장으로 촘촘한데, 실제 결함으로 확인한
  40장 중 회귀가 이름으로 못 박은 것은 **1장**뿐이다. 검사가 약해지면 나머지 39장이 조용해져도
  회귀는 초록이다 — `3a84739` 가 겪은 사고("회귀가 오탐을 지키고 있었다")의 **거울상**이다.
- **회귀 두 시험이 matdb 레인을 조용히 건너뛴다**(`test_help_truth.py:399` ·
  `test_yaml_inline_comments.py:85`). 동작 자체는 정상이라 결함은 아니고 커버리지 구멍이다.
- **MSVC `\r\r\n` 갈래는 어느 플랫폼에서도 안 돈다.** 리눅스에서는 우연히 초록, 윈도우에서는
  아무도 안 돌린다. "변이 19건 중 18건" 의 그 하나가 이 자리다.
- **덱 쓰기 6곳은 `DeckWriter` 를 지나지 않고 스스로 개행을 붙인다.** 허용 목록 관문은 **수**만
  센다 — 선언은 맞는데 값이 틀린 부류는 안 잡는다(`e841e5a` 가 고친 동반 파일 3곳이 정확히 그 부류였다).

## 부록 — 감사 방법과 감사 자신의 오류

7갈래(P0 · P1 · P2+약속 · 검증실행 · 배포 · 미결전수 + 완결성비평), 읽기 전용, 빌드 금지,
리포 루트에서 op 실행 금지. 비평이 plan2 항목 번호를 전수로 세어 **29개 전부 감사됨**을 확인했다.

비평이 잡은 사실 오류 6건. 이 목록을 남기는 이유는 다음 감사도 같은 함정을 밟을 것이기 때문이다.

1. **"커밋 4건 미푸시" 는 틀렸다.** 두 갈래가 이것을 최우선 경보로 올렸는데, `git push` 를
   **URL 로** 했어서 로컬 `origin/main` 참조만 낡아 있었다. 실제 원격은 이미 HEAD 였다.
   → **푸시 판정에 로컬 `origin/main` 을 쓰면 안 된다. `git ls-remote` 를 쓴다.** (오늘 `git fetch`
   로 맞췄다.)
2. 배포 자리 `GLIBC_2.38` 은 감사 중에 해소됐다(오늘 재빌드).
3. 그 재빌드로 검증 갈래의 바이너리 md5 근거가 무효가 됐다(회귀 결과 자체는 유효하고, 새
   바이너리로 52/52 를 다시 확인했다).
4. "리포 `materials/` 에 `material_db.json` 이 없다" 는 사실이 아니다(1.27MB 추적 파일 실재).
5. 모집단 숫자가 틀렸다(489장).
6. **없는 경로에 grep 을 걸어 0건을 얻고 그것을 부재의 증거로 썼다.** "문서를 믿지 마라" 가
   "grep 결과도 **경로를 확인하고** 믿어라" 까지 가야 한다.
