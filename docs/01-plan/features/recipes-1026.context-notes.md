# 레시피 결정 노트 (2026-10-26)

## 1. 실데이터 실행은 플랫폼 잡, 제안 시험만 API 안에서 바로
설계 설명(사용자에게 보인 글)에 「실행은 플랫폼 잡으로 합니다. 세션 소유 · 슬롯 4개 · 로그 · env_snapshot을 그대로 씁니다」라고 적었다.
그대로 한다. 잡이면 CPU 슬롯을 바이너리 잡과 나눠 쓰고, 취소 · 로그 · 산출 파일 · 세션 소유가 따라온다.
제안할 때의 자기 시험은 리포트를 읽지 않는 작은 계산이라 잡으로 돌리면 LLM 이 한 번 더 기다려야 한다 — API 안에서 같은 샌드박스로 바로 돌린다(동시 2 · 60초).

## 2. api.sif 에는 numpy · scipy 가 없다 — 설계 글의 정정
설계 글에 「api.sif의 파이썬 3.12로 돌리고, numpy와 scipy는 들어 있습니다」라고 적었는데 틀렸다.
10-26 `python3 -I` 로 재 보니 이미지에는 없고, 앞서 본 numpy 2.4.5 · scipy 1.17.1 은 호스트 `~/.local`(apptainer 가 홈을 붙인다)의 것이었다.
샌드박스는 `-I` 라 사용자 site 를 안 본다(봐서도 안 된다 — 박스마다 다르다). 그래서 이미지에 넣는다. 나머지 패키지는 지금 이미지의 판으로 고정한다 —
다시 구우면서 fastapi · pydantic 판이 따라 바뀌면 이번 일과 상관없는 동작이 바뀐다.

## 3. 커밋 · 푸시는 API 가 하지 않는다
「등록 시 git」 은 등록하는 순간 `platform/recipes/<이름>/` 에 파일을 쓰는 것까지로 했다. 커밋 · 푸시는 `tools/recipes_publish.sh` 가 한다. 까닭은 셋이다.
- 재부팅 때 HWAXPortal 이 개발 트리를 `reset --hard origin/main` 한다. **커밋했지만 안 민** 파일은 그때 지워지고, 커밋하지 않은 새 파일은 남는다.
- 다른 세션이 같은 브랜치에 동시에 커밋한다. 서버 프로세스가 중간에 끼어 커밋하면 남의 스테이징과 섞인다.
- 푸시는 바깥으로 나가는 일이다. LLM 의 등록 한 번이 사람 확인 없이 GitHub 으로 가게 하지 않는다.

## 4. 일곱 번째 도구 `recipe_deprecate`
선택지 글에 「사람은 내리거나 지울 수 있다」고 적었다. 사람이 Claude 에게 「이 레시피 내려」라고 할 길이 있어야 해서 도구를 하나 더했다.
설계 글의 「고정된 여섯 개」 는 「레시피가 늘어도 도구는 그대로」 라는 뜻이었고 그것은 지킨다. 내리기는 올린 사람 · 관리자만, 까닭을 남긴다.

## 5. 누구나 새 판을 올릴 수 있다 — 대신 앞 판의 시험을 통과해야 한다
경험이 쌓이려면 남의 레시피도 고칠 수 있어야 한다. 그 대신 새 판의 `run` 으로 앞 등록 판의 시험을 다시 돌려 전부 통과해야 등록된다.
결과 꼴을 일부러 바꾸는 판은 새 이름으로 올린다. 판은 바뀌지 않으므로 앞 판은 기록으로 남는다.

## 6. 파이썬 층만으로는 모자라다 — 커널 층을 더했다
AST 검사 · 제한 builtins · 감사 훅은 우회 사례가 알려져 있다. API 인스턴스 환경에는 DB 주소 · JWT 비밀 · 게이트웨이 토큰이 있고, 같은 사용자라
`/proc/<API>/environ` 과 `/workspace/platform/.env` 를 읽을 수 있다. 그래서 Landlock(읽기 뿌리 · 쓰기 0)과 seccomp(소켓 · kill · ptrace …)를 겹으로 둔다.
10-26 탐침에서 둘 다 api.sif 안에서 켜졌다. 커널 층이 없는 박스(prod 커널 미확인)에서는 파이썬 층만 남는다 — 실행 기록의 `sandbox` 칸이 말한다.

## 7. 탈출 시험은 미끼 파일로
탈출 시험은 시험이 만든 미끼 파일(읽기 뿌리 밖)을 읽으려 해 본다. 진짜 비밀 파일(`platform/.env`)은 열어 보지 않는다.
