# HWAX 요청 결정 노트 (2026-10-27)

## 1. KR-03 은 부호 버그가 아니다 — 재현으로 가렸다
요청서는 원인을 'acos 인자 범위'로 짐작했고, 소스엔 10-01 '부호 버그 고침' 주석이 있다. 둘 다 KR-03 의 실제 원인이 아니다.
부호 고침(`22c7f9e`)은 배포본(`44f16c9`, 10-17)에 이미 있다. 재현(standalone)으로 **`else` 한 실근 가지**가 범인임을 확인했다 —
대칭 텐서는 늘 세 실근인데 고유값이 겹치면 판별식 `q²/4+p³/27` 이 반올림으로 미세 양수(스케일 1e12 대비 +260)로 떠 그 가지로 빠지고
세 주응력을 같게 만든다. 변형률 매개화(`r=(I1²-3I2)/9`, 한 실근 가지 없음)로 바꾸면 요소1·2 모두 정답(2841.058/1217.596/1217.596).
소스 주석도 "StrainTensor 쪽은 맞으니 건드리지 말 것"이라 했다 — 그 꼴을 응력에 쓴다. [[feedback-dont-invert-diagnosis]] [[feedback-lsdyna-zero-is-default]]

## 2. 내 재현은 전단 0 요소도 틀렸다 — 요청서는 맞다고 함
요청서는 요소1(전단 0)은 배포본에서 맞다고 했는데, 내 inline 재현은 둘 다 틀렸다(det 계산 경로가 달라 판별식 부호가 갈린 듯).
어느 쪽이든 결함은 퇴행 고유값 전반이라 고치면 둘 다 안전하다. 고침 뒤 두 요소 다 회귀로 박는다.

## 3. KR-01 은 '짐작 금지' 설계를 깨지 않는다
`resolve_task` 는 exact·alias(짐작 없음)만 푼다. task_code 도 **exact 동등**으로만 더한다(정규화 일치는 여전히 후보).
과제코드가 유일 식별자라 exact 는 안전하다. dev_revision key(과제 key + 코드)도 과제명 기준이 된다는 것을 설명에 적는다.

## 4. KR-02 는 path 변환 — 기존 소비자 깨지지 않게
`{task_key:path}` 로 바꿔도 '/' 없는 key 는 그대로 동작한다. MCP 는 `quote(safe='')` 로 인코딩만 더한다.

## 5. KR-04·05·09 는 인프라 — 저쪽(포털) 반쪽과 독립
우리 반쪽만 넣는다. KR-04 표지는 포털 deploy-all 이 만든다(6절). 우리는 표지가 **있으면** 건너뛰기만. 없으면 지금과 같다.
KR-05 자동 채움은 AIDataHub `_common.sh` 꼴을 따른다. KR-09 는 'no crontab for' 만 빈 목록으로.
