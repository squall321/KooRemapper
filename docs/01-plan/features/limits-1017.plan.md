# 한계 여섯 — 작은 셋 · 큰 셋 (2026-10-17)

**날짜** 2026-10-17 · **요청** 「말고 또 할거 남았나」 → 「셋다 고치는게.낫겠는데」 · 결정 넷은 권장안(AskUserQuestion)

## 왜
4차 배포(`1164d8ed` · SIF v117) 뒤 「알고 남긴 한계」가 여섯이다. 작은 셋은 정본을 두 번째 소비자에게 붙이는 일이고,
큰 셋은 지금 **거절하거나 null 로 막아 둔 자리**를 실제로 푸는 일이다. 사용자가 여섯 모두 고치기로 했다.

## 결정 (사용자 2026-10-17)
1. 범위 — 작은 셋 + 큰 셋 모두. 끝나면 빌드부터 SIF 까지 다시 배포한다(상시 지시).
2. 2차 솔리드 값 — **코너로 잰 값을 낸다** · `geometry_basis: corners` 로 표시한다.
3. 고쳐 쓰는 op 의 인클루드 — **`flatten_includes: true` 를 줄 때만** 닫힘을 펼쳐 홀로 서는 한 파일로 고친다. 주지 않으면 거절.
4. 재결속 공차 — 기본은 정확 일치 · **`tolerance` 를 줄 때만** 공차.
   (결정 없이 넣기로 한 것 — 재결속의 인클루드 덱 받기 · 파트 감쇠·초기응력 카드 받기)

## 작은 셋
- **S1 hfdamp 거절 종료 코드 255 → 1.** `hfdamp_apply` 가 −1 을 돌려 셸이 255 로 받는다. 다른 op 은 거절이 1 이다.
- **S2 cleanup-nodes 의 인클루드 걸음 → 정본 `include_closure`.** 세 패스(섹션 · 참조 · bbox)가 각자 8단 재귀를 돈다.
  정본은 `␣+` 이음 이름 · 인클루드 안 `*END`(그 파일만 끝) · 깊이 상한을 「못 봤다」로 알리기를 안다. 큰 덱(2.32GB)을
  담지 않는 전제는 지킨다 — 주 덱은 흘려 읽고 인클루드 카드만 모아 정본에 넘긴다.
- **S3 `cleanupDeadNodeRefs` 의 목록 칸 범위 → 정본 `NodeRefs` 표.** 세트(1-8 · 칸 1 · 2-8) · 세그먼트(1-4) · 이력(1-8)이
  두 곳에 따로 있다. 세트 분류도 정본(`classifySetNode`)을 쓴다 — 고치는 쪽은 `_ADD` 만 건너뛰어 `_INTERSECT` 를 절점 목록으로
  읽는다(돌려서 확인한다).

## 큰 셋
- **B1 2차 솔리드 리더.** 리더가 `*ELEMENT_SOLID` 절점 칸의 앞 8개만 담는다. 그래서 TET10 은 중간절점이 코너 자리로 들어온
  육면체가 되고(그림 셋 거절 · modelmeta null · info 고아 상한) 재결속이 소속을 다 못 본다.
  - 담는 곳 — `Mesh` 에 EID → 덱 순서 전체 절점(**2차 요소만** — 1차 덱은 메모리가 늘지 않는다).
  - 코너 — ELFORM 16·17(TET10)은 N1..N4(매뉴얼 Fig 19-31) → `nodeIds` 를 TET4 꼴로 · 종류 `TET10`.
    23·24·29(육면체)는 지금처럼 앞 8칸이 코너다. **25·26·27·28 은 매뉴얼 본문에 코너 차례가 없다**(그림뿐 · Remark 16
    「개발 중」) — 절점은 다 읽되 기하는 지금처럼 거절·null 로 둔다.
  - 카드가 모자란 2차 요소(노드를 8+2 로 쪼갠 덱)는 기하를 거절한다(매뉴얼 Card 2 는 N1..N10 한 장이다).
  - 소비자 — `bboxReport`(고아) · modelmeta(`geometry_basis` · `n_node` · `bbox`) · info(고아 · 야코비안) · 그림 셋 ·
    재결속(소속) · `KFileWriter`(2차 요소를 전체 절점으로 쓴다 — 없으면 쓰지 않는다).
- **B2 재결속.** `tolerance`(같은 파트 제목 안 · 거리 안에 하나일 때만 · 여럿이면 못 풂 · 요소는 짝지은 절점 집합으로) ·
  인클루드 덱(닫힘을 **다** 읽어야 받는다) · `*INITIAL_STRESS_*`·`*DAMPING_PART_*` 카드(칸 자리는 정본 `IdRefs`).
- **B3 `flatten_includes`.** 실측(모든 op 사례를 주 덱 + `*INCLUDE` 로 쪼개 다시 돌림) — 고쳐 쓰는 op 14개가 rc 1,
  10여 개가 rc 0 인데 산출이 다르다(조용한 무편집 포함).
  - 정본 — `include_closure` 에 「홀로 서는 줄로 펼치기」(인클루드 카드를 그 파일 본문으로 바꾼다 · 닫힘이 다 읽혀야 한다).
  - 붙이는 곳 — 엔진(`ModelAssembler`) 한 곳이 assemble 과 단독 op 13개를 덮는다 · 줄 기반 op 은 각자.
  - 옵션이 없을 때 — 대상 파트가 인클루드 안에 있으면 **거절**하고 옵션을 안내한다(조용한 무편집을 거절로).

## 순서
S1 → S3 → S2 → B1 → B2 → B3 → 문서 → 배포. 각 단계는 시험을 먼저 쓰고(돌연변이로 빨개지는지 본다) 커밋 · 푸시한다.
