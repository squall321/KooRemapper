# 맥락 노트 — StepForge 조각 삽입

## 2026-10-16
- **입력이 실재한다.** 저쪽 `1425fcf`(조각 내보내기)·`540f89f`(경계 문서 확정본). 저쪽 리포를 고치지 않고 읽기만 했다.
- **이름은 아직이다.** 플랫폼 카탈로그의 op 이름이 곧 CLI 이름이라(60개 중 59개가 CLI 이름 그대로) 새 op 을 넣는 순간
  사용자에게 이름이 보인다. 이름은 확인받고 정한다(메모리 「Confirm Naming First」). 그래서 이름이 안 보이는 핵심부터 짓는다.
- **JSON 파서를 새로 둔다.** matdb 의 `md_parseJson` 은 너그럽다(`\uXXXX` 를 안 풀고 오류를 말하지 않는다). 계약 리더는
  「모르는 칸은 거절」이라 엄격해야 한다. matdb 를 옮기면 그 동작이 바뀐다 — 옮기지 않는다(두 파서의 뜻이 다르다).
- **sid 는 10자리까지**(저쪽: 9,999,999,999 를 받는다) — int32 를 넘는다. `ranges` 는 int64 로 읽는다.
- **`coord_sha` 가 저쪽과 같은 값이다(실측).** 저쪽 식을 파이썬으로 돌린 기댓값 셋(정육면체 모서리 · 음수·음의 0·
  세 자리 지수 · 한 점)과 C++ 값이 같다. C 의 `%16.9e` 와 파이썬 `f"{v:16.9e}"` 는 세 자리 지수에서 둘 다 17칸으로
  넓힌다. 덱에서 읽은 좌표(10 유효 자리)는 double 로 왕복해도 같은 글로 돌아온다.
- **조각의 노드 줄은 음수 좌표와 붙는다**(`       9-3.000000000e+01…`) — 리더가 고정폭으로 읽어 맞다(시험에 넣었다).
- **이름은 경계 문서 그대로 `cad_solid_merge_to_deck`.** 사용자에게 추천안(두 리포 문서가 같은 이름 · 밑줄 선례
  `stcx_fullangle_drop`)과 하이픈 대안을 올렸고, 답이 「다 끝까지 마무리해」였다 — 앞서 「권장안대로」라고 한 것과 같은
  뜻으로 받았다. 바꾸려면 CLI 분기·카탈로그·도움말 원본 세 곳이다.
- **저쪽 실물 조각이 대조를 통과했다**(`coord_sha` 4/4) — 저쪽 라이브 시험 산출(`var/work/a50/K2/live/…`)을 읽기만 해서
  예제·회귀 픽스처로 옮겼다(합성 과제 K2라이브-B).
- **PID·SECID·MID 는 한 이동량**(세 공간의 최대값 중 가장 큰 것 위로). 저쪽 규약(셋이 같은 번호 · `ranges.pid` 가 셋의
  대역)을 덱 안에서도 세우려고 — 낮은 공간에서 번호 몇이 비는 것은 해가 없다.
- **쓰기 뒤 검증이 블록을 안 보고 있었다**(`f6cd30b`) — 블록만 넣는 op 은 건드린 파트가 비어 대조가 건너뛰어졌다.
- **도움말 실행기의 `*PART` 제목 판정**(`fbb633a`) — 제목 앞 `$# 이름` 주석(저쪽 조각 꼴)을 제목으로 못 봤다.
- **2줄 혼재 훑기가 조각까지 2줄로 바꿨다** — 솔리드 두 줄 꼴(EID PID / 절점)은 LS-DYNA 에서 합법이라 같은 규칙으로
  옮기게 했다. i10 훑기는 조각까지 i10 으로 바꿔 이 op 이 「조각은 표준 폭」으로 거절한다 — 그 훑기는 rc 를 안 보고 산출
  칸 폭만 봐서 **헛통과**한다. 「i10 덱 + 표준 조각」은 `test_cad_solid_merge.py` C 가 본다.
