# 결정 노트 — 없는 절점을 가리키는 카드

- **(2026-10-16) 찾은 길.** 2차 솔리드 작업에서 「고아 절점을 지우는 op 이 같은 뿌리로 덱을 깨나」를 재다가,
  meshfix 를 돌려 보니 다시 짠 파트의 옛 절점을 세트·SPC·이력이 그대로 가리켰다. 원장의 P2-6 이 이미
  「meshfix 는 하나도 고치지 않는다」고 적었고 **그 말이 지금도 사실**이다(실측).
- **바꿔 쓰기보다 잡기가 먼저인 까닭.** `--strict` 가 못 잡으면 meshfix 말고도 같은 덱을 만드는 길(손편집 ·
  다른 도구)이 다 통과한다. 그리고 meshfix 는 `boundary_nodes: fixed` 로 표면 절점 번호를 이미 지킬 수 있다 —
  재결속 없이도 쓸 길이 있다.
- **오탐 규율.** 절점 정의는 `*NODE*` 블록 첫 칸을 **넘치게** 모은다(놓칠 수는 있어도 없는 것을 있다고 말하지
  않는다). 확실한 갈래만 본다. 실사용 덱 전수로 새 경보를 하나하나 본다.
- **줄마다 한 건.** 전체 절점 세트(1,300만 멤버)가 통째로 매달리면 「카드 N건」이 수백만이 된다. 플랫폼이 그 수를 읽으므로
  줄마다 첫 번호와 개수로 낸다. 같은 까닭으로 정본은 키워드 글자를 참조마다 담지 않고(`kwLine`), 거르는 조건(`keep`)을 받는다.
- **조각 덱.** 맨 `*NODE` 가 하나도 없으면 단정하지 않는다 — 플랫폼 실측(2026-09-27)에서 단정 등급 148장 중 147장이
  조각 때문의 오탐이었다. 그 규율을 절점 축에도 그대로 둔다.
- **meshfix 는 원문을 들지 않는다**(700MB 덱). 그래서 흘려 읽으며 `mayReference` 가 참인 블록만 담아 검사한다. 줄 번호는
  원래 번호로 돌려 적는다.
- **`fixed` 모드 실측.** 판 덱(`demo_flat_tet.k`)에서 표면 절점 361개가 짝을 찾았다 — 379·380·381 은 남고 382 는 못 찾아
  세트 한 줄만 짚었다. 꼭짓점 8개만 가리키면 rc 0 이고 산출이 `--strict` 를 통과한다.
- **(2026-10-16) 실사용 결과.** 6,053장 중 5,276장이 그 갈래 카드를 가졌고 새 경보 0 — 이 박스의 실사용 덱에는 매달린 절점
  참조가 없다(그리고 거짓 경보도 없다). 스윕이 고장 나지 않았음은 같은 스크립트가 나쁜 덱을 잡는 것으로 확인했다.
