# SceneForge — 장면 포지 창립 계획 (2026-10-28 · 이름 확정 전)

> 이 문서는 SceneForge 리포가 생기면 그쪽 `docs/PLAN.md` 로 옮긴다. 리포 생성과 HEAX 등록은 이름 확정(D-1) 뒤에 한다.
> 계약 번호(C-n)·단계(Pn)·결정(D-n)은 총괄 계획 `drop-twin-1028.plan.md` 와 같다.

## 0. 한 줄
StepForge 의 CAD 형상과 DynaForge 의 해석 결과를 **하나의 USD 장면**으로 합쳐 사진급으로 그린다. 쓰임은 둘이다 — 디지털 트윈 보고, 그리고 실물 시험 재현.

## 1. 두 가지 일
1. **디지털 트윈 보고** — 위험 각도의 낙하 장면을 실제 제품처럼 보이는 mp4·정지 화면으로 낸다. 임원·고객·부서 보고용이다.
2. **실물 시험 재현** — 낙하 시험의 고속 카메라와 같은 시점·같은 시각으로 해석을 그려 시험 영상과 나란히 놓는다. 보고를 넘어 **해석 검증 도구**다. 브라우저 뷰어로는 못 하는 일이다.

엔지니어의 매일 원인 분석은 이 포지가 아니라 DynaForge 의 브라우저 변형 뷰어가 맡는다(D-5).

## 2. 왜 따로인가
1. **런타임이 다르다** — Omniverse Kit 는 RTX 렌더러·USD·MDL·스트리밍이 같이 도는 큰 GPU 스택이다. CPU 앱인 DynaForge(FastAPI·Apptainer)나 StepForge(OCC·SQLite)에 넣으면 GPU 전용 의존성을 끌어들인다.
2. **새 정본이 생긴다** — 합성 USD 장면 · 외관 라이브러리 · 시험 카메라 교정 · 렌더 템플릿은 기존 포지 누구의 것도 아니다.
3. **낙하만 쓰지 않는다** — 휨·배터리·열 해석의 트윈 보고로도 넓어진다.
4. **장애와 자원을 떼어 놓는다** — Kit 가 죽거나 GPU 메모리가 터져도 다른 포지는 흔들리지 않는다. GPU 20장의 순서·배당을 따로 관리한다.
5. **기술이 다르다** — USD·MDL·렌더링 전담이 필요하다(D-6).

## 3. 갖는 것과 참조하는 것
| 갖는 것(정본) | 참조만 하는 것(복사하지 않는다 — id 와 해시로) |
|---|---|
| USD 장면 합성 규칙과 장면 캐시 | CAD 형상·재질 이름·파트 신원(StepForge C-7·C-8) |
| 외관 라이브러리(C-9) — 재질 이름 → 외관 | FE↔CAD 매핑 가중치(StepForge C-6) |
| 렌더 템플릿 — 카메라·조명·바닥·슬로모션·컨투어 범위 | S1 경량 추출본과 manifest(DynaForge C-3) |
| 시험 카메라 교정(C-12 를 받아 정리한 것) | 파트별 최대 응력 — **다시 계산하지 않는다**(정본은 DynaForge) |
| 렌더 결과물(C-11)과 렌더 작업 순서·GPU 배당 | 시험 영상 원본(시험실) |

## 4. 구조
**4-1 제어면 — cae00 앱 서버.** FastAPI · MCP · Postgres · 웹 화면 · Apptainer. 다른 포지와 같은 꼴이다.
- 렌더 요청을 받고(C-10), 입력 해시를 확인하고, 장면을 합성하고, 렌더 잡을 걸고, 결과를 저장한다.
- 작업 순서와 GPU 배당을 갖는다(동시 렌더 수 · 우선순위 · 취소).

**4-2 렌더 작업자 — viz 노드(10대 × RTX PRO 6000 2장).** Omniverse Kit(필요하면 Kit-CAE)를 담은 GPU 컨테이너다.
- 포털 실행기가 viz 노드로 분배한다(C-13). 제어면은 노드를 직접 고르지 않는다(DynaForge 실행기 계약과 같은 규율).
- 헤드리스(디스플레이 없음)로 돈다. 결과는 공유 저장소에 쓴다.

**4-3 자산 저장.** 외관 라이브러리 · 템플릿 · 교정 · 장면 캐시 · 결과물. 장면 캐시는 입력 해시(C-3·C-6·C-7·C-9 판)가 같으면 다시 쓴다.

**4-4 포트·등록(제안 — 포털 PORT-MAP 에서 확정).**
- API 8710 · MCP 8711 · Postgres 5437(지금 5432~5436 · 5732 가 쓰인다).
- HEAX 등록은 DynaForge 와 같은 2엔트리 — 웹(proxy · `portal_auth: true`)과 MCP(직결 · `portal_auth` 없음).
- 인증은 게이트웨이 공유 시크릿 + PAT. `POST /api/v1/auth/sso/verify` 를 처음부터 둔다(포털 표준 위임 점검 — DynaForge KR-18 과 같은 계약).

## 5. USD 장면의 층
원본 데이터를 기준으로 두고 USD 는 **조합 층**으로만 쓴다. 변형은 C-6 가중치로 CAD 정점에 옮겨 USD 시간 샘플로 쓴다(Kit-CAE 3.0 은 HDF5 를 못 읽는다 — §11-1).

| 층 | 내용 | 출처 |
|---|---|---|
| 형상층 | CAD 파트 · 파트 키 · 재질 이름 | StepForge USD(C-7) |
| 변형층 | 표면 변위를 가중치로 CAD 정점에 옮긴 시간 샘플 | S1(C-3) × 가중치(C-6) |
| 외관층 | 재질 이름 → 외관 | 외관 라이브러리(C-9) |
| 연출층 | 카메라 · 조명 · 바닥 · 슬로모션 구간 · 컨투어 범위 · **배율 표기** | 렌더 템플릿 |
| 시험층 | 시험 카메라 교정 · 시험 영상(겹쳐 보기) | C-12 — 시험 재현 모드에서만 |
| 파손층 | 요소 삭제 플래그를 CAD 위에 표시 | S1(C-3) — 방법은 P4 과제 |

변형층은 USD 시간 샘플로 직접 쓰기를 권한다. Kit-CAE 데이터 위임으로 읽으려면 EnSight Gold · VTK 변환이나 자체 `SdfFileFormat` 플러그인이 필요하다(10-28 조사 — 공식 충돌 예제도 EnSight Gold 로 바꿔 쓴다). 장면 크기 · 열기 시간은 P1 에서 잰다.

| | 보고(report) | 시험 재현(test_repro) |
|---|---|---|
| 변형 배율 | 과장 가능 — 화면에 「변형 ×N」 표기 의무 | **×1 고정** |
| 카메라 | 템플릿(충돌 부위 추적 · 정해진 시점) | 시험 카메라 교정값 |
| 시간 | 슬로모션 구간 템플릿 | 시험 영상과 충돌 시각 t0 동기 |
| 외관 | 외관 라이브러리 | 외관 라이브러리 + 실물 색·마감 맞춤 |
| 결과 | mp4 · 정지 화면 | 시험 영상과 나란히 · 겹쳐 보기 |
| 화면 문구 | 「보기 전용 — 판정은 해석 결과(정본)」 | 같음 + 교정 판·동기 오차 |

## 7. 도구 (MCP · REST — 고정 몇 개)
- `render_request`(C-10) · `render_status` · `render_result`
- `list_templates` · `appearance_get` · `appearance_put`(C-9)
- `calibration_register`(C-12 를 정리해 등록) · `scene_preview`(장면 합성만 — 문제 찾기용)
- **SceneForge 는 다른 포지를 부르지 않는다.** 렌더 결과는 파일로 내고, DynaForge 반입은 포털 절차가 한다(C-11).
- 성패는 본문으로 말한다(`ok` · `reason` · `warnings[]`). 산출이 없으면 값을 지어내지 않고 이유를 낸다(포털 요청서 09-16 §4 의 넷을 처음부터 지킨다).

## 8. 작업 흐름 — 보고 mp4 하나
1. 포털 절차가 렌더 요청을 낸다(C-10).
2. 제어면이 입력을 확인한다 — C-3·C-6·C-7·C-9 가 다 있고 해시가 맞는지. 하나라도 없거나 틀리면 **거절하고 까닭을 말한다**.
3. 장면을 합성한다(USD). 입력 해시가 같은 캐시가 있으면 다시 쓴다.
4. 실행기를 거쳐 viz 노드에 렌더 잡을 건다(C-13).
5. mp4·정지 화면과 메타(배율 · 템플릿 · 각 입력의 판)를 결과물로 저장한다.
6. 포털 절차가 결과를 DynaForge 에 반입한다(C-11 → 리포트 미디어). 리포트에서 바로 열린다.

## 9. 시험 재현에 필요한 것
- **카메라 교정** — 내부(초점거리 · 센서 · 왜곡)와 외부(위치 · 방향). 기록이 없으면 사진 속 알려진 형상으로 카메라 자세를 역추정한다(PnP).
- **시간 동기** — 시험과 해석에서 각각 충돌 시각 t0 를 정해 맞춘다. 고속 카메라는 초당 수천~수만 장이라, **해석 출력 주기가 성기면 맞출 수 없다**. 비교할 각도는 해석 쪽 d3plot 출력 주기부터 맞춰야 할 수 있다(DynaForge·포털과 함께 정한다).
- **×1 배율과 실물 외관** — 색·마감이 실물과 맞아야 사진과 견줄 수 있다(D-7).
- **비교 화면** — 나란히 · 겹쳐 보기. 시험에 스페클(DIC)이 있으면 변위를 숫자로 맞대는 길로 넓힐 수 있다.
- **파손** — 실물 사진의 유리 균열을 해석의 요소 삭제와 같은 자리에 보여야 한다(P4 과제).

## 14. 이름
**SceneForge** 를 제안한다. 이 포지가 갖는 정본이 장면이고, 렌더러를 바꿔도 이름이 맞기 때문이다. 대안은 TwinForge · RenderForge 다(총괄 계획 §2).
