# 맥락 노트 — 인클루드 닫힘 · `IdAllocator` 첫 채택

## 2026-10-15

- **두 문제가 한 자리였다.** `IdAllocator` 의 「인클루드에 쓰인 번호를 재발행하지 않는다」와
  `--strict` 의 「주 덱을 못 본다」가 같은 능력(인클루드 닫힘에서 정의를 모으기)을 요구한다.
  두 번째 소비자가 생기는 순간이라 한 리더로 모은다.
- **범위는 실측이 정했다.** 실사용 88장 · 카드 408장이 전부 맨 `*INCLUDE` · 한 줄 · 상대경로였다.
  `_TRANSFORM` 등은 0건이라 **따라가지 않고 말한다**로 충분하다 — 오프셋을 모른 채 읽으면 번호가
  그럴듯하게 틀린다.
- **로컬 디렉터리 = 주 덱 폴더.** 매뉴얼(181591)이 「local directory first」라고 한다. 중첩
  인클루드를 하위 파일 폴더에서 찾으면 LS-DYNA 보다 **넓게** 찾게 되고, 그러면 LS-DYNA 가 못 찾을
  덱을 괜찮다고 한다. 실측 407/408 은 「포함하는 파일 폴더 기준」으로 잰 값이라 주 덱 기준으로
  **다시 잰다**(U1 마지막 칸).
- **SET 은 한 통으로 둔다.** plan2 P1-3 이 「네임스페이스 입도는 이 단계에서 바꾸지 않는다」고 했다.
  매뉴얼상 SET 네임스페이스는 종류별이지만(`*SET_PART 6` 과 `*SET_NODE 6` 공존 합법 — 실사용 24%),
  contact 는 지금 모든 종류를 한 통으로 세어 그 위로 낸다. 한 통이 더 **보수적**이다(겹칠 수 없다).
  입도를 바꾸면 번호가 달라져 골든이 움직인다 — 그것은 별 결정이다.

## 2026-10-16 — ModelAssembler 커서

- **같은 스캐너를 파일마다.** 인클루드용 스캐너를 새로 쓰지 않는다 — 주 덱이 쓰는 규칙(`KFileReader`·
  `*SECTION_` 첫 카드·`*SET_` 첫 데이터 줄·지역 스캐너들)을 인클루드 파일마다 그대로 돌린다. 그래야
  「덱을 인클루드로 쪼갠 것」과 「쪼개지 않은 것」의 커서가 같다. 스캐너를 하나로 모으는 것은 다른 일이다
  (그때는 발행자마다 차분 0 을 증명해야 한다).
- **인클루드 줄을 멤버로 든다.** 지역 커서가 op 시점에 자기 스캐너로 세야 해서다. 쪼개지 않은 같은
  덱이면 어차피 `rawLines_` 에 다 들어 있었을 줄이다 — 메모리가 「쪼개지 않은 덱」 수준이 된다.
- **폭.** LS-DYNA 는 폭을 실행줄·주 덱 `*KEYWORD` 로 전체에 정하고 `*INCLUDE ±`·키워드 접미사로만
  바꾼다(Vol_I 19343-19353). 인클루드 파일 자신의 `*KEYWORD I10=Y` 가 먹는지는 **매뉴얼에 없다.**
  `KFileReader` 는 파일마다 자기 `*KEYWORD` 를 본다. 실사용 88장 — 주 덱 전부 표준 · 인클루드 398장 맨
  `*KEYWORD` · 9장 없음 · `±` 0건이라 **갈리는 덱이 없다.** 갈리면 단정 못 한다고 말한다(추측하지 않는다).
- **LS-DYNA 라이선스가 만료됐다(2026-10-16 실측).** 셸·솔리드 EID 공유 규칙을 솔버로 재려 했는데
  대조군 덱까지 `Network license: Program license has expired!`(Error 70022)로 멈췄다. 솔버로 재야 하는
  일은 지금 못 한다.
- **시험 기대 둘이 틀렸다(실측이 고쳤다).** spider rbe3 은 세트를 만들지 않고 중심 노드 하나를 낸다. restack 은
  솔리드끼리 맞닿으면 세트를 안 만든다 — 셸 층이 끼어야 `maxSetId_` 로 접촉 세트를 낸다. 그리고 인클루드
  덱의 restack 은 PIDREF 검사가 strict 로 거절한다(「그 안을 찾지 못한다」 — 별개 소비자). 레인에
  `pid_refs: warn` 을 주고, 「조용하다」 검사는 로더 문구(`곳을 읽지 않았습니다`)만 보게 했다.
- **matdb 는 「최대 + 1」 막이에 안 닿는다** — 새 MID 를 31·41 처럼 건너뛰어 낸다. 그래서 ② 는 둔감하지만
  ①(쪼갠 = 안 쪼갠)이 옛 바이너리에서 문다. 신탁 둘을 같이 둔 이유가 이것이다.
- **assemble 안의 hfdamp·cnrb2solid** — 옛 로더 경고가 이 둘의 발급까지 덮었다. 경고를 「못 본 자리만」으로
  좁히면 이 둘이 조용히 겹칠 수 있는지 봤다 — 둘 다 멤버 커서를 참조로 받고 주 덱 값으로 **올리기만** 한다
  (cnrb2solid 는 0 일 때만 채운다). 그래서 같이 덮인다.
