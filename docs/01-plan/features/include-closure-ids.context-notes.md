# 맥락 노트 — 인클루드 닫힘 · `IdAllocator` 첫 채택

## 2026-10-15

- **두 문제가 한 자리였다.** `IdAllocator` 의 「인클루드에 쓰인 번호를 재발행하지 않는다」와
  `--strict` 의 「주 덱을 못 본다」가 같은 능력(인클루드 닫힘에서 정의를 모으기)을 요구한다.
  두 번째 소비자가 생기는 순간이라 한 리더로 모은다.
- **범위는 실측이 정했다.** 실사용 88장 · 카드 408장이 전부 맨 `*INCLUDE` · 한 줄 · 상대경로였다.
  `_TRANSFORM` 등은 0건이라 **따라가지 않고 말한다**로 충분하다 — 오프셋을 모른 채 읽으면 번호가
  그럴듯하게 틀린다.
- **로컬 디렉터리 = 주 덱 폴더.** 매뉴얼(181591)이 「local directory first」라고 한다. 중첩
  인클루드를 하위 파일 폴더에서 찾으면 LS-DYNA 보다 **넓게** 찾게 되고, 그러면 LS-DYNA 가 못 찾을
  덱을 괜찮다고 한다. 실측 407/408 은 「포함하는 파일 폴더 기준」으로 잰 값이라 주 덱 기준으로
  **다시 잰다**(U1 마지막 칸).
- **SET 은 한 통으로 둔다.** plan2 P1-3 이 「네임스페이스 입도는 이 단계에서 바꾸지 않는다」고 했다.
  매뉴얼상 SET 네임스페이스는 종류별이지만(`*SET_PART 6` 과 `*SET_NODE 6` 공존 합법 — 실사용 24%),
  contact 는 지금 모든 종류를 한 통으로 세어 그 위로 낸다. 한 통이 더 **보수적**이다(겹칠 수 없다).
  입도를 바꾸면 번호가 달라져 골든이 움직인다 — 그것은 별 결정이다.
