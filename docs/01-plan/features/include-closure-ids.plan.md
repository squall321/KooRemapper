# 계획 — 인클루드 닫힘을 읽어 번호를 모은다 (`IdAllocator` 첫 채택 + 주 덱 `--strict`)

체크리스트 `include-closure-ids.checklist.md` · 맥락 `include-closure-ids.context-notes.md`
장부 항 — `docs/requests/deck-contract-checklist.md` P1-3(`IdAllocator`) · P1-5(`--strict` 결정)

## 0. 왜 — 실측 둘이 같은 자리를 가리킨다

1. **번호 발행이 인클루드를 못 본다.** contact 는 `ct_findMaxSetId(sets)+1` 로 세트를 내는데 `sets`
   는 주 덱 파일 하나에서만 읽는다. 인클루드에 `*SET_PART 5` 가 있으면 5 를 **다시 낼 수 있다**
   (plan2 P1-3 의 조건 — 「인클루드에 쓰인 번호를 재발행하지 않는다」).
2. **`--strict` 가 거꾸로 판정한다(2026-10-15).** 실사용 study 덱 1,683장 중 막힌 142장의 92%가
   **인클루드 조각**이고, 인클루드를 **가진** 주 덱 83장은 「읽지 않아 단정 불가」로 **한 장도 안 본다.**

둘 다 「주 덱에서 인클루드 닫힘을 읽어 정의를 모은다」가 있으면 풀린다.

## 1. 범위를 실측으로 정했다

실사용 덱(`/data` 아래 50MB 이하)에서 인클루드를 쓰는 덱 **88장 · 카드 408장** —
- 키워드 꼴은 **맨 `*INCLUDE` 뿐**(`_TRANSFORM`·`_PATH`·`_BINARY`·`_NASTRAN`·`_AUTO_OFFSET` **0건**)
- 이름이 여러 줄 0 · `␣+` 이음 0 · 절대경로 0 · `..` 0 · 하위 폴더 3
- 포함하는 파일의 폴더 기준으로 풀면 **407/408 이 있다**

## 2. 매뉴얼 규칙(그대로 따른다)

| 규칙 | 근거 |
|---|---|
| 맨 `*INCLUDE` 는 이름 카드를 **여러 장** 받고 다음 키워드가 끝낸다 | Vol_I 179253-179254 (Card 1a) |
| 이름은 `␣+` 로 **세 줄까지** 잇는다(최대 236자) | Vol_I 179670-179674 (Remark 2) |
| 인클루드는 **중첩**된다 | Vol_I 179636-179638 (Remark 1) |
| 인클루드 파일 안의 `*END` 는 **그 파일만** 끝낸다 | Vol_I 179654 |
| 찾는 순서 — **로컬 디렉터리 먼저**, 못 찾고 이름에 경로가 없으면 `*INCLUDE_PATH` 디렉터리. `_RELATIVE` 는 입력 파일 위치 기준 | Vol_I 181591-181600 |

**로컬 디렉터리 = 주 덱의 폴더**로 본다(LS-DYNA 는 덱 폴더에서 돈다). 중첩 인클루드도 하위 파일의
폴더가 아니라 **거기서** 찾는다 — 매뉴얼이 그렇게 말하고, 우리가 더 넓게 찾으면 LS-DYNA 가 못 찾는
덱을 「괜찮다」고 하게 된다.

## 3. 따라가지 않는 것 — 말한다

`*INCLUDE_TRANSFORM`(ID 오프셋 IDNOFF·IDEOFF·IDPOFF·IDMOFF·IDSOFF…)·`_BINARY`·`_NASTRAN`·
`_AUTO_OFFSET`·`_STAMPED_*`·`_COMPENSATION_*` 등 맨 `*INCLUDE` 가 아닌 것은 **따라가지 않고
`notFollowed[]` 에 키워드를 적는다.** 소비자는 그것이 하나라도 있으면 **「단정 불가」**로 다룬다.
오프셋을 안 걸고 읽으면 번호가 **그럴듯하게 틀린다** — 가장 나쁜 꼴이다. (실사용 0건이라 지금 비용 0.)

## 4. 단위

| | 무엇 | 관문 |
|---|---|---|
| U1 | `include_scan::readClosure(mainPath)` — 읽은 파일(순서) · 못 읽은 이름 · 따라가지 않은 카드 · 순환 | 단위 시험(여러 줄·`␣+`·중첩·`*END`·순환·없는 파일·`_TRANSFORM`) + **실사용 88장에서 못 푼 수** |
| U2 | `UsedIds` — 닫힘 전체의 네임스페이스별 최대값. SET(**모든 종류 한 통** — contact 규약 유지) · CONTACT(CID) | 단위 시험 + **contact 의 기존 스캐너와 추적 덱 전수 차분 0** |
| U3 | `IdAllocator` — 빈 대역표면 `max+1`(**오늘과 같은 번호**) · `issue(ns)` · `verify` | 단위 시험 |
| U4 | contact 첫 채택 — 커서 둘(`nextSetId` 17곳 · `nextContactId` 3곳)을 `issue` 로 | **골든 10장 바이트 동일** + 새 픽스처(인클루드의 SET 5 → 6 을 낸다) |
| U5 | `checkSetReferences` 를 닫힘 위에서 — 주 덱이 단정 가능해진다 | 실사용 재측정(83장의 판정이 「단정 불가」에서 실제 값으로) · 조각 판정은 **안 바뀐다** |

## 5. 이번에 안 하는 것

대역표의 **값**(P1-4 — 스코프 결정 대기) · 나머지 발행자(hfdamp·ModelAssembler 8곳·disconnect —
다음 단위) · `_TRANSFORM` 오프셋 적용 · 조각을 주 덱 문맥에서 판정하기(조각만 보고는 주 덱을 모른다).
