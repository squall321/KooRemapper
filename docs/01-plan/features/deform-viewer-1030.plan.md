# 브라우저 변형 뷰어 1단계 — 형상 · 가중치 (2026-10-30)

총괄 `drop-twin-1028.plan.md` 의 P2 「브라우저 변형 뷰어」(D-5 — DynaForge 화면, S2 맵에서 각도를 누르면 열린다) 가운데 **형상 · 가중치**만 먼저 짓는다. 변형 프레임(C-3 S1)은 KooD3plotReader 계약 초안 2 · 1단계 구현이 나왔지만 운영 이미지에 아직 없어 2단계로 둔다.

## 사용자 결정 (10-30)
- **형상 · 가중치만 먼저** — StepForge glb(C-7) · 가중치(C-6)는 계약이 섰다. 변형 프레임은 C-3 가 정해지면 붙인다(되돌릴 일이 적은 쪽).
- **리포트에 묶음 붙이기** — DynaForge 가 StepForge 산출 폴더를 직접 읽거나 StepForge 에 내려받기 API 를 새로 요청하지 않는다. C-11 렌더 반입과 같은 꼴로 fe_cad 묶음(zip)을 리포트에 붙인다. 이 선택이 리포트 ↔ 묶음 잇기도 정한다(붙인 것이 그 리포트의 형상).

## 무엇
1. **붙이기(백엔드)** — `POST /reports/{id}/cad`(zip, 소유자만) · MCP `attach_cad(report_id, path)`(폴더 · zip). 검사는 전부 아니면 전무. 리포트 하나에 묶음 하나 — 같은 열쇠 · 같은 파일이면 그대로(멱등), 다른 묶음이면 갈아 끼운다.
2. **뷰어(화면)** — 리포트 구면 위험도 맵에서 각도(케이스)를 고르면 「형상 보기」 로 그 리포트의 glb 를 three.js 로 연다. 파트를 그 각도의 파트별 최대 응력으로 칠하고, 묶음 정보(열쇠 · 덱 · 가중치 요약 · 검사 결과)를 보인다. 묶음이 없으면 붙이는 길을 말한다.

## 검사 — 받는 쪽(C-6 · C-7)
한 자리(백엔드 `app/reports/cad_bundle.py`, 순수)에서만 한다. 화면은 백엔드가 통과시킨 묶음만 받는다.
- **꼴** — zip 은 평평한 이름만(폴더 · `..` · 절대 경로 거절), 개수 · 크기 상한. `manifest.json` 필수, `format = stepforge.fe_cad_manifest` · `version = 1` · 열쇠 64 hex.
- **파일** — manifest `files[]` 의 이름 · bytes · sha256 이 모두 맞아야 한다. 적히지 않은 파일이 있으면 거절(manifest.json 은 빼고).
- **열쇠** — manifest · `variants.view` · weights · parts · pairs 의 `key` 가 같아야 한다.
- **보기 판** — `variants.view.glb[]` · `weights` 가 files 에 있다. 렌더 판(`variants.render`)은 있으면 함께 받되 이번 뷰어는 보기 판만 쓴다.
- **가중치** — `format = stepforge.fe_cad_weights` v1 · 리틀엔디언 · 정렬 8 · 행마다 nnz 3. 파트마다 배열 오프셋이 8 의 배수이고 bin 안에 든다 · 개수가 맞는다(row_ptr = 행+1, col · w = nnz, dist = 행) · row_ptr 가 0 에서 시작해 줄지 않고 nnz 로 끝난다 · 행마다 Σw ≈ 1.
- **glb 정점** — glb 의 JSON 덩이를 읽어 파트의 node → mesh → primitive POSITION 개수가 가중치 행 수와 같은지 본다(「행 = glb 정점」).
- **이 리포트의 기기인가** — 묶음 pairs 의 pid 와 리포트 파트 id 가 하나도 안 겹치면 거절, 일부만 겹치면 경고. 덱 sha 로는 못 잇는다 — 각도별 덱은 바닥 · 초기 속도가 달라 sha 가 다르다.
- S1 쪽 검사(가중치 열이 S1 `node_ids` 안에 드는가)는 2단계.

## 하지 않는 것(이번)
- 변형 프레임 · 응력 색의 절점 단위 표시 — C-3 S1(2단계).
- 낙하 방향 화살표 · 바닥 — 정확한 값은 S1 `/posture`(초기 속도 · 바닥 평면)가 준다. 리포트 각도(lat · lon)를 방향으로 바꾸는 규칙을 하나 더 두면 사본이 된다.
- 붙이는 주체(포털 절차의 한 단계 · 사용자 MCP) — 길만 만들고, 누가 붙일지는 포털과 정한다.
  ⚠ MCP `attach_cad` 는 **MCP 컨테이너가 읽는 경로만** 된다 — StepForge 산출 자리(`/data/appdata/step_forge/…`)는 dev MCP 컨테이너에서 안 보였다(10-30 실측 「path not found on the MCP host」 — `upload_local_path` · `attach_render` 와 같은 규칙). 운영도 같을 것이다. 붙일 주체가 정해지면 길은 둘 — REST(multipart, 어디서든) · MCP 가 보는 자리로 옮겨 놓기(또는 그 자리를 읽기 전용으로 묶기 — 운영 설정).

## 결정 기록
- (10-30) 위 사용자 결정 둘.
- (10-30) 검사는 백엔드 한 자리 — 화면에 같은 규칙을 또 두면 사본이 된다. glb 정점 수도 백엔드가 JSON 덩이로 센다(바이너리 덩이는 안 푼다).
- (10-30) 화살표 · 바닥은 2단계(`/posture`) — 위 「하지 않는 것」.
- (10-30) 같은 열쇠에 다른 파일은 갈아 끼우지 않고 거절 — StepForge 는 같은 판 열쇠면 같은 바이트다(D-645). 받아 주면 위쪽 어긋남이 묻히고, 옛것을 먼저 지우는 순서가 생겨 저장이 깨질 때 리포트 칸이 지운 파일을 가리킨다.
- (10-30 화면 확인에서 고친 셋)
  - 빛 — three r155+ 는 빛 세기를 물리 단위로 받아 Lambert 밝기가 「색 × 세기 ÷ π」 다. 세기 0.8 이면 범례 색의 ⅓ 밝기라 208 MPa 가 범례에 없는 올리브로 보였다. 바탕빛 2.4(≈0.76π) · 방향빛 1.0 으로 범례 색의 76–100% 에 든다.
  - 고른 파트 — 비침(emissive)이 칠과 섞여 범례에 없는 색이 됐다. 칠은 그대로 두고 빨간 모서리선으로 두른다.
  - 고르기 — 모서리선이 mesh 의 자식이라 광선이 선을 먼저 맞혀 「안 고름」 이 됐다. mesh 만 본다.
  - 속 보기 — 휴대폰 꼴은 속 파트(PCB · PKG)가 겉판에 가린다. 고른 파트만 남기고 비친다(18%).
- (10-30) 저장 자리에 리포트 id 를 넣었다 — 한 세션에 리포트가 여럿이고 같은 묶음을 둘에 붙일 수 있다(같은 이름이면 저장 함수가 `_1` 로 피한다).
