# 미뤄 둔 결함 둘 — 맥락 · 결정 기록 (2026-11-20)

계획 `deferred-defects-1120.plan.md` · 체크리스트 `deferred-defects-1120.checklist.md`.

## 1. 왜 지금 · 왜 이 둘
- 11-08 사용자 결정으로 「다음 판」 에 미뤘던 것이다(운영 판에도 있는 기존 결함). 11-20 남은 일 정리에서 「물성을 조용히 바꾸는 것 먼저」 로
  이 둘을 권했고 「진행해줘」 를 받았다.
- 다섯 가운데 둘만 한다 — 권한 범위가 둘이었다. 나머지 셋은 계획 0절에 이름만 남긴다.

## 2. F-1 — 잰 차례
- 탐침(scratch — 리포에 없다)이 dev 라이브러리를 물고 `ConnectivityAnalyzer` → `StructuredGridIndexer::assignIndices` 를 돌려 요소마다 (i,j,k)
  를 모았다. 서로 다른 칸 수가 unfold 가 쓴 요소 수와 **정확히 같았다**(53 · 238) — 손실은 색인 충돌 하나로 설명된다.
- 위상 색인 시제품(같은 탐침)은 시작 모서리의 세 이웃 면에 축을 붙이고, 이웃으로 넘어갈 때 「맞닿은 면 = 같은 축 반대 부호 · 그 맞은편 = 같은 축
  같은 부호 · 나머지 네 면은 맞닿은 면과 두 절점을 나눠 가진 이쪽 면의 축」 으로 틀을 옮긴다. 같은 요소에 두 길이 다른 칸을 주면 충돌로 센다.
  색인이 된 덱 전부에서 충돌 0 · 칸 전부 유일.
- 「지금 = 위상」 은 요소마다 칸이 같다는 뜻이다(축 이름 · 방향을 맞춘 뒤 — 지금 색인기는 끝에 축을 크기순으로 다시 놓는다).

## 3. 결정
- **A 를 짓고 B 는 내놓기만 한다.** A 는 「조용한 손실」 을 「큰 소리의 거절」 로 바꾸는 가장 작은 고침이고 DF-14 에서 사용자가 고른 갈래와
  같다. B 는 `map` 의 뿌리(모든 매핑 산출이 이 색인을 탄다)를 바꾸므로 혼자 정하지 않는다 — 수치(83 같음 · 8 새로 됨)와 함께 묻는다.
- 유일성 검사는 채움률 검사 **뒤**에 둔다 — 지금 채움률로 실패하는 다섯 덱의 오류 글을 바꾸지 않는다(그 글을 읽는 시험 · 사람이 있을 수 있다).
- 이미 색인이 든 메시(`allAssigned` 갈래)는 건드리지 않는다 — 덱에서 온 메시는 그 갈래를 타지 않는다.
- unfold 의 요소 수 검사는 「읽은 수 = 지은 수」 하나다. 까닭은 색인기 글(A-1)이 말하고, A-2 는 색인이 멀쩡한데 3단계가 건너뛴 경우의 뒷문이다.

## 4. F-2 — 결정
- 여섯 자리를 폭에 맞춘다(거절 글만 고치는 길보다 — 절점 · 요소 · 세트는 이미 long 을 읽고 쓰기는 줄을 그대로 옮겨, 남은 것이 첫 칸 읽기뿐이다).
- `indexDeck` 에서는 이미 키워드마다 재는 폭(`setW`)을 그대로 쓴다 — 이름을 `cardW` 로 바꿔 `*PART` · `*SECTION_SOLID` · `*SET_PART` 가 같이
  쓴다.

## 5. 계획을 쓴 뒤 더 잰 것(F-1)
- unfold 를 리포 덱 339 개에 돌렸다(고치기 전 바이너리). 읽은 수 = 쓴 수 83 · **잃음 3**(`test_small_bent.k` 100 → 53 · `wave_bent.k`
  250 → 238 · `examples/teardrop/teardrop_mapped.k` 2,000 → 1,214) · 거절 253. 색인 탐침의 「칸이 겹친 덱」 과 같은 셋이다 — 겹침 말고 다른
  까닭의 손실은 나오지 않았다.
- 구멍 난 격자(상자 10×5×2 에서 요소를 뺀 것)는 잃지 않는다. 안쪽 요소 하나 · 둘을 빼면 rc 0 으로 99 · 98 을 다 쓰고, 모서리 요소나 한 줄을
  통째로 빼면 검증기가 rc 1 로 막는다(「Element N has 2 neighbors (expected 3-6)」). 그래서 평판 생성 3단계의 「칸이 비면 건너뛴다」 는 겹침
  말고는 잃는 사례를 찾지 못했다 — A-2 는 실패 사례가 있어서가 아니라 연산이 제 불변식을 스스로 지키게 하는 뒷문이다.
- `map` 의 굽은 기준으로 넣으면 세 덱 모두 rc 1 이었다(뒤의 모서리 절점 검사 — 「only 0/8 · 1/8 corner nodes found」). **조용히 틀린 `map`
  산출은 찾지 못했다(재지 못한 것 — 그런 덱이 리포에 없다).**

## 6. 고친 뒤 잰 것(F-1)
- 새 시험은 고치기 전 빨강 넷(U-1 · U-2 · M-1 · M-2) → 고친 뒤 14 항 초록.
- 변이 확인 — A-1 을 잠시 끄고 지으면 세 덱 모두 A-2 가 rc 1 로 막는다(「Unfold lost elements: generated 53 of 100」 · 238 of 250 ·
  1214 of 2000 — 산출 없음). 되돌려 다시 지었다.
- 같은 339 덱을 다시 돌리면 같음 83 · 잃음 0 · 거절 256(253 + 3) — 멀쩡하던 83 덱은 그대로다.
- `map` 의 거절 글이 뒤의 모서리 검사에서 색인 겹침(「12 of 250 elements share an (i,j,k) slot …」)으로 앞당겨졌다. rc 는 전과 같다(1).
