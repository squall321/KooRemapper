# Context Notes — DynaForge 개발 요청서 v1.0(11-17)

설계 `df-request-1117.plan.md` · 체크리스트 `df-request-1117.checklist.md`
작업 중 내린 결정과 그 근거를 계속 덧붙인다.

## 2026-11-17 · 요청서를 소스와 먼저 대조했다
- 15건 가운데 우리 쪽 결함은 DF-14 하나다(예전부터 — 11-08 `59b6960` 이 `info` 에만 알림을 달았다). 나머지는 캠페인 단위의 새 기능이거나
  생성기 · 게이트웨이 · 다른 플랫폼의 몫이다.
- DF-14 를 세는 자리는 `Mesh::addElement` 가 아니라 리더의 추가 자리다 — 리더 밖에서 13곳이 그 함수를 부른다(요소를 바꿔 끼우는 op).
  거기서 세면 op 이 바꾼 것까지 「잃었다」 가 되어 쓰기가 멀쩡한 산출을 거절한다.
- 쓰기 거절은 `KFileWriter` 두 입구 한 곳에 둔다(이미 `secondOrderWritable` 가 같은 꼴). op 마다 두면 빠뜨린 op 이 조용히 쓴다.
  메시를 비우고 새로 짓는 자리(remap 결과)는 표를 옮겨 줘야 해서, 덱을 쓰는 op 마다 돌려 거절을 재본다.
- 401 은 우리 쪽에서 고칠 것이 아니라 가를 것이다 — API 가 내는 401 글이 셋이고 그 글이 까닭을 말한다. 운영 게이트웨이 설정은
  보지 못했다(HEAXHub 로컬 매니페스트는 portal_auth 없음).

## 2026-11-17 · DF-14 를 지으며
- 칸 이름은 사용자 확인 — 「낱칸 — 우리 꼴」 → `model.element_id_collisions`(덮여 잃은 요소 정의 수) · `model.parts_missing`(요소가 하나도
  안 남은 파트 수). 고아 절점은 있는 칸(`orphan_nodes`) 그대로다.
- 같은 족 안의 겹침(이미 망가진 카드 — LS-DYNA 도 멈춘다)도 리더가 잃으므로 같이 센다. 쓰기 거절도 같다 — 잃은 요소가 산출에서
  빠지는 것은 족을 건넜든 아니든 같다.
- 덮인 요소의 곁표(2차 솔리드 전체 절점 · 두께 셸 번호)를 같이 지운다 — 남기면 뒤 요소(셸)가 앞 솔리드의 절점 목록을 물려받아
  고아 절점 수가 틀린다. 결정 문장 밖의 작은 정정이라 끝 보고에 적는다.
- 덱을 쓰는 op 마다 돌려 거절을 쟀다 — map(평판 · 굽은 쪽) · unfold · squeeze · shellmap · tetremesh. map · unfold 는 굽은 덱이 육면체만
  받아 두께 셸 겹침으로 잰다(셸 겹침이면 그보다 앞의 「HEX8 만」 거절에서 막힌다 — 그것도 산출은 없다).
- 경고 · 거절을 하지 않는 자리 — contact detect · surfview(덱을 쓰지 않는다 — 앞 요소 없이 돈다) · dynain 쓰기(`*INITIAL_STRESS` — 메시
  쓰기가 아니다). 결정 문장(「덱을 다시 쓰는 op」) 밖이라 끝 보고에 올린다. prestress 의 뒤집기 임시 덱은 `KFileWriter` 라 거절된다.

## 2026-11-17 · 포털이 옮긴 결정 문서와 리스크 앱 요청
- 포털(hwaxportal-71)이 사용자 결정 문서(D1 · D4 · D5 · D7 · C1 · C4 · C5)와 리스크 앱 RK-06 을 옮겼다 — 정보이고 승인은 아니다. 1차에
  더할 것을 사용자에게 물었고 셋 다 더한다(D4 적재 공식 답 칸 · D5 environment 칸 · inspect sha256).
- 요청서 원문은 리포에 두지 않는다 — 포털 부탁(미출시 과제 이름 · PC 경로). 커밋 전 사본을 지웠다.
- D5 읽기 — environment 는 리포트 스키마 둘(`ReportRead` · `ReportListItem`)의 계산 칸이라 찾기 · 요약뿐 아니라 그 스키마를 쓰는 응답
  모두(세션 리포트 목록 · 메타 고침 · 세션 적재)에 실린다. 원샷 intake 는 손으로 짓는 응답이라 따로 넣었다.
- D4 의 `public_url` 은 `KOORM_PUBLIC_BASE` 가 있어야 채워진다 — cae00 에 이 값이 없으면 null 이다(운영자 몫). 토큰 종류는 코드가 받는
  것이고 운영 게이트웨이가 헤더를 넘기는지는 이 칸이 보증하지 않는다.
