## 왜
10-15 ~ 10-16 캠페인(StepForge 경계 → 인클루드 닫힘 → 번호 발행 → 2차 솔리드 → 절점 참조 → 삽입·재결속·`id_floor` →
게시, 61커밋)이 끝났는데 정리 문서가 없다. 그리고 점검해 보니 **07a6802(분석 op 이 인클루드를 읽는다)가 남긴 낡은 말**이
MCP 가 내보내는 설명 곳곳에 있다 — 「KooRemapper 는 `*INCLUDE` 를 읽지 않는다」 · 그림 op 「마스터 덱은 거절한다」 ·
`section` 의 「리더는 그 안을 읽지 않는다」 안내. MCP 를 쓰는 쪽(사람·AI)이 그 말을 믿고 틀린 판단을 한다.

## 무엇을
1. **MCP 설명** — 카탈로그(`describe_operation` 의 원문)에서 오늘 바뀐 op 의 낡은 문장을 고치고 빠진 동작을 적는다 ·
   `server.py` 도구 설명(인클루드 · 게이트) · SKILL.md(새 흐름) · TOOLS.md(도구 수).
2. **같은 뿌리의 콘솔 문구·주석** — `section` 안내 · `info` 의 「읽지 않았으므로」 · 주석 넷 · 도움말 한 줄. 문구만 바꾼다
   (동작 그대로). 플랫폼 파서가 잡는 줄(`*INCLUDE 안은 보지 않았습니다:`)은 **건드리지 않는다**.
3. **관련 md** — 매뉴얼 · platform README 의 낡은 자리.
4. **보고서** — `docs/04-report/deck-contract-1016.report.md`(기존 보고서 꼴 · 수치는 다시 잰다).
5. 살아 있는 스택에 반영 — 카탈로그는 API 재기동, 도구 설명은 MCP 재기동. **바이너리 문구는 게시가 있어야 닿는다** —
   게시 · SIF 굽기는 사용자 결정으로 남긴다.

## 하지 않는 것
- MCP `run_operation` 에 `allow_missing_includes` 를 더하는 일 — 안전 게이트를 AI 가 넘을 길을 여는 결정이라 사용자에게
  묻는다. 지금은 설명을 사실대로 고친다(그 값은 REST 로만 넘긴다).
- 다른 리포(pyKooCAE 매뉴얼)는 상태만 보고 알린다.
