생성기(`koo_deep_report`)에는 **있었다** — `--hotspot-clusters` 로 상위 P%·거리계수·최소요소·
최대군집·판정기준(`von_mises` 등)을 받아 군집을 만들고, HTML 에 `DATA.hotspot` 으로 **탭까지**
붙인다(실측: 102 군집). 그런데 플랫폼 `normalize_deep` 은 그 키를 **읽지 않는다.**

★이것은 ④ 고아 절점 신호, `modelmeta` 2차 솔리드와 **같은 부류**다 — 상류에 데이터가 있고
플랫폼이 조용히 버린다. 세 번째다.

## 왜 '정규화가 아는 키만 통과' 가 계속 뒤처지는가

정규화는 **허용 목록**이다. 생성기가 키를 늘릴 때마다 플랫폼은 가만히 있어도 뒤처지고,
뒤처진 것이 **보이지 않는다**(에러도 경고도 없다). 그래서 이번에는 목록을 늘리는 대신
**일반 블록 접근**을 만든다 — 임베드 데이터의 모든 최상위 블록을 이름으로 꺼낼 수 있게.

그리고 **차집합 자체를 회귀로 고정**한다(A-2). 생성기가 키를 늘리면 그 회귀가 빨개져서
"새 것이 생겼다" 를 사람이 알게 된다. 허용 목록을 고치는 것을 **잊을 수 없게** 만드는 쪽이
허용 목록을 잘 관리하는 것보다 낫다.

## 조사에서 두 번 속았다 — 기록해 둔다

1. 처음에 키 이름을 `grep` 해서 '쓰인다/안 쓰인다' 를 갈랐다. **출력 필드명에 속았다** —
   `"min_principal"` 은 `parts_metrics` 의 **출력** 키라서 "쓰임" 으로 세어졌고, 하마터면
   "min 은 읽고 max 는 안 읽는 비대칭" 이라는 **없는 결함**을 보고할 뻔했다.
   → `data.get("…")` 로만 다시 셌다. **읽는 것과 쓰는 것을 같은 패턴으로 찾으면 안 된다.**
2. 블록 단위 차집합을 '하위 키 이름이 하나라도 겹치면 일부 전달' 로 셌더니 `hotspot` 이
   "1/36 전달" 로 나왔다 — 겹친 하나는 `part_id` 같은 우연이었다. 사실은 **0 전달**이다.
   → 어림짐작 지표는 **0 과 1 을 구분하지 못한다.** 정본은 `data.get` 전수였다.
