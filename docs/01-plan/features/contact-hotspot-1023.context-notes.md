- **(10-23) 새 판 고정본은 운영 이미지로 만든다.** 시스템 python 에는 `lasso` 가 없어 하중경로를 건너뛴다(「no matsum (lasso missing)」).
  `/opt/apptainers/SmartTwinPostprocessor.sif` 안에서 같은 생성기를 돌리면 하중경로까지 실린다. 실제 파이프라인

  (원본 캠페인 폴더에는 쓰지 않고 스크래치 사본에서).
- **(10-23) 압축본의 피크는 다시 재지 않는다.** 생성기 규칙 — 「시계열 요약은 항상 원해상도 선계산」(`energy_flow_builder.py`). HTML 의
  `ke`/`ie` 는 솎은 것이라 그 위의 max 는 참피크를 놓친다. null + 까닭으로 낸다.
- **(10-23) `contact_profile` 은 sphere 와 impact 가 같은 꼴이다**(`pairs` + `pf/ti/tw`, 축만 각도/위치). 전용 함수 하나를 둘이 쓴다.
- **(10-23) 세트 해석은 정본 하나로.** modelmeta · contact · optimize 셋이 같은 조회를 따로 한다(두 번째 소비자를 넘었다).
  파서는 `ids` 를 계속 비워 둔다(닫히는 쪽) — 멤버 세트 목록은 따로 든다. 펼치는 것은 해석기만 한다.
- **(10-23) impact 압축본은 엣지 이름이 sphere 와 또 다르다**(`peak_f`·`total_w`·`total_imp`·`conf`). sphere 꼴만 맞췄다면 impact
  하중경로는 여전히 null 이었다 — 실리포트로 돌려서 알았다. 압축본 안내(`form_note`)도 고정 문장이 아니라 **실제로 빠진 칸만** 적는다.
- **(10-23) `_ID` 접촉 두 결함은 시험 덱을 LS-DYNA 가 받는 꼴로 바꾸다 나왔다.** `*CONTACT_*` 에는 `_TITLE` 이 없다(info --strict).
  optimize 가 Card 3 을 Card A 로 알고 SFSA 에 0 을 썼다(보고는 「SOFT=1->0」). 세트 일과 별개지만 같은 접촉 경로라 같이 고쳤다.
  ★시험이 두 관심사를 섞으면(쌍을 제목으로 찾기) 옛 바이너리에서 엉뚱한 항목이 빨개진다 — 쌍은 접촉 순번으로 고른다.
- **(10-23) 61파트 덱 기하 탐지는 gap 0.05 에서 786쌍**이다(옛·새 바이너리 같다). 앞서 사용자에게 말한 700 은 DB 에 남은 더 옛 판의 값이었다.
- **(10-23) 덱 바이트 대조의 「달라진 op 2개」(cleanup-nodes · extract-parts)는 report JSON 의 임시 폴더 경로뿐이다** — 덱 바이트는 같다.
  실행마다 폴더가 달라 늘 그렇게 나온다(그 경로를 가리는 것은 관문 도구의 몫 — 이번에 고치지 않았다).
