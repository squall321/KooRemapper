# DF 2차 ② 맥락 노트 — 런 출처 · 유효성 · 동시 올리기

계획 `df-provenance-health-1122.plan.md` · 체크리스트 `df-provenance-health-1122.checklist.md`.

## 1. 결정과 그 까닭(2026-11-22)
- 사용자가 고른 것 — 「② 계획을 지금 먼저」 · 「set_campaign_health_thresholds」 · 「KE 0 invalid · ±10 % 밖 warn · 접촉 −100 mJ 아래 warn」 ·
  「invalid(health_missing) — 기본 제외」. 그 뒤 받은 글 「계획한건 전부 만들고, 다 만들면 검증런을 cae00에서 돌릴게」 — 단계마다 멈춰 칸 ·
  검증 사례를 확인받지 않고 짓는다. 11-21 결정 문장의 「칸과 검증 사례를 확인받은 뒤 짓습니다」 를 이 글이 갈음한다고 읽었다.
- 판정을 저장하지 않는다 — 문턱을 바꾸면 그 자리에서 다시 판정되고, 저장한 판정이 낡을 일이 없다. 런 수는 한 캠페인 5,000 안팎이라 읽을 때
  세어도 된다.
- `hg_over_ie_max` 는 비(0.10 = 10 %)로 받는다 — 요청서 함정 줄이 같은 양을 `|HG|/IE ≤ 0.1` 로 적었다. 추가 질량 두 칸은 이름대로
  백분율이다.
- `solver` 의 열쇠는 요청서에 없다(「판 · MPP/SMP · 코어 수」) — 열쇠를 지어내지 않고 글 · 숫자 값의 객체를 그대로 받는다. 나머지 열쇠는 모르면
  422 다.
- 받기 줄 앞 커밋 — 롤백은 ORM 객체를 만료시켜(비동기에서 지연 읽기가 깨진다) 쓰지 않는다. 두 라우트는 줄 앞에서 이미 커밋한 상태라 새로 굳는
  것이 없다.
