## 2026-11-20 · 소스에서 본 것(설계에 닿는 것만)
- intake 는 리포트를 읽고(크기 상한 · gunzip · 묶음 풀기) → 세션을 만들거나 찾고 → K 파일을 저장하고(커밋) → `ingest_report` 가 해석 ·
  검증을 모두 끝낸 뒤 쓰기 시작한다. 해석 실패(`ValueError`)면 라우트가 방금 만든 세션이나 K 파일을 지우고 400 을 낸다.
- `ingest_report` 의 쓰기 구간은 커밋 하나다(개정 잇기만 저장점). 그래서 쓰기 구간 맨 앞에서 런 행을 잠그면(`FOR UPDATE`) 그 커밋까지 잠금이
  이어진다 — 같은 런의 둘째 요청은 잠금에서 기다렸다가 「이미 가졌다」 를 본다. 잠금을 저장점 밖에서 잡으므로 개정 잇기가 되감겨도 풀리지
  않는다.
- 세션 팩토리는 `expire_on_commit=False` 다. 되감기(rollback)는 객체를 만료시켜 뒤의 정리 코드가 속성을 읽다 깨진다 — 「이미 가졌다」 로 물러날
  때는 되감지 않고(아직 아무것도 안 썼다) 정리 코드의 커밋이 잠금을 푼다.
- 저장된 리포트 파일의 sha256(`SessionFile.sha256`)은 올라온 바이트(푼 뒤)의 sha256 과 같다 — 런의 지문으로 그 값을 쓴다.
- MCP `_unwrap` 은 4xx 에서 `message` 만 올린다. 그래서 같은 이름 캠페인의 409 는 id 를 글에도 넣는다(`data.campaign_id` 는 REST 손님용).
- intake 는 토큰마다 분당 60 호출이다(`ratelimit_upload_per_min` — 넘으면 429 `Retry-After`). 1,393 건이면 한도만으로 23 분쯤이다 — 올리는
  쪽이 429 를 지켜야 한다. `capabilities.intake` 와 업로드 안내에 싣는다.
- `rest_catalog` 은 이 리포 · SP 어디에도 없다(게이트웨이의 것). 우리 쪽의 「한 곳에서 공표」 는 `capabilities.intake` 다.
- 도구 수는 `server.py` 의 `@mcp.tool(` 를 세어 낸다(스모크 · capabilities · parity 시험). 글에 박힌 90 은 README · TOOLS.md ·
  CLAUDE_DESKTOP.md 와 cae00 점검 문서(게시 때 고친다)다.
