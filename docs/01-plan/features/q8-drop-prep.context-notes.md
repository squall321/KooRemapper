# Context Notes — Q8 전각도 낙하 준비 3종

작업 중 내린 판단과 그 근거. 이어받는 사람이 다시 캐지 않도록 **왜** 를 적는다.

## 2026-10-10 — 요청서 전제를 재는 것으로 시작했고, ④가 반대였다

요청서는 "현재 `info` 는 bbox 를 하나만 내고 그것이 `*NODE` 전체 기준" 이라고 적었다.
**반대다.** `Mesh::calculateBoundingBox()`(`include/core/Mesh.h:258-268`)가 고아 절점을
**일부러 뺀다** — 주석에 이유가 적혀 있다("바깥에 떨어진 고아 참조 절점이 bbox 를 부풀리면
`map`·`shellmap` 의 모든 파라메트릭 비율이 하류에서 왜곡된다").

Q8 상황을 재현한 픽스처(요소 x 0~10, 고아 x=−40·28)로 쟀다 —
`info` 폭 **10** · `modelmeta model.bbox` 폭 **68** · `modelmeta parts[].bbox` 합집합 폭 **10**.

**그래서 67.50mm 를 낸 것은 KooRemapper 가 아니다.** 하류(DropSet)가 `*NODE` 에서 직접 뽑은
값이다. 이 도구는 함정을 피하는데 **그 사실을 말하지 않아서** 자기 bbox 를 계산하는 하류가
그대로 빠진다. ④의 수선이 "요소 기준 bbox 추가" 가 아니라 **"기준을 말하고 차이를 보이는 것"**
인 이유다.

★교훈 적용 — 지난 캠페인에서 반복된 실수 ③("옛 값·추정값을 검증 없이 참값으로 쓴다")과 같은
모양을 요청서에서 봤다. 요청서의 수치는 전부 실측이지만 **어느 도구가 낸 값인지**가 빠져 있었고,
그래서 원인이 KooRemapper 로 지목됐다. 수치를 적을 때 **누가 쟀는지**도 적어야 한다.

## 라벨을 바꾸지 않는다 — 소비자가 정규식으로 파싱한다

`platform/backend/app/runner/kfile_inspect.py:22-24` 가 `^Min bound:`·`^Max bound:`·`^Size:` 를
정규식으로 읽고, 그 값이 프런트 `FileMeta.bbox_min/max` → `ComparePanel`·`FilePanel` 로 간다.
`tools/regress/test_packed_node.py:51` 도 같은 패턴을 쓴다. **그래서 추가만 한다.**

덤으로 알게 된 것 — 플랫폼이 쓰는 `bbox_min` 은 `info` 에서 오므로 **이미 요소 기준이라
안전하다**. 고칠 데가 없다. 위험한 쪽은 `modelmeta` JSON 안에서 `model.bbox_min`(전체 절점)과
`parts[].bbox_min`(요소 기준)이 **같은 이름으로 다른 기준**인 것이다. 지금 프런트 `ModelMeta`
타입은 `model` 을 선언조차 하지 않아 소비자가 없지만, MCP·DataHub·AI 분석이 읽으면 걸린다.

## 정상 덱 출력을 더럽히지 않는다

`bbox basis` 한 줄은 **항상** 찍는다 — 그게 하류에 보내는 신호다. 전체 절점 bbox 와 고아 수는
**고아가 있을 때만** 찍는다. 모든 `info` 호출에 네 줄을 더하면 정작 중요한 비정상 신호가
일상 출력에 묻힌다.

WARN 문턱은 **`0.01 × 최대 요소 범위`** 로 둔다 — 축 범위가 0 인 평면 메시에서 0 으로 나누는
것을 피하면서 축척에 상대적이다. Q8 이면 기기 길이 ~150mm 의 1% = 1.5mm 이고 실제 차이가
52.95mm 이므로 걸린다.

## 2026-10-10 (이어서) — ④ 구현에서 **예정에 없던 둘**이 나왔다

### 신호가 플랫폼까지 끊겨 있었다

`info`·`modelmeta` 를 고치고 플랫폼 경로를 실제로 돌려 보니 `modelmeta.orphan_nodes` 가
`None` 이었다. `kfile_modelmeta.run_modelmeta` 가 `model` 블록을 **통째로 버린다** —
주석에 "model 카운트는 inspect 의 info 와 중복" 이라고 적혀 있고, **그땐 맞았다**(`model` 이
절점·요소·파트 수와 bbox 뿐이었을 때). 지금은 그 안에 **`info` 에 없는 신호**(고아 수·bbox
두 기준)가 들어 있다.

★지난 캠페인의 "진입점이 둘이면 거기서 정합성이 깨진다" 와 같은 모양이다. op 을 고치는 것으로
끝이 아니고 **소비자까지 세어야** 한다. 세 자리를 이었다 — 래퍼 통과 · 프런트 타입 선언 ·
`FilePanel` 표시. 타입 선언을 빠뜨리면 조용히 사라진다(`synthetic_footprint` 때 그랬다).

그리고 그 회귀(`test_orphan_node_signal.py`)는 **플랫폼이 실제로 돌리는 바이너리**를 쓴다.
게시본(`43084d35`)에서는 빨갛고, compat 빌드로 교체해야 통과한다 — **그게 의도다.** 지난
캠페인에서 "관문은 전부 초록인데 플랫폼은 구 바이너리" 를 겪었고, 이 가드가 그 자리를 막는다.

### `conventions.bbox` 가 거짓을 적고 있었다

새 문구를 추가했더니 JSON 에 **중복 키**가 생겨 뒤쪽이 이겼다. 그래서 기존 문구를 읽어 보니 —

> "model.bbox_*: 같은 기준의 합집합이라 덱의 고립 절점은 들어오지 않는다"

**사실이 아니다.** 고아를 x=−40 에 둔 덱에서 `model.bbox_min.x = -40` 이다. 중복을 지우고 그
자리를 바로잡았다. 이번 캠페인에서 계속 나온 종류 — **문서가 코드보다 앞서 말한다.**

### 라벨을 안 바꾼 것이 맞았다

`Min bound`·`Max bound`·`Size` 를 그대로 두고 추가만 했다. 회귀 C 절이
`kfile_inspect.py` 의 정규식을 **그대로 복사해** 맞춰 보므로, 누가 라벨을 바꾸면 거기서 걸린다.
그리고 C-2 가 "플랫폼이 받는 `Size` 가 요소 기준인가" 를 못 박는다 — 68 이 오면 사고다.
