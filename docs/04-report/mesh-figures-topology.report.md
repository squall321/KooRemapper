## PDCA 사이클 상세

### Plan

요청의 핵심은 **"메시에 적합한 걸로"** 였다. StepForge(CAD/OCC) 어법을 베끼지 않는 것이 제약이었고,
전달 방식은 사용자가 **"1차는 의존성 0"** 으로, 그림은 **네 개 전부**로 골랐다.

계획의 전제를 먼저 쟀고 **단면에는 3D 렌더링이 필요 없다**는 결론을 얻었다.

| 실측 | 값 |
|---|---|
| 286,052 요소(46.5MB) 배터리 적층 단면 | **5.51 s** · RSS 90MB |
| 470MB 권취 전극 덱 | **28.56 s** · RSS 1,019MB · 산출은 덱의 **0.33%** |

모서리∩평면은 1차 방정식이다 — 반복도 테셀레이션도 법선도 음영도 없으므로 **거짓말할 경로가 없다**.

### Design

**① 면이 아니라 모서리로 자른다.** 공용 면 테이블(`Element::getValidFaceIndices`)이 육면체 기준이고
퇴화 판정이 `fn[0]==fn[1] && fn[2]==fn[3]` 뿐이라, TET4(`n5..n8 = n4`)에서 면 0·3 이 **선인데 통과한다**.
그래서 단면은 **종류별 모서리 표**로 풀었다.

**② 자유면은 종류별 면 표로.** 같은 이유로 `surfview` 는 자기 면 표를 가졌다 — 그 사본이 뒤에
위상 정본화의 재료가 된다.

**③ 거절을 설계에 넣는다.** `stackdiagram` 은 파트 AABB 만 쓰는 모식도라 **감긴 적층에서는 쓸 수 없다**.
포갠 것을 층처럼 쌓은 그림은 완전히 그럴듯해 보이므로, 그 자리에서 **그리지 않는다**.

### Do

**신규 op 3종**

| op | 무엇 | 산출 |
|---|---|---|
| `section` | 평면으로 자른 요소 다각형 | `_section.json` + `_section.svg` |
| `surfview` | 자유면만 직교투영·깊이정렬 | `_surface.svg` |
| `stackdiagram` | 파트 축범위로 층 모식도 + 중립축 | `_stackdiagram.svg` |

**요소 위상 정본화** — 같은 지식이 **여섯 벌**로 흩어져 서로 달랐다. 그 중 **넷을 정본으로 모았다**.

| 사본 | 어디 | 맞았나 | 결과 |
|---|---|---|---|
| ① | `include/core/Element.h` 고정 육면체 표 (소비자 11곳) | **틀렸다** | **정본이 됐다** |
| ② | `surfview.cpp` 의 `facesFor` | 맞다 | 제거 → `using topo::facesOf` |
| ③ | `section.cpp` 의 `edgesFor` | 맞다 | 제거 → `using topo::edgesOf` |
| ④ | `ModelAssembler.cpp` 손으로 적은 사면체 면 표 | 맞다 | 제거 → `topo::facesOf(TET4)` |
| ⑤⑥ | 같은 함수 쌍의 육면체 면·모서리 사본 | 맞다(육면체 한정) | 제거 |

> ⚠ **"위상이 한 곳에서 나온다" 는 아직 참이 아니다.** 같은 육면체/사면체 표가 손으로 적힌 채
> 리포에 **최소 여덟 벌 더** 남아 있다(`ModelAssembler` 3 · `modelmeta` · `hfdamp` ·
> `PatchExtractor` 2 · `Element.h` 의 죽은 `getEdgeLocalNodes`). 값은 지금 일치해 결함은 없지만
> `PatchExtractor` 의 `TET_FACE`·`HF` 는 **순서가 정본과 다르다**. 정확한 문장은
> **"여섯 벌 중 넷을 정본으로 모았다"** 다.

## 완성된 항목

### 그림 (4종, 사용자가 전부 선택)

1. **접힘 적층 단면 두 칸** — `section` + `compare` + `mode: panels`. 칸마다 축·축척이 따로다
   (실측: A 는 축 y·z축 ×4.29, B 는 축 z·y축 ×6.15).
2. **변형 전·후 겹침** — `mode: overlay`. **같은 평면**으로 둘을 자르고 B 를 점선으로.
   절점 번호가 짝이라 짝맞춤 비용이 0.
3. **자유면 음영·와이어** — `surfview`. **등축**이다(3D 를 늘이면 모양 자체가 거짓이다).
4. **층 모식도** — `stackdiagram`. 중립축·기하 중심면·굽힘강성을 **같은 그림에** 긋는다.
   계산은 `neutralaxis` 와 **같은 `computeNeutralAxis()`** 이고 회귀가 두 op 의 숫자를 맞대어 본다.

### 거절이 기능인 자리

- `stackdiagram` — 솔리드 축 범위가 포개지면 **rc=1**, 그림을 쓰지 않고 `section` 을 안내.
  `force: true` 면 그리되 그림에 **"층 순서를 믿지 말라"** 를 적는다.
- 세 그림 op — **2차 솔리드**(ELFORM 16·17·25~28) 거절. ELFORM 23(20절점 육면체)은
  **거절하지 않는다**(1차 원본과 단면이 120 다각형·총면적 4.712178200 으로 동일).

### 고친 결함 — 출력이 거짓을 말한 자리

- overlay 의 B 덱이 `axis_chosen_because` 에 "config 가 지정했다" 고 **거짓**을 적었다.
- 제어문자를 버린 사실이 매니페스트에 없었다 → `title_control_chars_stripped`.
- 기본 평면이 **거울면**이라 `stackwrap` Y 뒤집힘에 **원리적으로 눈먼다**는 사실을 말하지
  않았다 → `at_is_default_mid_plane` + 콘솔 안내.
- 카탈로그의 `extract-surface` **"HEX8/TET4 지원"** 이 거짓이었다.

  에러가 됐다.
- 확대 배율이 응답에 **아예 없었다**(문서 세 곳이 준다고 적어 둔 값) → `figure_numbers`.
- 프런트가 세 그림에 **같은 캡션**을 돌려 썼다(`alt="단면 그림"` 이 자유면 뷰에도).

- 패리티 표의 리포트 행이 2026-08-15 에 멈춰 `web=False` 였다.
- 지어낸 footprint 를 **실측처럼** 내보냈다 — 유일한 impact 샘플에서 **25/25 가 합성**이고
  `zmin`/`zmax` 가 전부 None 이었다. 플래그·요약·경고를 전파하고 프런트가 **빨간 점선**으로 그린다.

- `platform/mcp_server/figures_smoke.py`(20항) — **오직 살아 있는 스택을 거쳐서만** 판정한다.
- `fit_to_budget` — 응답을 **재서** 파트 행을 뺀다. 61파트 덱에서 고정 캡 20 은 20행,
  재서 빼면 **25행**(같은 예산).

## 미완료 / 열린 항목

### ★작성 중 새로 발견 (아직 안 고쳤다)

1. **SVG 의 '거짓말 막는 글자' 두 줄이 겹친다.** `s_section.svg` 에서 가로 눈금 라벨이 y=860,
   바로 밑 `…배 확대 · 단위 없음` 이 **y=866** — 6 px 간격에 폰트가 11~12 px 다. 실제 배터리
   덱에서도 같다. 래스터로 확인했다(`google-chrome --headless --screenshot`). 회귀는
   **XML 파싱과 문자열 존재만** 보므로 이 충돌을 영원히 못 잡는다.
   ⚠ 체크리스트의 "이 호스트엔 래스터라이저가 없다" 는 **틀렸다** — `google-chrome` 과
   ImageMagick 이 있다. 할 수 없었던 게 아니라 **안 한 것**이다.
2. **2차 솔리드 거절이 그림 op 셋에만 걸려 있다.** `secondOrderSolidPids` 의 소비자는
   `section`·`surfview`·`stackdiagram` 뿐이다. 실측 — 같은 TET10 덱에서
   `modelmeta` 부피 **0.257812**(참값 0.5, **−48.4%**, rc=0·경고 없음),
   `extract-surface` 자유면 **12면**(참값 8). "op 전반이 거절한다" 로 쓰면 **과장**이다.
3. **`offset` 의 야코비안은 반쪽만 적으면 오해를 만든다.** 음수는 0개가 맞지만 같은 픽스처에서
   압출 24개 중 **16개가 두께 0**이고, 그 산출 덱을 `KooRemapper info` 에 넣으면 이 도구 자신이
   **"Negative Jacobian elements: 16"** 이라고 말한다. 회귀 D-3 의 셀 평균 척도는 0 을 음수로
   세지 않아 이것을 못 본다.

- ★**`figures_smoke.py`·`smoke.py` 가 어느 워크플로에도 없다**(`.github/workflows/` grep 0건).

### 기능·검증

- 위상 표 사본이 **최소 여덟 벌** 남아 있다(값은 일치하나 `PatchExtractor` 는 순서가 다르다).

  확인하지 않았다**. 검증은 "바깥으로 일관되다" 까지다.
- `q8-report-checklist.md` 의 **§3-1c 카드 폭**(`%8d`×5 → `%10d`)은 LS-DYNA 확인이 먼저다.

## 한계 (정직한 명시)

- `stackdiagram` 은 **모식도**다. 파트 AABB 만 쓰므로 감긴/접힌 적층에서 쓸 수 없고, 그 자리는
  거절한다. 정확한 기하는 `section` 이 답한다.
- `surfview` 는 **등축**이다. 적층이 얇게 보이는 것이 사실이고, 층 두께는 `section`(비등방·배율을
  적는다) 또는 `stackdiagram`(모식도)이 답한다.
- 큰 SVG(실측 12.2MB)는 MCP 5MB 상한에 걸린다 — `save_result_to_path` 로 돌려야 한다.
  삼각형을 솎아 줄이지 않는다(구멍이 뚫리면 그림이 거짓이 된다).
- 깊이정렬은 삼각형 무게중심 기준이라 서로 관통하는 삼각형은 순서가 틀릴 수 있다(그림에 적는다).
- `.svg` 다운로드 media_type 을 **일부러 `application/octet-stream` 으로 뒀다** — 같은 출처에서
  `image/svg+xml` 로 서빙하면 **저장형 XSS** 가 되므로, 클라이언트가 `<img>` 로만 띄운다.
- 챗·LLM 은 **픽셀을 못 본다**. 그래서 응답은 숫자가 중심이고 그림은 URL·파일로 간다.

## 교훈

### 잘된 점

- **거절을 기능으로 설계한 것.** 사용자가 ④ 를 만들라고 뒤집었을 때, 내 반대 근거 셋을 버리지
  않고 **동작 셋**으로 옮겼다(포개지면 거절 · 중립축을 같은 그림에 · 바닥 처리 수를 보고).
- **전/후를 재서 적은 것.** 옛 바이너리가 남아 있어 "5면 → 4면", "12/12 섞임 → 전부 바깥",
  "31200.4 → 31158.7" 을 **측정**으로 말할 수 있다.
- **감사를 반증 단계까지 돌린 것.** 48건 중 20건이 교차검증에서 탈락했고, 그 덕에 "stackdiagram
  이 셸 덱을 거절하지 않는다" 같은 그럴듯한 오보가 걸러졌다.

### 반복된 실수 (같은 모양이 네댓 번)

**① 같은 지식의 사본이 조용히 갈린다 — 다섯 번.** 위상 표 여섯 벌 → 플랫폼 바이너리 vs 리포
바이너리 → 카탈로그를 캐시한 API 프로세스 vs MCP 프로세스 → appt313 스테이징 바이너리 →
스테이징 셰임 2종. 매번 "정본을 정했다" 로 닫혔지만 **소비자를 전수로 세지 않아** 다음 사본이
남았다. 지금도 여덟 벌이 남아 있다.

**② "내가 잰 경로" 와 "실제로 도는 경로" 를 바꿔 말한다 — 세 번.** `build/dev` 직접 실행을 재고
플랫폼 동작을 주장했다(34/34 초록인데 MCP 에 ③④ 가 없었고, 관문 초록인데 바이너리가 세 op 을
몰랐다). **지금도 같은 모양이 하나 있다** — 회귀 70/70 인데 2차 솔리드는 그림 op 밖에서 여전히
조용히 틀린다.

**③ 옛 값·추정값을 검증 없이 "참값" 으로 쓴다 — 네 번.** `modelmeta` 의 "옛 값 = 맞는 값"(실제
+0.1338% 오차) · 쐐기의 "참값 0.5"(실제 0.25) · "등축 0.13 px"(실제 0.081) · 그리고 이 보고서를
쓰려고 적었던 **"비등방 ×412.8 → 33.46 px"**(어느 덱에서도 안 나오는, 곱셈으로 지어낸 수 —
실제는 배터리 덱 ×34.65 → 2.81 px).

**④ 못 한 일을 "할 수 없다" 로 적는다 — 두 번.** "통합 전 바이너리가 더는 없다"(세 벌이 살아
있었다) · "이 호스트엔 래스터라이저가 없다"(chrome·ImageMagick 이 있다). 둘 다 **백업·대체
수단을 안 찾아본 것**이다.

**⑤ 범위를 좁게 잡아 "완료" 로 닫는다.** 체크리스트 C 절이 `section` 만 봐서 ③④ 가 MCP 로
부를 길이 없었고, 게시를 항목에 두지 않아 34/34 초록이 플랫폼 동작을 뜻하지 않았고, D-5 가
"카탈로그에 적었다" 로 닫혔는데 카탈로그엔 0건이었고, 2차 솔리드 거절이 그림 op 만 보고 닫혔다.

**⑥ 숫자만 보는 관문은 통째로 빠진 기능을 통과시킨다.** 패리티가 SKILL.md 의 **숫자**만 봐서
도구 셋이 없어도 초록이었다. **같은 구멍이 지금 하나 더 있다** — 그림 회귀가 XML 파싱과 문자열
존재만 봐서 **라벨이 겹쳐도 통과한다**(위 미완료 1번).

### 그래서 바꾼 작업 방식

- 사본을 정본으로 모으기 전에 **"이 표의 무엇에 누가 기대나"** 를 셋으로 쪼개 묻는다 —
  면 **집합** · **감김** · **인덱스 번호**. 이 질문이 두 회귀를 미리 잡았다.
- **제약을 피하는 수선과 없애는 수선을 구분한다.** 시작 꼭짓점 보존은 "지금과 같아짐" 을 성공으로
  본 것이었고, 그 밑에 "옛 값 = 맞는 값" 이라는 검증 안 한 전제가 있었다.
- "참값" 을 적을 때 **측정인지 추정인지** 구분해 적는다.
- 수치를 적을 때 **덱 파일명을 함께** 적는다(요소 수가 같은 형제 덱이 다른 숫자를 낸다).
