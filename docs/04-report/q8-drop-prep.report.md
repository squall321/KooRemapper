## 2. ④ — 전제가 반대였고, 절반은 이미 되어 있었습니다

요청서는 "`info` 의 bbox 가 `*NODE` 전체를 본다" 를 전제로 했습니다. **코드로 재 보니
`info` 의 bbox 는 이미 요소가 쓰는 절점만 봅니다**(`Mesh::calculateBoundingBox()` 가 고아를
이미 뺍니다 — `map`/`shellmap` 의 파라메트릭 비율이 틀어지지 않도록 그렇게 되어 있었습니다).

즉 **67.50 mm 는 이 도구가 낸 값이 아닙니다.** 하류에서 `*NODE` 를 직접 읽어 뽑은 값입니다.
도구는 함정을 피하고 있었는데 **그 사실을 말하지 않아서**, 자기 bbox 를 따로 계산하는 쪽이
그대로 빠졌습니다.

그래서 고친 것은 bbox 값이 아니라 **기준을 말하게 한 것**입니다.

```
Min bound:    (0.0, 0.0, 0.0)          ← 라벨 그대로 (하류 파서가 이 세 줄을 읽습니다)
Max bound:    (14.55, 70.2, 150.1)
Size:         (14.55, 70.2, 150.1)
bbox basis:   요소가 쓰는 절점만 (고아 제외) — 낙하판·접촉면은 이 기준을 쓰라
All-node min: (-26.9, 70.2, 150.1)     ← 고아가 있을 때만 나옵니다
Orphan nodes: 118568
[WARN] x 축에서 전체 절점 bbox 가 요소 기준보다 52.95 넓다
```

- `Min bound`·`Max bound`·`Size` **라벨은 바꾸지 않았습니다** — 하류 두 곳이 정규식으로
  파싱하고 있어서, 이름을 바꾸면 플랫폼의 bbox 가 조용히 사라집니다.
- 고아가 **없으면** 전체 절점 블록과 경고를 내지 않습니다(정상 출력을 더럽히면 비정상 신호가
  묻힙니다).
- `modelmeta` 는 `bbox_basis`·`bbox_used_*`·`orphan_nodes` 를 JSON 으로 냅니다. 정규식이
  아니라 JSON 이라 깨지지 않습니다. **웹 화면에도 빨간 줄로 뜹니다.**

## 3. ② `cleanup-nodes` — 요청서가 보고한 실패의 원인을 찾았습니다

요청서 §1 에 적힌 것 — "비-`*NODE`/`*ELEMENT_` 줄에서 8칸·10칸·공백 분리로 숫자를 전부
긁었더니 118,568개 **전부가 참조됨**으로 나왔다."

**그 실패의 원인은 '숫자를 긁은 것' 이 아니라 `*SET_NODE_*` 블록까지 긁은 것입니다.**
운영 덱에는 보통 '전체 절점' 세트가 하나 있고, 그 블록은 **모든 절점 ID 를 글자 그대로
담습니다.** 그걸 참조로 세면 고아가 하나도 남지 않습니다.

재현해서 확인했습니다 — `*SET_NODE_*` 를 보통 키워드처럼 다루게 바꾼 바이너리에서
삭제 가능이 3 → **0** 이 되고, 회귀 18항이 빨개집니다.

### 그런데 반대로 고치면 또 깨집니다

`*CONSTRAINED_NODAL_RIGID_BODY` 는 절점을 직접 적지 않고 **절점 세트를 `NSID` 로** 가리킵니다.
요청서의 CNRB 71건이 바로 그 경로입니다. 세트 멤버십을 그냥 버리면 그 71개가 삭제 후보가
됩니다. 그래서 규칙을 이렇게 두었습니다.

| 무엇 | 참조로 세나 |
|---|---|
| 요소 연결성 | **센다** |
| `*SET_NODE_*` 멤버십 | **세지 않는다** (세트는 대신 **정리**합니다) |
| 세트를 **이름하는** 카드 | **센다 — 전이로** (CNRB 71건이 여기서 살아남습니다) |
| 그 밖 모든 키워드 | **센다**(과포함) — '내가 이해한 것만 지운다' |

### 쓰는 법

```yaml
# 1) 먼저 보기만 — 기본값입니다. 덱을 쓰지 않습니다.
model: q8_close.k
report: cleanup_report.json
```
```yaml
# 2) 분류를 확인한 뒤 지우기
model: q8_close.k
output: q8_close_clean.k
mode: safe                 # report(기본) | safe | force
prune_sets: true
report: cleanup_report.json
```

리포트에 `bbox_before`/`bbox_after` 가 **반드시** 들어갑니다 — 67.50 중 얼마가 애초에
형상이 아니었는지가 거기서 보입니다. 콘솔도 어느 축에서 얼마나 줄어드는지 한 줄로 말합니다.

### 요청서의 `keep_referenced_by` 다섯은 기본값으로 넣었습니다 — 다만

**그 목록이 안전을 만들지 않습니다.** 목록에 없는 키워드가 절점을 가리키면 조용히 깨지므로,
이 op 은 **모르는 키워드도 전수 훑어서** 삭제 후보와 같은 정수를 가지면 그 절점을 남기고
`unknown_keyword_kept` 에 적습니다. 목록이 바꾸는 것은 **귀속 이름**과 `mode: force` 분기뿐입니다
(회귀 J-2 가 "목록을 바꿔도 삭제 가능 수가 같다" 를 고정합니다).

### `*INCLUDE` 를 읽습니다

읽지 않으면 인클루드가 쓰는 절점을 고아로 보고 지웁니다. `mode: safe` 는 못 읽은 인클루드가
하나라도 있으면 **쓰지 않습니다**(rc=1). 인클루드 안에 정의된 절점은 **지우지 않습니다**
(주 덱만 다시 쓰므로 지울 수가 없고, 지울 수 없는 것을 '삭제 가능' 으로 세면 수가 거짓이 됩니다).

## 4. ① `extract-parts` — '뽑기' 보다 '남은 것이 멀쩡한가'

```yaml
model: q8_close.k
output: battery_only.k
parts: [12, 13, 14]
# 또는 PID 를 외우지 않고:
# part_titles: ["batt*", "*cell*"]
renumber: false            # true 면 매핑 표를 함께 냅니다
report: extract_report.json
```

op 이 **산출 덱을 되읽어** 네 축의 미정의 참조를 스스로 찍고, 0 이 아니면 rc≠0 입니다.

```
[OK] verify: 산출 덱의 미정의 참조 0 (절점·파트·섹션·재질 전수)
```

### `*INCLUDE` 를 펼쳐 넣습니다 — 이게 가장 중요합니다

2.32 GB 급 덱은 거의 늘 인클루드로 쪼개져 있습니다. 고른 파트의 요소가 그 안에 있으면
인클루드를 읽지 않는 순간 **요소가 하나도 없는 덱**이 조용히 나옵니다. 그래서 읽어서 제자리에
펼치고, 산출은 **홀로 서는 한 파일**이 됩니다(하류 `unfold`→`prestress`→`relax` 가 원하는 꼴).
못 읽는 인클루드는 **거절**합니다.

### 조용히 버리지 않습니다

- 읽을 수 있는 것은 격자 3족(`SOLID`·`SHELL`·`TSHELL`)과 **보 족 5종**
  (`BEAM`·`DISCRETE`·`MASS`·`SEATBELT`·`PLOTEL`)입니다 — 칸 자리를 LS-DYNA 매뉴얼로
  확정해 두었습니다(§9).
- 그래도 모르는 변형(`*ELEMENT_MASS_NODE_SET`·`*ELEMENT_INERTIA`·`*ELEMENT_SEATBELT_*` 등)이
  **고른 파트의** 요소를 담고 있으면 **거절**합니다. 안 고른 파트의 것이면 버리고 수로 적습니다.
  필요한 족이 더 있으면 말씀해 주세요 — 같은 자리에 한 줄씩 더하는 일입니다.
- 버린 **모든** 키워드를 `dropped_keywords` 에 키워드별로 셉니다.
- `*CONTROL_*` 과 `*DATABASE_`(단 `*DATABASE_HISTORY_*` 제외)는 **싣습니다** — 안 싣으면
  뽑은 덱이 애초에 돌지 않습니다.

## 5. ★확인 없이 정한 것 두 가지 — 한 줄로 바꿉니다

요청서에 명시가 없어 판단한 자리입니다. 원하시는 쪽이 다르면 말씀만 주시면 됩니다.

1. **`cleanup-nodes` 의 기본 `mode` 는 `report`** 입니다(덱을 쓰지 않습니다).
   → 지우는 쪽이 기본이면 사고가 조용합니다. 분류를 보고 `mode: safe` 를 한 줄 적는 것은
   쉽지만 지워진 덱을 되돌리는 것은 어렵습니다.
2. **`extract-parts` 의 `include.sets: referenced` 는 세트를 '자릅니다'**(빼지 않습니다).
   → 빼면 그 세트를 가리키는 접촉·경계 카드가 미정의 참조가 되어 덱이 돌지 않습니다.
   전부 빼려면 `include.sets: none` 입니다(그러면 검증이 그 손실을 잡습니다).

## 6. ★검증되지 않은 것 — 실제 덱으로 재지 못했습니다

**요청서의 실측 분류(고아 118,568 · CNRB 71 · 다른 세트 3 · 삭제 가능 118,529)를
이 도구로 재현하지 못했습니다.** 2.32 GB Q8 Close 덱이 개발 호스트에 없습니다.

- 회귀가 고정하는 것은 분류의 **수**가 아니라 분류의 **규칙**이고, 픽스처는 합성입니다.
- 요청서 §6 의 포맷 함정은 전부 합성 픽스처로 재현해 막았습니다 —
  8자리 절점 ID 가 칸을 꽉 채우는 경우 · CRLF · 고차 솔리드의 두 줄 절점 카드 ·
  `*SECTION_*_TITLE`/`*SET_*_TITLE` 제목줄 · `*SET_PART_LIST` SID 줄 위치.
- **덱을 받을 수 있으면**(또는 운영서버에서 `mode: report` 로 한 번 돌려 `cleanup_report.json`
  만 보내 주셔도 됩니다) 그 수를 대조해 이 보고서를 갱신하겠습니다. `report` 모드는 덱을
  쓰지 않으므로 안전합니다.

## 9. 보 족 다섯 — 칸 자리를 매뉴얼로 확정했습니다 (2026-10-11 추가)

`extract-parts` 가 보 요소를 담은 파트에서 거절하던 것을 풀었습니다. 근거는 LS-DYNA
매뉴얼 Vol_I (R16@e545952c7, 03/21/25) 원문입니다.

| 족 | Card 1 | 절점 칸 | PID 칸 | 추가 카드 |
|---|---|---|---|---|
| `BEAM` | `EID PID N1 N2 N3 RT1 RR1 RT2 RR2 LOCAL` | 2·3·4 | 1 | 옵션마다 1장 |
| `DISCRETE` | `EID PID N1 N2 VID S PF OFFSET` | 2·3 | 1 | `_LCO` 면 1장 |
| `MASS` | `EID ID MASS PID` | **1** | **3** | 없음 |
| `SEATBELT` | `EID PID N1 N2 SBRID SLEN N3 N4` | 2·3 **와** 6·7 | 1 | 없음 |
| `PLOTEL` | `EID N1 N2` | 1·2 | **없음** | 없음 |

★절점 칸 **개수**까지 적은 이유 — '칸 2부터 끝까지' 로 뭉개면 보의 `RT1`·`LOCAL` 과
안전벨트의 `SBRID`·`SLEN` 이 절점이 됩니다. 세기만 하면 과포함(안전한 방향)이지만,
**`renumber: true` 가 그 칸을 덮어써 카드가 깨집니다.**

`cleanup-nodes` 도 같이 정확해졌습니다 — 그 칸들과 번호가 같은 고아 절점이 전에는 '참조됨'
으로 영구히 남았습니다.

**아직 미지원**(만나면 거절하거나 과포함합니다): `*ELEMENT_MASS_NODE_SET`(칸 1 이 절점이 아니라
**절점 세트 ID** 입니다) · `*ELEMENT_SEATBELT_{ACCELEROMETER,PRETENSIONER,RETRACTOR,SENSOR,
SLIPRING}`(옵션이 아니라 **별개 키워드**이고 칸 배치가 다릅니다) · `*ELEMENT_INERTIA` 등.

### `info` 관련 정정

이 보고서 초안에 "`info` 가 매달린 절점을 찍지만 종료코드가 0 이다" 라고 적을 뻔했습니다.
**`--strict` 가 이미 그 일을 합니다** — 매달린 절점 덱에서 rc=1, 온전한 덱에서 rc=0 입니다.
음수 야코비안은 **일부러** 그 관문에 넣지 않았습니다(셸 덱이 전부 빨개져 진짜 결함을 가립니다).

바뀐 것은 하나입니다 — `--strict` 없이 돌렸을 때 **그 길이 있다고 한 줄 안내**합니다.
기본 종료코드는 그대로 0 입니다(바꾸면 이 op 을 부르는 플랫폼·pyKooCAE 체인이 전부 영향을
받습니다).
