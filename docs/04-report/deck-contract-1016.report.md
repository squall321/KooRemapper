### Value Delivered

| 관점 | 내용 |
|------|------|
| **Problem** | 덱을 고치는 op 들이 **주 덱 파일만** 세어 번호를 냈다 — 실사용 인클루드 덱 88장 중 83장에서 주 덱 최대값이 닫힘의 최대값보다 작아, 인클루드에 이미 있는 번호를 **다시 낼 수 있었다**(같은 종류 ID 가 둘이면 LS-DYNA 는 키워드 단계에서 멈춘다). 분석 op 은 마스터 덱에서 절점 0 을 냈고, 2차 솔리드 덱에서는 부피(−48.4%) · 질량 · 고아 수 · 야코비안이 **그럴듯하게** 틀렸다. meshfix 는 지운 절점을 가리키는 덱을 rc 0 으로 냈다. StepForge 와 합의한 우리 몫 셋(삽입 · 재결속 · 번호 발행)은 0건이었다. |
| **Solution** | 인클루드 닫힘을 **매뉴얼 규칙대로** 읽는 정본 하나를 세우고 발행자와 분석 op 이 모두 그것을 쓰게 했다. 칸 자리를 정본 표로 모아 **검사하는 쪽(`info --strict`)과 고치는 쪽(meshfix · 재결속 · 절점 정리)이 같은 표**를 읽는다. 틀린 줄 아는 값은 숫자 대신 `null` + 까닭으로 낸다. 경계 op 셋은 계약 대조에서 **하나라도 어긋나면 쓰지 않는다.** |
| **Function/UX Effect** | 마스터 덱의 info · modelmeta · 그림이 실제 모델 값을 낸다. 조각 넣기는 `id_floor` → StepForge `export_part_fragment` → `cad_solid_merge_to_deck` 세 걸음이고 **대응표 번호가 곧 덱 번호**다. 재메시 뒤 덧붙인 세트 · SPC · 접촉은 `rebind_entities_after_remesh` 로 새 번호에 묶인다. MCP 로 같은 길이 열리고(SKILL.md · 카탈로그 · 도구 설명 갱신), 살아 있는 관문이 새 op 셋을 지킨다. |
| **Core Value** | **덱의 바이트를 바꾸는 쪽은 덱을 깨면 안 된다.** 이번 결함의 대부분은 rc 0 으로 LS-DYNA 가 멈출 덱을 내던 것이다. 이제 모르는 칸 · 못 읽은 인클루드 · 짝 없는 절점 앞에서는 **멈추고 그 줄을 짚는다** — 조용히 틀린 덱보다 rc 1 이 낫다. |

## 교훈

### 잘된 점
- **주장을 돌려서 확인했다.** 지난 보고의 「선택형 hfdamp 가 의심스럽다(돌려 보지 않았다)」를 돌려 보니 사실이었다.
  이번 라운드에서도 ale · hfdamp · 업로드 순서 · StepForge 의 세트를 문서에 적기 전에 돌리거나 코드를 읽었다.
- **계약에서 하나라도 어긋나면 쓰지 않는다.** 삽입 · 재결속 · meshfix 가 같은 규율이다 — 거절 표가 기능의 절반이다.
- **검사하는 쪽과 고치는 쪽이 한 표를 읽는다.** 사본을 정본으로 옮기자 사본이 품던 결함 둘(i10 집중질량 · CNRB 둘째
  정의)이 저절로 드러났다.

### 반복된 실수
- **전제를 뒤집은 커밋이 그 전제를 적은 말을 남겼다.** `07a6802`(분석 op 이 인클루드를 읽는다) 뒤에도 「KooRemapper 는
  `*INCLUDE` 를 읽지 않는다」가 MCP 도구 설명 둘 · 카탈로그 셋 · 콘솔 안내 둘 · 주석 넷 · 백엔드 셋에 남았다. 마무리
  점검에서야 찾았다.
- **살아 있는 관문에 새 op 이 없었다.** 새 op 셋이 `deckops_smoke` 에 없어 게시본이 낡아도 빨개질 곳이 없었다.
- **장부 빈칸** — 지어 놓은 칸 둘(삽입 · 조각 `unit`·`frame`)이 빈칸이었다. 그리고 확인하지 않은 말(「저쪽 라이터는
  세트를 쓸 수 있다」)을 장부에 적을 뻔했다 — 커밋 전에 저쪽 코드를 읽고 고쳤다.

- **정본끼리도 어긋났다** — 카탈로그 offset 의 「TSHELL: NO czm」을 1차 점검에서 「이제 맞는 말」로 넘겼는데 돌려 보지 않은
  판단이었다. 2차에서 돌리자 거짓이었다(매뉴얼 §22 와 회귀 D 절이 맞았다). 그리고 문서의 **예시**(REMAP 스텝)도 돌려 보니 틀렸다.

### 그래서 바꾼 작업 방식
- 전제를 뒤집는 변경은 **그 전제를 말하는 문장을 같은 커밋에서 찾는다** — 코드 · MCP 설명 · 카탈로그 · 도움말 · 매뉴얼.
- 새 op 은 만들 때 `deckops_smoke` 의 `CASES` 에 넣는다(구조화 op 은 모르는 키를 거절하므로 `model` 을 덧붙이지 않는다).
- 굽기 같은 프로덕션 단계는 분류기가 막는다 — 우회하지 않고 명령을 건네고 기다린다(2차에서는 굽기 로그를 읽는 것도 막혔다 —
  끝났다는 알림을 기다린다).
- 문서에 적는 예시(체인 스텝 · 명령)는 **그 배선 그대로 돌려 보고** 적는다.
