## 구현하지 않고 표면화하는 것 (설계 트레이드오프)

  완화 요소가 이미 있다(JWT TTL 12h, MCP용 PAT는 revoked_at으로 폐기 가능). 저심각도에
  비해 비용이 커서 규칙 2에 따라 보류하고 사용자에게 결정을 위임한다.
- **Pagination 꽉 찬 마지막 페이지 off-by-one (#7, low)** — total/hasMore 입력이 없으면
  꽉 찬 중간 페이지와 마지막 페이지를 구분할 수 없다. 현재 어디에도 연결되지 않은(dead)
  컴포넌트라, 미사용 상태에서 API를 추가하는 것은 투기적이다(규칙 2). 연결 시점에 total을
  넘기도록 컴포넌트에 주석으로 한계를 명시하고 보류한다.

# 2026-09-23 — 인클루드·설정 파일 저장 정합성 (include-integrity)

## 왜 하는가 — 실측으로 드러난 사실 셋

사용자 질문("인클루드된 별도 파일이나 설정 파일도 저장되냐")을 코드·dev DB·디스크·바이너리로 확인한 결과다.

1. **리더는 `*INCLUDE` 를 따라가지 않는다.** `KooRemapper info` 로 확인: 인클루드 파일이 있어도
   없어도 노드 수가 같다(2/2). 인클루드된 내용은 모델에 들어오지 않는다.
2. **라이터는 `*INCLUDE` 줄을 보존한다.** `indent` 로 확인: 입력의 `*INCLUDE sub/extra.k` 가
   출력 덱 4–5행에 그대로 남고, op 자신의 `*INCLUDE <output>.dynain` 이 뒤에 붙는다.
3. **업로드는 경로를 평평하게 만든다.** `storage.safe_filename` 이 `Path(name).name` 으로 디렉터리를
   전부 떼어낸다 — `sub/part.k` → `part.k`.

**1+2+3 이 합쳐지면 사고가 된다.** 하위 폴더 인클루드를 가진 덱을 올려 op 을 돌리면, 산출물은
`sub/part.k` 를 가리키는데 세션에는 `part.k` 밖에 없다. 내려받아 LS-DYNA 에 넣으면 — LS-DYNA 는
인클루드를 따라가므로 — 실패하거나 조용히 파트가 빠진다. 도구는 아무 말도 하지 않는다.

## 설계 결정

**③ 하위 경로 보존이 정합성의 본체다**(앞서 "손이 제일 많이 간다" 고 적었지만 우선순위는 반대로 제일 높다).
②는 깨졌을 때 알려 주는 관문, ①은 재현성 위생이다.

- **경로 보존** — `safe_filename`(평탄화)은 그대로 두고 `safe_relpath`를 새로 만든다. 상대 경로만 허용하고
  `..`·절대경로·드라이브 문자를 제거하며 구성요소마다 기존 문자 규칙을 적용한다. 쓰기 직전에 목적지가
  세션 디렉터리 안인지 재확인한다(읽기 쪽은 `abs_path`가 이미 막는다 — 방어를 두 겹으로).
  `session_files.filename` 은 이미 하위 경로를 담을 수 있다(워커가 중첩 산출물을 그렇게 등록한다).
- **정합성 검사** — `meta.includes` 를 세션 파일 목록과 대조한다. 업로드 응답에 경고로 싣고(막지 않음),
  잡 생성 때 422 로 막되 **명시적 우회 플래그**를 둔다. 리더가 인클루드를 안 읽으므로 "op 은 성공하는데
  산출물이 깨지는" 형태라, 실행 전에 막는 것이 유일하게 효과적인 지점이다.
- **설정 파일 등록** — `build_command` 가 쓴 파일들을 `kind="generated"` 로 **명시 등록**한다.
  스냅샷 순서를 바꾸는 방식(=산출물로 잡히게)은 의미가 틀리다 — 그것은 바이너리의 산출물이 아니라
  플랫폼이 만든 입력이다. `inspect_kfile` 은 돌리지 않는다(yaml 이라 `info` 가 실패한다).

## 확인 방식
- 경로 트래버설: `..`·절대·드라이브·심링크·긴 경로·빈 구성요소를 단위 시험으로 막는다.
- 정합성: 하위 폴더 인클루드 덱을 올려 경고가 나오는지, 빠뜨리면 잡이 422 로 막히는지.
- 설정: 잡을 돌린 뒤 파일 목록에 `config.yaml` 이 `generated` 로 뜨고 내려받아지는지.

### 9. "예제가 곧 구동기" 설계의 한계 — 예제가 **안 켜는 옵션**은 아무도 안 본다

매트릭스가 42 op 전부 판정해도 여전히 못 보는 자리가 있었다. 소스의 `std::ofstream` 30곳을
전수 분류하니 셋이 더 나왔다 — cclip `stress_output: include` 의 dynain · cclip `free_output` 의
`_free.k` · squeeze `strain_mode` 의 dynain. 카탈로그 예제가 그 세 키를 안 적는다.

dynain 이 갈리는 것이 특히 나쁘다. `*INCLUDE` 로 **함께 풀리는 짝**의 개행이 어긋난다.
`DynainWriter.cpp:111` 은 이미 그 이유로 refFile 개행을 따르고 있었다 — 리포 안에 올바른
구현이 있었는데 셋만 빠져 있었다(`cclip.cpp:802` 가 meshfix 2줄 판정의 정본이었던 것과 같다).

그래서 관문을 **소스 축**으로 하나 더 뒀다 — `test_deck_ofstream_allowlist.py`. `std::ofstream`
을 파일별로 선언하고 수가 달라지면 FAIL 이다. 줄 번호는 흔들리고 변수 이름은 파일 안에서
겹치니(meshfix 의 `o` 가 둘) **수 + 이유**로 센다. 막는 것은 "아무도 모르게 늘어나는 것" 이다.

### 10. 우연한 보존은 계약이 아니다

`strip`·`matswap` 은 리눅스에서 CRLF 를 지킨다. 고쳐서가 아니라 **그 리더가 `\r` 을 안 떼기**
때문이다. 그래서 DeckWriter 로 옮겨도 변이 시험이 안 죽는다(리눅스에서는). 옮긴 이유는
MSVC 텍스트 모드가 그 경로에서 `\r\r\n` 을 내는 것이다. 변이가 안 죽는 변경은 커밋 메시지에
**안 죽는다고 적는다** — "변이 19건 중 18건 잡힘" 이 정직한 숫자다.

생겼을 것이다. 소비자가 늘면 이 숫자를 다시 재야 한다(`dist-to-drive.sh` 상단 표).

### 12. "컨테이너에 `.git` 이 없다" 는 틀렸다 — 없는 것은 `git` **실행 파일**이다

결론(런타임에 git 을 부르지 않는다)은 같지만 근거가 달랐다. `.git` 은 작업 트리 바인드로
읽힌다. 그래서 "파싱하면 되지 않나" 로 갈 수도 있었는데, 폐쇄망 운영 서버에는 애초에 리포가
없으므로 출처는 **배포가 내려놓은 파일**이어야 한다. 근거가 틀리면 결론이 같아도 다음 사람이
엉뚱한 방향으로 확장한다.

### 13. `BUILD_INFO.txt` 는 받는 쪽에 **한 번도 내려앉지 않았다**

`dist-to-drive.sh` 가 커밋·sha256·mtime 을 성실히 적어 올렸는데, `dist-from-drive.sh` 는 그것을
mktemp 스테이지에 받아 두고 **스테이지째로 지웠다**(trap). 즉 "운영에서 되짚을 수 있게" 라는
그 파일의 목적이 처음부터 달성된 적이 없다. **만드는 쪽만 보고 받는 쪽을 안 보면 이렇게 된다.**

### 14. ID 발행자 후보 목록이 두 곳 틀렸고 9개가 빠져 있었다

계획서의 8개 후보 중 `modelmeta` 는 발행자가 아니고(JSON 만 낸다), `cnrb2spring` 은 '최대+1' 이
아니라 **고정 번호대 + 충돌 검사**다 — 그래서 할 말이 다르다("겹쳐 발급할 수 있다" 가 아니라
"겹침 0건이라는 판정을 단정할 수 없다"). 반대로 빠진 발행자가 9개 더 있어 전수는 27곳이고,
**그중 18곳이 `ModelAssembler::loadBaseModel` 하나를 지난다.** 그래서 '발행자마다 한 줄'(27줄)이
아니라 **헬퍼 1개 + 창구 2개**가 최소다. 경고를 공통 함수(`hfdamp_apply` 등)에 넣으면 assemble
경로에서 **두 번** 찍힌다 — 진입점에만 둬야 한다.

### 15. 같은 판정이 셋 있으면 그중 하나는 틀려 있다

`*INCLUDE` 판정이 리포에 셋 있었다. `ModelAssembler::rsCountIncludes` 는 `*INCLUDE_PATH` 를
제외했고(옳다), `ReferenceIntegrity` 는 제외하지 않아 **탐색 경로를 파일로 셌다** —
`*INCLUDE_PATH` 만 있는 덱에서 `info` 가 거짓 경고를 냈다. `cclip` 의 스캔 코퍼스 수집도 같은
누락이었다. 그리고 **기존 `test_reference_integrity.py` 는 이 오탐을 못 잡는다**(진짜
`*INCLUDE` 만 쓴다) — 변이를 걸어도 초록이었다. 중복 구현은 시험도 함께 빗나간다.

### 16. ⚠ 내가 CI 를 깨뜨렸다 — 그리고 사실 확인이 그것을 찾아냈다

"gmsh 가 없으면 skip 이 아니라 FAIL" 로 바꾼 것은 옳다. 그런데 `.github/workflows/regress.yml`
은 gmsh 를 깔지 않는다 — **그 커밋 이후 CI 는 빨갛다.** 회신에 "CI 가 이제 막는다" 고 쓸 뻔했다.
규율을 바꾸면 **그 규율을 실행하는 자리(CI·개발 박스·컨테이너)를 전부 따라가야 한다.**
게다가 워크플로 파일은 이 토큰으로 못 올린다(`workflow` 스코프) — 패치를 리포에 실어 두는
것으로 대신했다. 재부팅이 개발 트리를 `reset --hard origin/main` 하므로 커밋 안 된 변경은 사라진다.

### 17. 변이 시험이 두 번 나를 고쳤다 — **헛통과와 거꾸로 된 가드**

· P1-8 에서 "덮어쓴 파일을 입력 종류 집계에서 뺀다" 는 가드를 썼는데 변이가 살아남았다.
  들여다보니 **가드가 거꾸로**였다 — 덮어쓴 파일의 **왕복 전** 개행도 이 잡의 입력이다.
  빼면 입력이 실제로는 갈려 있는데 "일치" 로 단정해 오탐을 낸다. 모를 때는 말하지 않는 쪽이다.
· P0-6 에서 '번호 불변' 시험을 산출 덱의 ID 집합 비교로 썼는데, 발급이 0건인 조합
  (`hfdamp` + 1파트 덱)에서는 **기존 ID 만** 비교해 헛통과했다. '입력 대비 새로 생긴 ID' 로
  바꾸고 **발급이 0건이면 그 자체로 FAIL** 하게 한 뒤에야 변이가 죽었다.
**변이가 안 죽으면 코드가 아니라 시험을 먼저 의심하라.**

### 22. 참조 검사를 넓힐 때 **오탐의 뿌리는 거의 늘 칸 읽기**였다 (P1-6)

요소→파트·파트→섹션·재질 검사를 붙이자 리포 덱 275장 중 21장이 떴다. 그중 2장은 **내 검사가
틀린 것**이었다 — `*PART` 카드2 를 10칸부터 읽었더니 칸이 어긋난 덱(`base_model_3part.k` 계열,
LS-DYNA 기준으로는 SECID 칸이 **정말로 비어 있다**)에서 그 파트가 '정의된 적 없다' 가 되고,
그 파트를 쓰는 요소 전부가 가짜 미정의 참조로 뜬 것이다.

고친 방향은 **새 규칙을 만들지 않는 쪽**이었다. `KFileReader::parsePartSection` 이 이미
"자유형식 토큰 → 10칸 → 8칸" 이라는 순서를 정해 뒀으니 그 순서를 그대로 쓴다. 판정을 하나 더
만들면 같은 덱을 두 곳이 다르게 읽는다. 대신 어긋난 카드는 `notChecked` 로 **세어서 말한다** —
조용한 것과 못 본 것을 감추는 것은 다르다.

남은 19장은 전부 실제 결함이었다(섹션이 아예 없는 덱, 8칸 덱에 10칸으로 적힌 요소 카드, …).
**픽스처를 고치지 않았다.** 고치면 회귀가 무엇을 지키는지 알 수 없게 된다 — 그래서 시험이
"이 덱은 계속 시끄러워야 한다" 를 이름으로 못 박는다.

부수로 얻은 것: `rsIntField` 는 공백이 하나라도 있으면 **-1** 이다. 내 고정폭 폴백이 칸을
다듬지 않고 넘겨 그 길이 통째로 죽어 있었고, 돌연변이 시험(토큰 경로를 끄기)이 그것을 드러냈다.
시험이 통과한다고 그 길을 밟은 것은 아니다.

### 23. `*CONTACT` 손상 탐지는 **서명이 확인될 때만** 자를 들이댄다

"표준 접촉은 Card 1·2·3 이 필수" 는 표면 대 표면 계열에서만 참이다. `*CONTACT_1D`·
`*CONTACT_INTERIOR` 는 카드가 한 장이다. 그래서 Card 1 의 3·4번째 칸이 SSTYP/MSTYP 로
읽히는지(0-6) 확인되고 나서야 3장 규칙을 쓴다. 이 빗장이 없으면 그 변종이 통째로 "필수 카드가
1장뿐" 으로 뜬다 — 돌연변이 M12 가 처음에는 살아남았고, 그 변종 덱을 시험에 넣어서야 죽었다.

### 24. 정의는 **한 키워드 아래 여러 장** 온다 — 첫 카드만 읽은 대가

P1-6 을 커밋·푸시한 뒤에 검증 워크플로가 내 판정을 뒤집었다. `*SECTION_SOLID` 하나 아래
섹션 1·2 를, `*MAT_ELASTIC` 하나 아래 재질 1·2 를 쓰는 것이 **정상**이다 — 매뉴얼이
"Card Sets. For each section … include one set of data cards. This input ends at the next
keyword" 로 못 박아 뒀고 `examples/wrap/cylinder_2layer.k` 가 실제로 그렇게 생겼다.
블록의 첫 카드만 읽은 내 구현은 그 덱 2장을 **가짜 미정의 참조**로 띄웠고, 더 나쁜 것은
회귀가 그 오탐을 "계속 시끄러워야 한다" 로 못 박고 있었다는 것이다.

고친 방향 — 카드 세트의 **길이 표가 우리에겐 없다.** 그래서 정의는 **넘치게** 모은다(데이터
줄 첫 칸의 양수를 전부 정의로). 넘치면 놓칠 뿐 없는 것을 있다고 말하지 않는다. 오탐과 누락
중 오탐이 훨씬 비싸다 — 한 번 나면 이 보고를 아무도 안 믿는다.

배운 것 두 가지. ① **전수 조사에서 '떴다' 를 '진짜다' 로 넘겨짚지 마라.** 19장 중 17장이
진짜였고 2장이 내 오탐이었는데, 17장을 하나씩 확인하고 나서 나머지도 같은 부류라고 봤다.
② 픽스처를 이름으로 못 박는 시험은 **판정이 틀리면 그 틀림까지 못 박는다.** 강한 시험의
대가다 — 그래서 못 박기 전에 그 덱을 매뉴얼로 한 번 더 봐야 한다.

### 25. `*SET_*_GENERATE` — 범위를 펼치면 **없는 개체를 만들어 낸다**

`ct_parseSets` 는 데이터 줄의 모든 토큰을 멤버로 읽었다. `*SET_PART_LIST_GENERATE 7 / 1 5` 가
**파트 1 과 5** 로 읽혔다. 더 나쁜 것은 type 판정이었다 — `_LIST` 를 찾아 **그 앞만** 남겼으니
매뉴얼 정규 철자에서 방언이 통째로 사라지고 `type` 이 "PART" 가 됐다. 그러면 소비자가 그 틀린
멤버를 그대로 쓴다. 실측으로 `modelmeta` 의 연결 변이 하나 빠졌다.

**고칠 때 하마터면 더 나쁜 것을 만들 뻔했다.** 처음엔 범위를 그대로 펼쳤다. 매뉴얼을 읽고서야
알았다 — "B[N]BEG and B[N]END may simply be **limits on the ID's** and not element ID's" 이고
멤버는 "그 사이에 **정의된** ID" 뿐이다. 그대로 펼치면 `1 999999` 짜리 덱에서 없는 파트 백만
개가 멤버가 되고, `mm_resolveSide` 는 존재 여부를 걸러 주지 않으므로 그것이 곧 연결 그래프에
들어간다. 처음 판이 통과한 시험(A-1 이 `[1,2,3,4,5]` 를 기대했다)은 **틀린 것을 못 박고
있었다** — 24번과 같은 실수를 이틀에 두 번 할 뻔했다.

그래서 파서는 **펼치지 않는다.** `SetDef::ranges` 에 담고, **정의 목록을 아는 쪽**
(`ct_resolveSetRanges(sets, mesh)`)이 좁힌다. 안 부르면 `ids` 가 빈 채로 남는다 — 그것이
의도다(닫히는 쪽으로 실패). 화면은 "못 좁혔다" 와 "0건" 을 구분해 말한다.

교훈 — **기대값을 코드에서 뽑지 말고 매뉴얼에서 뽑는다.** 내 첫 시험의 기대값은 내 구현을
그대로 베낀 것이었고, 그러면 시험은 아무것도 검증하지 않는다.


### 26. 전수 스윕과 돌연변이 시험을 **같은 바이너리 경로로** 동시에 돌리면 안 된다

2026-09-28. SECTION·MAT 겹침 검사의 오탐 표면을 실사용 1,268장에 재는 스윕을 배경에 걸어 두고,
그 사이에 돌연변이 시험을 돌렸다. 돌연변이 스크립트는 `build/linux/bin/KooRemapper` 를 **변이된
코드로 몇 번이고 재빌드한다** — 스윕이 쓰는 바로 그 경로다. 결과로 "실사용 5장에서 겹침" 이
나왔는데 그 5장을 손으로 열어 보니 지금 바이너리는 아무 말도 하지 않았다. **측정이 변이된
바이너리의 것이었다.**

**How to apply:** 오래 도는 측정은 바이너리를 **복사해서** 쓴다(`cp build/linux/bin/KooRemapper
/tmp/…/kr_stable`). 그리고 측정 중에는 빌드를 걸지 않는다. 돌연변이 시험이 도는 동안 어떤 배경
측정도 그 경로에 기대면 안 된다.

### 28. 진단 체계 — 기록은 있었고, 없던 것은 **시각·상관자·빌드 정체**였다

2026-09-29. "실패했을 때 사용자가 로그를 복사해 넘기면 우리가 그것만 보고 고치게 하자" 는 요청으로
시작했다. 코드 전에 실측부터 했고, **전제가 뒤집혔다.**

기록 토대는 이미 있었다. `Job` 이 `resolved_cmd`(실제 argv + 생성된 yaml) · `exit_code` ·
`stdout_path`/`stderr_path` · `error_summary` · `warnings` 를 남기고, `GET /jobs/{id}/logs` 가
평문으로 준다(경로 봉쇄까지 있다). 그래서 이 일은 "기록부터 시작" 이 아니라 **"흩어진 것을 한
덩어리로 묶기"** 다. 만약 실측을 건너뛰고 "로그를 남기자" 로 착수했다면 이미 있는 것을 두 번
만들었을 것이다.

진짜 구멍은 셋이었다.

 · **잡마다 어느 바이너리로 돌았는지가 안 남는다.** `buildinfo` 는 `/api/health` 전용이다. 이
   캠페인에서 배포 자리 바이너리가 **다섯 번** 다른 것으로 덮였으니(27번), 빌드 정체가 없는 로그는
   증거가 아니다. 이것이 1순위다.
 · **로그 줄에 시각이 없다.** `main.py:24` 가 `logging.basicConfig(level=INFO)` 뿐이고 uvicorn 기본
   접근 포맷도 시각을 안 찍는다. "14:30 에 실패했다" 를 로그와 맞출 방법이 아예 없었다.
 · **접근 로그가 심장박동으로 덮여 있다.** `koorm_api.out` 의 `/api/health` 줄이 1,461개다 —
   감독자가 분당 폴링한다. 감독자 로그가 59% 심장박동이던 것과 **같은 병**이다(P1-10 ②).
   ⚠ **정정.** 처음에 이것을 "번들 품질의 전제" 로 적었는데 과장이었다. 앱·워커 줄은 stderr 로 가서
   `koorm_api.err` 에 따로 쌓인다(`grep -c koorm.worker koorm_api.out` = 0). 이 소음은 **요청 갈래**를
   못 읽게 만들고 **잡 갈래는 막지 않는다.**

네 번째 구멍은 병렬 정독이 찾았고 실측으로 확인했다. **잡이 흔적 없이 사라지는 부류가 있다.**
보존된 로그에 `ERROR:koorm.worker:job … crashed` 4건이 있고 끝이
`sqlalchemy.orm.exc.StaleDataError: UPDATE statement on table 'jobs' expected to update 1 row(s);
0 were matched.` 다 — 잡이 도는 중에 행이 사라졌다(세션 삭제 + `ON DELETE CASCADE`). 복구 경로
(`runner_loop.py:536-542`)가 `j = await db.get(Job, jid)` 뒤 `if j and j.status == "running"` 이라
**행이 없으면 아무것도 쓰지 않는다.** 확인 — 그 4건은 DB 에 **한 건도 없고**,
`error_summary = 'worker exception'` 인 잡은 전체에서 **0건**이다(현재 잡 11건). 복구가 한 번도
성공한 적이 없다.

그래서 설계가 바뀐다. **번들은 DB 행에만 의존할 수 없다.** 크래시 기록을 행이 없어도 남는 자리
(잡의 stderr 파일)에 쓰고, 번들 조립은 **잡 id + 파일**만으로도 동작해야 한다. 행이 없을 때
404 로 끝내면 정작 가장 진단이 필요한 부류에서 진단이 불가능해진다.

**정한 것** — 받는 형태는 **둘 다**(짧은 요약은 클립보드, 전문은 `.zip`). 덱 본문은 **메타만
기본 + 문제 줄 opt-in**(고객 CAE 모델이라 형상·물성이 기본으로 나가면 안 된다). 서버측 로그는
**상관자 방식**(correlation id 가 붙은 줄만, 타 사용자 줄은 섞지 않는다).

**How to apply:** 새 기능 요청을 받으면 "무엇을 만들까" 보다 **"이미 무엇이 있나"** 를 먼저 grep
한다. 이 리포는 같은 일을 다른 이름으로 이미 해 둔 경우가 잦다. 그리고 로그 기능을 만들 때는
**읽을 수 있는지**를 먼저 본다 — 심장박동이 덮은 로그와 시각 없는 줄은 기록이 아니라 소음이다.

### 29. 진단 체계 구현 — 주석 하나가 나를 틀리게 했고, 심링크가 레다ct 를 뚫었다

2026-09-29. 28번의 설계를 그대로 구현했다(0~5단계). 여기서 배운 것을 적는다.

 · **`SessionFile.rel_path` 는 세션 폴더 기준이 아니다.** `app/models.py:107` 주석이
   `# rel to session dir` 라고 적어 뒀는데 실제로는 **스토리지 루트 기준**(`<user>/<session>/<name>`)
   이고 정본 접근자는 `storage.abs_path()` 다(`storage.py:108`). 그 주석을 믿고
   `resolve_within(session_dir, rel_path)` 를 써서 경로를 두 번 겹쳤고, 덱 줄 발췌가 조용히 빈
   dict 를 냈다. **주석은 근거가 아니다 — 쓰는 쪽(`services.py:264`)을 봐야 한다.**
   (그 주석 자체는 내 변경 범위가 아니라 고치지 않았다.)

 · **`platform/storage` 가 심링크다**(`/data/svc/kooremapper/storage`, D9 이전). 그래서 레다ct 가
   `storage_dir.resolve()` **하나만** 접었을 때, 실제로 쓰이는 미해석 경로가 그물을 빠져나가
   `<home>` 으로 접혔다. 절대 경로가 새지는 않았지만 **번들을 읽는 쪽이 "이게 스토리지인지" 를
   알 수 없게** 됐다. 심링크가 있는 배치에서는 **양쪽 다** 접어야 한다. 시험이 이것을 잡았다.

 · **"행 없이도 번들을 내준다" 는 설계를 버렸다.** 28번에서 그렇게 적었지만, 행이 없으면
   `user_id` 가 없어 **소유권을 확인할 방법이 없다.** 인증 없이 내주면 접근 통제 구멍이고 그쪽이
   더 나쁘다. 사라진 잡은 `_note_crash` 가 잡의 stderr 에 적는 CRASH 블록과 워커의 ERROR 줄이
   정본이며, 그것을 읽는 사람은 서버에 있는 유지보수자다. 번들은 행(=소유권)을 요구한다.

 · **시험이 실제 DB 를 쓴다.** 컬럼을 더하고 `alembic upgrade head` 를 올리기 전에는
   `column jobs.env_snapshot does not exist` 로 **25건이 빨갰다.** 모델만 바꾸고 시험을 돌리면
   코드 결함으로 오해한다.

 · **또 파이프로 종료코드를 감췄다.** `pytest -q | tail -12` 로 돌려 "exit code 0" 을 보고
   초록이라 읽었는데 실제로는 25 failed 였다. 27번에 적어 둔 실수를 **같은 세션에서 반복했다.**
   그래서 이후에는 `> 파일 2>&1; rc=$?` 로 받고 rc 를 먼저 찍는다.

 · **내 수정 자체가 틀렸다 — `rmtree` 가 "남는 자리" 를 지운다.** 28번에서 크래시를 "행이 없어도
   남는 자리(잡의 stderr 파일)" 에 적기로 했는데, `delete_session` 이 세션 폴더를 `shutil.rmtree`
   로 통째로 없앤다(`sessions/services.py:287-289`). 그러면 `open(path,"a")` 가
   `FileNotFoundError` 로 실패해서, **정작 대비하려던 그 부류에서 파일에는 아무것도 남지 않는다.**
   손으로 재현해 확인했다. 이제 **인스턴스 로그에 먼저** 적고 파일은 보조로 둔다. 그리고 호출자가
   "파일에 남겼다" 고 **단정하지 않는다** — 못 남겼으면 그렇게 말한다. 안심시키는 거짓 보고가
   침묵보다 나쁘다.

 · **소스만 고치고 `dist` 를 두면 화면에 없다.** 프런트 두 파일을 고치고 빌드를 안 해서 버튼이
   실사용에 없었다(`dist` 가 09-27 것이었다). "다 수정했나" 를 확인하다 잡았다. 빌드 뒤 실사용
   API 가 새 번들을 서브하는 것까지 봤다(재기동은 필요 없다 — 디스크에서 읽는다).

 · **관측을 고친 것과 원인을 고친 것은 다르다.** `delete_session` 은 여전히 도는 잡을 보지 않는다.
   이 작업으로 달라진 것은 그 사실이 로그에 남는다는 것뿐이다. 막을지(409) 먼저 취소할지는
   제품 동작이 달라지는 결정이라 사용자에게 물었다.

**How to apply:** 새 칸을 더하면 **마이그레이션을 올린 뒤** 시험을 본다. 레다ct 를 쓰면 그 경로가
**심링크인지** 확인한다. "남는 자리" 에 적기로 했으면 **그 자리가 정말 남는지** 그 시나리오를
손으로 재현해 본다. 프런트를 고쳤으면 **빌드했는지** 본다. 그리고 긴 명령은 파이프로 감싸지
않는다 — 감싸면 실패가 사라진다.


### 30. 적대적 검토가 내 진단 체계에서 셋을 더 찾았다 — 셋 다 사실이었다

2026-09-30. 29번을 커밋한 뒤 "다 수정했나" 를 확인하면서 내 변경을 5갈래로 적대적 검토시켰다.
**셋이 나왔고 셋 다 내가 직접 재현했다.** 하나하나가 "조용한 거짓" 부류다.

 · **`Job.input_file_ids` 를 아무도 채우지 않는다.** 리포 전체에 쓰는 코드가 없고 실측도
   `select count(*), count(input_file_ids), count(output_file_ids) from jobs` → **11 | 0 | 11** 이다.
   내 번들은 그 칸만 보았으므로 `deck_lines` opt-in 이 **아무것도 담지 못하고** 모든 번들이
   `입력 : (없음)` 이라고 적었다 — 사용자가 켤 수 있는 유일한 동의 장치가 죽어 있었다.
   고침 — 비어 있으면 세션의 `input` 파일로 되돌아가고 **근거를 번들에 적는다.**

 · **덱 원문 줄이 `deck_lines` 와 무관하게 나간다.** `ModelAssembler.cpp:3111` 이
   `f.text = rawLines_[li]`(덱 원문)을 출력 목록에 넣고 `merge.cpp:1147` 이 `console.info` 로 찍는다.
   stdout 은 플래그와 무관하게 번들에 실리므로 **"끄면 덱 본문이 안 나간다" 는 지킬 수 없는 약속**
   이었다. 고침 — 데이터를 지우면 진단이 죽으니 **사실을 적는다.** 번들 `notes` 와 화면 문구를
   바꿨다("덱 발췌 더 담기" + "로그에는 도구가 출력한 덱 줄이 이미 포함될 수 있습니다").

 · **500 에 상관자가 안 붙었다 — 상관자가 필요한 바로 그 경우다.**
   `@app.exception_handler(Exception)` 은 Starlette 이 `ServerErrorMiddleware` 로 옮겨 달고 그것은
   사용자 미들웨어보다 **바깥**이다. 그래서 라우트가 터지면 (1) 내 미들웨어의 응답 후처리가 아예
   안 돌아 헤더가 안 붙고 (2) `finally` 가 먼저 돌아 contextvar 가 `-` 로 돌아간 뒤 핸들러가 로그를
   찍었다. 재현 — `/ok`·`/four` 는 붙는데 `/boom` 은 `X-Request-Id=None`,
   `ERROR app.shared.errors [-] Unhandled error`. 고침 — 상관자를 `request.state` 에도 두고 에러
   핸들러가 헤더와 500 본문에 싣는다.

**How to apply — 내가 놓친 이유가 제일 중요하다.** 내 시험은 `diagnostics.build` 를 **직접** 부르며
`inputs` 를 손으로 넘겼다. 실사용은 `_assemble_diagnostic` 을 지난다. 즉 **실사용이 쓰지 않는
장치로 관문을 측정했다** — 26번이 돌연변이 바이너리로, 24번이 같은 박스의 절대 경로로 틀렸던 것과
같은 부류다. 그래서 시험을 실사용 진입점에 붙여 다시 썼고
(`test_the_production_path_finds_the_input_deck`), 그 시험이 있었다면 첫 판에서 잡혔다.

**규율:** 새 관문을 만들면 **실사용이 그 관문에 들어가는 경로로** 시험한다. 헬퍼를 직접 부르는
시험은 그 헬퍼만 지키고, 아무도 그 헬퍼를 그렇게 부르지 않으면 아무것도 지키지 않는다.

### 31. 배포 절차를 베끼면 뒤처진다 — 포털의 forge 갱신이 그랬다

2026-09-30. "한 줄로 반입+재기동" 을 만들다가, 그것을 실제로 부르는 자리가 HWAXPortal 의
`infra/scripts/update-forges.sh dynaforge` 임을 알았다. 그리고 그 함수가 update-all
(`deploy-all-from-drive.sh` 의 `if want kooremapper` 절)을 **손으로 베낀 축약판**이었다.

베낀 쪽에 없던 것 — `platform/.env` 부트스트랩 · `set_remote KOORM_DRIVE_REMOTE` · 리포 없을 때
clone · 지문 기반 재기동(`hwax_restart_cycle`). 그리고 **프로브가 루트를 봤다**: `:8700/` 은 SPA 라
백엔드가 고장나도 200 이고 `:8701/` 은 MCP 루트라 404 여서, '떠 있지만 고장난' 상태가 합격하고
MCP 는 매 회 죽은 것처럼 보였다. 정본은 이미 `/api/health`·`/mcp` 짝을 쓰고 있었다.

**How to apply:** 배포 절차를 두 군데 쓰지 마라. 대상 선택이 있는 정본이 있으면(`want`) **위임**한다
(`deploy-all-from-drive.sh kooremapper`). 축약판은 처음엔 같아 보이고 시간이 지나면 조용히 갈라지는데,
갈라진 쪽이 하필 '초록' 을 찍는다.

⚠ 다만 **dev 박스로는 위임하지 않는다.** `git_update` 가 기본으로 `git stash push -u` +
`git reset --hard origin/<branch>` 를 한다 — 타 세션 WIP 를 날리고 공용 stash 스택까지 건드린다
(`NO_GIT_RESET=1` 이 escape hatch). 이 리포에 이미 적어 둔 두 위험(재부팅 reset · bare stash 금지)이
바로 그 함수다.

**이 리포 쪽에 더한 것** — `dist-from-drive.sh --restart`. 반입만 하고 `start.sh` 를 부르는 **수동**
경로는 `start_instance` 가 살아 있는 api 를 `✓ already running` 으로 건너뛰어 **새 코드가 안
올라간다.** `--restart` 는 `start.sh`(postgres → alembic upgrade head → api 순서다) 뒤
`restart-api-only.sh` 까지 돌리고 `/api/health` 가 **200 인지** 확인한 다음 revision 을 찍는다.

### 32. 메시 그림 — "3D 렌더링이 필요하겠지" 에 **아니라고** 답한 근거 (2026-10-03)

사용자 요청은 "stepforge처럼 가시화 + svg나 이미지로 MCP 전달" 이고 덧붙인 것이 **"메시에 적합한
걸로 해야 해"** 였다. StepForge 를 베끼지 말라는 뜻으로 읽었고, 재 보니 그 말이 맞았다.

**단면에는 3D 렌더링이 필요 없다.** 모서리∩평면은 1차 방정식이다 — 실측으로 273,600 요소(실제
배터리 적층)가 **순수 파이썬 0.79~0.83 s**, 별도로 잰 288,000 요소 합성 패널이 **0.35 s** 다.
그리고 **단면이 스스로 100배 솎는다**(288,000 요소 → 2,880 다각형 → SVG 163 KB). WebGL·GPU·OCC
가 하나도 필요 없다. 더 중요한 것 — 음영도 법선도 테셀레이션도 안 쓰므로 **거짓말할 경로가 없다.**

**버린 CAD 어법과 그 근거(숫자).**
  · **은선 투영** — 은선 제거의 결과로 남는 "보이는 선" 은 결국 자유면 모서리 89,292개인데 그것은
    면을 **세기만** 해서 2.25 s 에 나온다. 투영도 깊이정렬도 필요 없다. 게다가 자유면 모서리만
    그려도 `ink_ratio` 가 0.68 로 포화 근처다. 대체물은 특징 모서리(이면각) → O(10²~10³).
  · **단면 위 최소거리 치수** — 정합 메시에서 인접 층은 **절점을 공유**하므로 최소 간극이
    구조적으로 **정확히 0** 이다(`modelmeta` 가 `wrapped.k` 의 두 계면 모두 `gap_min: 0`).
    재면 언제나 0 이고 뜻이 없다. 대체물은 층 두께와 `R−z` — 둘 다 닫힌식으로 안다.
  · **전체 와이어프레임** — `ink_ratio`(선 길이 px ÷ 캔버스 픽셀) 임계가 **약 33,000 HEX8** 이다.
    배터리 273,600 요소는 **5.49**(픽셀마다 5.5번 칠한다), 자유면만 그리면 0.68.
  · **등각 칸** — 배터리 적층 60장 전체가 1200×900 등축에서 **28.19 px**, 다섯 층 유형이 **전부
    1 px 미만**. 가로:최박층 = **1 : 9,375** 다. 사용자가 말한 "1/1000 급" 은 과소평가였다.

**메시에서 더 강해지는 것 — 겹침.** CAD 의 "과제끼리 나란히" 는 파트를 이름으로 짝짓고 신뢰도를
달아야 한다. 메시 덱 쌍에는 그 문제가 **없다** — 절점 번호가 짝이고 KooRemapper 가 그것을
**요구한다**(§44.6·44.7). 그래서 나란히가 아니라 겹침으로 승격된다.

**그대로 베끼는 것 — StepForge `core/figure.py` 의 함정 16개 전부.** 그 파일은 기하를 한 줄도 안
만지고 `*PART` 제목은 STEP 라벨과 똑같이 자유 텍스트이며 같은 챗 호스트가 같은 규칙으로 자른다.

**1차는 의존성 0 으로 한다(사용자 결정).** C++ `section` op 이 좌표+매니페스트를 내고, 그림은
`ReportVisuals.tsx` 가 이미 하는 방식(인라인 SVG + 그림 안 범례 + canvas 경유 PNG)으로 그린다.
**그림 규약은 이미 리포 안에 있다 — 없는 것은 메시를 그리는 부분이다.** MCP 는 매니페스트를
텍스트로 + SVG URL 을 낸다. Claude 시야에 PNG 를 넣는 것은 2차이고, 그때 matplotlib + 나눔고딕
값을 치른다(한글 이름을 PNG 에 그리려면 폰트 래스터라이저가 필요하다).

### 33. 그림은 조용히 틀린다 — 재서 막을 것 (2026-10-03)

적대적 검토가 다섯 차원 **전부 FLAWED** 로 돌려보냈다. 그림이 "돌기는 돌고 그럴듯한데 틀린" 길이
그만큼 많다는 뜻이다. 설계를 바꾼 것들만 남긴다.

  · **평면 축을 잘못 고르면 60층 적층이 한 층의 바닥 윤곽이 된다** — 배터리 덱 z=const 는 61
    파트 중 **1개**만 맞고 x·y 는 56개다. 그런데 **감긴 덱은 반대다** — `refshell` 이 폭을 +z 로
    쓸므로 `wrapped.k` 는 z=const 가 3파트·72다각형이고 x=0 은 23개뿐이다. 규칙은 "적층 방향에
    수직" 이 **아니고** "이 덱에서 층이 어느 축으로 쌓였나" 다.
  · **평면이 층 경계에 정확히 걸리는 것이 사용자가 가장 보고 싶은 자리다** — 그리고 그것이 퇴화
    케이스다. 배터리 z=0.528 에서 다각형이 4,800 → **9,600**(두 배)이고 절점이 평면 위에
    **115,200번** 적중한다. ε 비켜 다시 자르고 **그 사실을 적는다.** 공차 0 을 쓰지 않는다.
  · **셸은 기하에 두께가 없다** — 실제 적층은 `*ELEMENT_SHELL`/`TSHELL` 이고 두께는
    `*SECTION_SHELL` T1..T4(0.008~0.153 mm)에만 있다. 기하만 그리면 **두께 0 의 선**이 된다.
    그림은 기하에 대해 참인데 사람이 묻는 질문("어디가 붙었나")에 대해 거짓이 된다.
    `neutralaxis` 와 같은 규율 — 못 읽으면 0 으로 쓰지 않고 제외하고 그렇게 말한다.
  · **마스터 덱에는 기하가 없다** — 실제 과제의 `01_main_phase1_stacked_tier-1.k` 는 **737 바이트**
    이고 `*INCLUDE` 7개에 `*PART`·`*NODE` 가 0개다. 그 파일을 그리면 **빈 그림이 성공으로** 나온다.
  · **CP949 파트 제목이 안전망을 통과한다** — `kfile_inspect.py:97` 이 `latin-1` 로 읽는다(바이트
    보존 목적의 **의도된** 결정). 모지바케는 DejaVu 로 **아주 잘** 그려지므로 "이 글자를 그릴 수
    있나" 만 보는 안전망에 안 걸린다. 인코딩을 판정해 어느 것이었나를 적어야 한다.
  · **음수 야코비안이 채움을 뒤집는다** — 추적 덱 489장 중 **111장이 정상 픽스처인데 음수**다
    (`runInfo` 주석의 실측). 꼭짓점 순서가 뒤집히면 다각형 채움이 조용히 거짓이 된다.
  · **폭 중앙 단면은 `stackwrap` 의 Y 뒤집힘을 원리적으로 못 본다** — 그 경고가 "대칭이면 보이지
    않습니다" 라고 적혀 있다. 중앙만 자르면 그림이 "괜찮다" 고 거짓말한다.
  · **축에 단위를 달면 거짓이다** — LS-DYNA 덱은 단위가 없다.
  · **`flat_stack.k` 로 축척 처리를 검증하면 결함이 안 잡힌다** — 그 픽스처는 층이 29~88 px 로
    보인다. 실제 비율(1:9,375)을 가진 픽스처를 따로 만들어야 한다.
  · **긴 텍스트가 그림을 먹는다** — 챗이 텍스트를 이어 붙인 **뒤** URL 을 달고 통째로 자르므로
    (`TOOL_RESULT_MAX=6000`, URL 줄 81자) 텍스트가 길면 **URL 이 잘려 그림이 사라진다.**
  · **MCP 도구 이름이 `section_view` 면 StepForge 의 같은 도구를 죽인다** — 같은 이름공간이다.
